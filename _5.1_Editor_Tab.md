## 1. Code structure

`POIAuthoringToolWindow` is a `partial class`, split across
`Assets/Framework/Editor/POIAuthoring/` — one file per concern, same single
class at compile time, so every field/method is visible from every file
exactly as if it were still one file:

```
POIAuthoringToolWindow.cs                    — window lifecycle, OnGUI shell, top action bar
POIAuthoringToolWindow.Constants.cs           — option/label arrays, colours
GlobalScene/POIAuthoringToolWindow.GlobalScene.cs      — Marker/Badge/Outline global tables
SpecificMarker/POIAuthoringToolWindow.SpecificMarker.cs — per-POI foldouts
Shared/POIAuthoringToolWindow.SymbolTable.cs  — generic symbol-table drawer, wall-library helpers
Shared/EntryDetailsPopup.cs                   — floating notes popup (standalone, not partial)
Shared/ExistingSymbolPickerPopup.cs           — curated "choose an already-registered symbol" popup
ConfigData/POIAuthoringToolWindow.ConfigHistory.cs  — config-data undo/redo
ConfigData/POIAuthoringToolWindow.ConfigFileIO.cs   — Load/Save/Copy-to-StreamingAssets
AssetPaths/POIAuthoringToolWindow.AssetPaths.cs     — path helpers, wall icon library resolution
RigLifecycle/POIAuthoringToolWindow.RigLifecycle.cs — Populate/Clear/Refresh/Capture, OnSceneGUI
MarkerSymbolTexturePostprocessor.cs           — auto-imports PNGs under any MarkerAssets/ folder as Sprite
```

**When adding a new method: put it in the file matching its concern above,
not back into the root shell.** If a change doesn't obviously fit one of
these files, that's worth a moment's thought about whether it's actually a
new concern needing its own file, per the same reasoning as the split
itself (see the archive's old §3 in `_5.2_Organize_Project.md` if the "why
partial classes" reasoning is ever in question).

## 2. Source of truth

Two config copies, by design:

- **Authoring source**: `Assets/Apps/<Wall>/config.json` — load, edit, and
  save here.
- **Runtime copy**: `Assets/StreamingAssets/<Wall>/config.json` — what
  `WallSession` actually loads. Never hand-edit this directly.

Workflow: `Load Config` → edit → `Save All to JSON` → `Copy to
StreamingAssets`. **`Save All to JSON` always writes every field
`WallConfigData` declares** (`JsonUtility.ToJson` doesn't omit defaults) —
if a config file is ever missing fields the class declares, that means it
was hand-edited at some point rather than saved through the tool; fix by
round-tripping it through Save, never by hand-adding the missing JSON keys
(see §5 below for why).

## 3. Top-level UI layout

Fixed top action area (Config/Streaming/Marker-prefab paths, Correction
anchor, Wall mesh reference, `Load Config`/`Populate Rig from JSON`/
`Clear Rig`/`Save All to JSON`/`Copy to StreamingAssets`/`Undo`/`Redo`) +
scrollable content area with two top-level foldouts: **Global Scene
Options** and **Specific Marker Options**. Both top-level foldouts, and the
Marker/Badge/Outline foldouts nested inside Global Scene Options, are
visually framed (coloured header + left border) so nesting is legible at a
glance.

## 4. Global Scene Options

### 4.1 Marker

- **Background shape**: `circle`/`rounded_square`/`hexagon`/`diamond`/
  `star`/`none`. (Renamed from "Marker shape" — this is specifically the
  background behind the icon, not the marker as a whole.)
- **Category Symbols table** — one row per category: name, live preview
  (36×36), Sprite field, resolved symbol name, colour swatch+hex (**hidden
  when Background shape is `none`** — nothing to tint), Details (`...`
  button → floating notes popup), remove.
- **Always seeded with 3 starter rows** (`religious`/`military`/`civic`,
  matching real `CategoryPalette.KnownIcons` keys) on a config that has
  none yet — no "seed" button to click first.
- **Wall icon library auto-creates** on first symbol drag — no manual
  "Create" step. A `HelpBox` above the table explains: import a PNG
  anywhere under the wall's folder as Sprite (2D and UI), drag it into any
  Symbol field, it's registered automatically.
- **"Choose existing"** button next to each Sprite field opens a curated
  grid popup (this wall's + framework-default symbols only) — for reusing
  an already-registered symbol without wading through Unity's whole-project
  picker (see §7).
- **"Import categories used by current POIs"** — a plain, always-visible
  secondary button (derives category rows from existing POI data);
  unrelated to the starter-row seeding above.

### 4.2 Badge

- `Enable badge` toggle (independent of Outline — see §4.3).
- **Background shape**: same options as Marker's, its own independent
  choice (`badge_shape` in config).
- Badge taxonomy table: same shared component as the Category Symbols
  table (§4.1) — literally the same `DrawSymbolTable<T>` method, driven by
  delegates rather than a badge-specific copy. Same starter-row seeding,
  same auto-created library, same Details popup.

### 4.3 Outline

- `Enable outline` toggle. **Independent of the Badge toggle** — a wall can
  have either, both, or neither; this used to be miswired (see §9).
- Outline mode: `gold` / `same_hue` / `none`.
- **One table**, columns **Outline Type** (line-style Sprite, same
  preview+picker pattern as the symbol tables) and **Outline Color** (the
  per-level `color_hex` override — this is the full "custom colour" answer;
  there is no separate 4th outline mode for it, `gold` with every level's
  colour overridden already gives full freedom). No percentage slider —
  `pct` auto-spaces evenly across however many levels exist whenever the
  list changes, never developer-facing. Details popup per row, same
  component as §4.1/§4.2.
- Line-style sprites resolve through `MarkerRingView.lineStyleLibrary` (a
  `SpriteKeyLibrary`, same mechanism as icons/shapes) when assigned, falling
  back to the original fixed 5-slot `RingSpriteSet` otherwise — a wall can
  add a custom line style (e.g. "wavy") by importing a PNG and registering
  it the same way as any other symbol.

## 5. Specific Marker Options

Per-POI foldouts:

- **Position** — `x_norm`/`y_norm`, captured-position toggle + XYZ.
- **Marker Style** — POI name, category (dropdown, not free text), Hero
  flag, and — **only shown when Hero is checked** — an optional "Hero
  symbol" Sprite field that overrides just this POI's icon (category
  colour/ring/badge stay unchanged). Same assign-to-library pattern as
  §4.1.
- **Badge Style** — badge category dropdown. Shown when the wall's Badge
  toggle (§4.2) is on.
- **Outline** — has-status toggle, status level (dropdown if outline levels
  exist, else a 0-100 slider — and either way updates the Scene view live,
  mid-drag, no extra click needed), unknown-status toggle, rotate-contour
  toggle. **Shown whenever the wall's outline mode isn't `none`** —
  independent of the Badge toggle (§9's fix).
- **Effects** — independent toggles for `Pulse`/`SunContours`/`SunCircles`/
  `RingPulse`/`SimpleSun`/`Beacon`, backed by `effect_mode` tokens.
  Completely independent of Hero — any POI can use any effect combination
  (`RingPulse`/`SimpleSun`/`Beacon` are mutually exclusive with each other,
  stack freely with the others).

## 6. Undo/Redo model

Two separate systems, deliberately:

- **Scene Undo** (Unity's own `Undo` API) — object-level operations
  (creating/deleting rig objects).
- **Config Undo** (editor-local history, `Ctrl+Z`/`Ctrl+Y`/`Ctrl+Shift+Z` or
  the Undo/Redo buttons) — JSON-backed data edits, via serialized config
  snapshots re-applied to `_config`.

## 7. Sprite asset pipeline — key facts

Full research/reasoning (Unity special-folder behaviour, why the
whole-project object picker shows unrelated sprites, SVG as an option,
third-party icon-pack import, bibliography) is in
`_5.1.1_Editor_Tab_Archive.md` §14 — kept there in full since it's real,
citable research, not build narrative. The load-bearing facts, so a local
agent doesn't need to open the archive for routine work:

- **Framework default PNGs live under `Assets/Framework/Runtime/UI/Markers/
  {Icons,Rings,Shapes}/`** — required to be under `Runtime`, not `Editor`:
  Unity strips anything under a folder literally named `Editor` from player
  builds. Referenced by the prefab as direct serialized references.
- **A wall's own `SpriteKeyLibrary` `.asset` lives under a `Resources/`
  folder** (`Assets/Apps/<Wall>/MarkerAssets/Resources/MarkerSymbols/`) —
  required, because `WallSession` loads it dynamically at runtime by a
  config-supplied string path (`marker_icon_library_resources_path`); that
  needs `Resources.Load`, not a baked reference. This is the *only* place
  in the whole pipeline that genuinely needs a `Resources/` folder.
- **The individual PNGs a wall registers don't need to be under
  `Resources/`** — only the library `.asset` that references them does.
  Unity's GUID-based asset references make the PNG's physical folder
  irrelevant to correctness.
- **`config.json` never stores a path to any individual PNG** — only string
  *keys* (`icon_key`, etc.), resolved against whichever `SpriteKeyLibrary`
  is active. Saving the config never copies or moves any PNG file.
- **Unity's generic Sprite picker (the "+" / `ObjectField`) shows every
  `Sprite`-typed asset in the whole project**, including individual sprites
  sliced from TextMeshPro's own bundled `EmojiOne.asset` — this is normal
  Unity behaviour, not a curated list this tool built. Use "Choose
  existing" (§4.1) instead when re-selecting an already-registered symbol.
- **PNG is the right default format** (lossless alpha — JPG cannot
  represent transparency and should be avoided). Unity 6.3's built-in
  Vector Graphics module supports SVG import as a real, already-available
  alternative if icon crispness under the effects' scaling animation is
  ever a real complaint.
- **Importing a third-party icon pack is ordinary Unity usage** — drag
  loose files into the wall's folder, or `Import Package` for a
  `.unitypackage`; `MarkerSymbolTexturePostprocessor.cs` auto-configures
  Texture Type for anything under a `MarkerAssets/` folder either way.

## 8. Runtime strictness

Missing/invalid optional visual config does not silently fall back to
design defaults — optional visuals are suppressed when required authored
data is missing (no valid category definitions → category styling
suppressed; no outline levels → status outline suppressed; etc). The Editor
may seed helpful starter data (§4.1); runtime itself stays authored-only.

on — with badge off and outline mode `gold` on, per-POI status was
completely unreachable. Fixed: Outline now gates on outline mode `!= none`,
independently of the Badge toggle. Worth remembering because it's exactly
the kind of thing that's easy to reintroduce by copy-pasting a foldout
condition without thinking about whether the two toggles are actually
supposed to be linked (they're not — badge and outline are deliberately
independent, a wall can use either, both, or neither).

## 11. Extension guidance

1. Keep JSON as the explicit source of truth for wall data.
2. Keep runtime asset loading deterministic (library references), not
   filesystem scans.
3. Keep scene-object undo and config-data undo separate.
4. Add foldouts/components before adding more always-visible controls.
5. Reuse the shared symbol-table drawer (`DrawSymbolTable<T>`, §1) for any
   new taxonomy that's structurally "a list of {label, icon, colour,
   details}" rather than writing another near-duplicate table.
6. New concern → new partial-class file (§1), not more methods in the root
   shell file.

## 13. Rig safety checks (Play Mode + Build)

Two editor-only classes guard against the duplicate-marker problem: when
`POIAuthoringRig` still has child objects (hard copies from Populate Rig)
at Play Mode entry or build time, the runtime `WallSession.SpawnPOIs()`
will instantiate a *second* set from `config.json`, producing overlapping
markers with white-line artifacts from z-fighting.

### 13.1 Files

- `Assets/Framework/Editor/POIAuthoringRigSafetyCheck.cs` --
  `[InitializeOnLoad]` static class. Subscribes to
  `EditorApplication.playModeStateChanged` (intercepts `ExitingEditMode`) and
  `EditorSceneManager.sceneSaving`. Scene-saving is a non-blocking
  `Debug.LogWarning` (developer may save mid-placement). Play-mode entry
  delegates to the dialog.
- `Assets/Framework/Editor/POIAuthoringRigBuildCheck.cs` --
  `IPreprocessBuildWithReport` (callbackOrder 0). Delegates to the same
  dialog; only throws `BuildFailedException` if the user cancels.
- The dialog and shared static helpers live in `POIAuthoringToolWindow.cs`
  (same partial class), because that is the class that owns
  `SaveAllToJson()` / `ClearRig()` / rig lifecycle methods.

### 13.2 Dialog flow

```
PromptBeforePlayOrBuild(isBuild):
  1. childCount = GetRigChildCountStatic()
     - GameObject.Find("POIAuthoringRig")
     - verifies parent is "PlacementCorrectionAnchor" (avoids false positives)
     - if 0 children -> return true (proceed, no dialog)
  2. EditorPrefs.GetBool(SkipPromptPrefKey) -> if true, return true (proceed)
  3. show DisplayDialogComplex:

     Build (2 buttons):
       [Save, Clear & Build]  [Cancel]

     Play (3 buttons):
       [Save, Clear & Play]  [Continue Without Clearing]  [Cancel]

  4. choice 0 (Save, Clear & ...):
       SaveAndClearRig() -> SaveAllToJson() + ClearRig() (or direct clear
       if window is closed, with a LogWarning) -> return true
  5. choice 1:
       Play: return true (continue without clearing)
       Build: n/a (only 2 buttons)
  6. choice 2 or -1 (Cancel or X): return false

   Play Mode: false -> EditorApplication.isPlaying = false (abort transition)
   Build:      false -> throw BuildFailedException
```

### 13.3 "Don't show again" toggle

`EditorUtility.DisplayDialogComplex` does not support checkboxes, so the
opt-out is a **menu item toggle** rather than a checkbox in the dialog:

- `TileStories/POI Authoring/Rig Safety Prompt on Play/Build`
- Checked (default) = prompts enabled; unchecked = skipped silently.
- Backed by `EditorPrefs` key `TileStories.RigSafetySkipPrompt`.
- `ToggleRigSafetyPrompt()` flips the bool;
  `ValidateToggleRigSafetyPrompt()` uses `Menu.SetChecked` to render the
  checkmark state in the menu.

To re-enable prompts after opting out: click the menu item again to check
it, or run
`EditorPrefs.DeleteKey("TileStories.RigSafetySkipPrompt")` in the Unity
console.
