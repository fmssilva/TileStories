# Marker & Label Displacement (2.5)

Resolves the marker/label overlaps that survive `_2.4`'s LOD pipeline: whatever is still crowded on
screen is nudged apart, nothing is hidden or merged (that is LOD's job). Continuous: re-evaluated every
`LODController` cycle (step 8), not a one-shot spawn-time fix.

## 1. Scope

**In scope:** detecting and resolving overlaps among the markers LOD left visible, every evaluation cycle;
three interchangeable algorithms; who gives way; leader lines; the dev-only demo; live Play Mode tuning.

**Out of scope:** deciding which markers are visible (`_2.4`); tap selection / magnifier; search and filter.

**Naming:** on a flat wall markers are coplanar, so there is no true depth occlusion; what looks like
overlap at a shallow angle is screen-space crowding from foreshortening. This domain resolves that.

---

## 2. How it works (runtime)

- `LODController.Evaluate()` builds its `VisualUnit`s (or, with LOD off, one per spawned marker) and calls
  `MarkerOverlapResolver.ApplyDisplacement(units, camera, settings, stability)` as **step 8**. Displacement
  runs whenever `displacement_settings.enabled`, with LOD on or off (`Update` only skips when both are off).
- **Who takes part** (`TakesPart`): visible, individual markers. A culled, capped or crowding-hidden marker
  never pushes a visible neighbour, and a cluster aggregate (LOD's own answer to crowding, no `MarkerView`)
  is left out. Every unit that does not take part is reset (no offset, label shown, no line).
- **Grouping:** screen positions of the true places (`MarkerView.UndisplacedWorldPosition`, so a moved
  marker never feeds its own offset back) closer than `overlap_threshold_px` join one group (union-find,
  chains count: `BuildOverlapGroups`).
- **Spreading:** `ComputeOffsets` (pure) gives each member a screen-pixel offset (section 5), capped at
  `max_displacement_px`. With `label_only`, a lower-priority label that still overlaps at the cap is hidden
  (`ResolveLabelsToHide`; its marker stays).
- **Hysteresis** (section 9): a marker moves only after two consecutive crowded cycles, and holds its
  offset through one uncrowded cycle.
- **Applying:** `MarkerView.ApplyLabelOffset` (label `anchoredPosition`, roll-compensated) and/or
  `ApplyMarkerOffset` (root along the camera's right/up). Each target clears the channel it does not use.
- **Switching off / new settings:** `LODController` notices `WallSession.DisplacementSettings` change by
  reference (live edits hand it a new object) or `enabled` go false, and calls `ClearDisplacement()` once:
  every marker back in place, labels shown, lines hidden.
- **Numbers:** each cycle returns a `DisplacementStats` (looked at, crowded groups, moved, longest move,
  labels hidden, leader lines), kept as `LODController.LastDisplacementStats` for the Editor's readout and
  the tests. A Label-only move on a marker whose level shows no label is not counted as a move.

---

## 3. Priority ordering

`HierarchyLevelEntry.priority` (lower = more important), an explicit developer-set field in the Hierarchy
Levels table, never derived from row order (reordering rows for display must not change behaviour).
Read through `MarkerHierarchyResolver.GetLevelPriority(key)` into `VisualUnit.hierarchyLevelIndex`.
Duplicate priorities are allowed and meaningful (a deliberate tie, section 7).

---

## 4. Screen space vs wall space

- **Label only (default):** the label is a child of the billboarded root, so its local X/Y are screen X/Y
  when the root is screen-aligned; for `world_up` / `yaw_only` / `wall_fixed` the offset is rotated by
  `-rootRollDeg` first (`_2.1_Marker_Orientation.md` Block 5). Divided by the root's lossyScale, so it is
  correct mid-reveal.
- **Marker / Both:** the root moves in world space along `cam.transform.right/up`, converted with the
  marker's perspective depth (`MarkerLayout.ScreenPixelsToWorld`) -- stays screen-aligned at grazing angles
  (`ShallowAngle_MarkerDisplacement_ResolvesScreenOverlap`).

---

## 5. Algorithms

Point-feature label placement is NP-hard (Christensen, Marks & Shieber 1995); simulated annealing wins for
static maps with unlimited compute, which a live AR view is not. Three cheap options, developer-selectable
(`displacement_algorithm`):

- **Fixed Axis** (`fixed_axis`): a vertical ladder, most important in the middle. Cheapest, always the same
  shape.
- **Candidate Position** (`candidate_position`): rings of 16 candidate spots, nearest free one wins, most
  important picks first; a small Y-gap penalty keeps labels readable.
- **Force Directed** (`force_directed`, default): pairwise repulsion with a priority-weighted pull back to
  the true place, then (equal priorities only) a vertical-separation pass. Up to
  `MarkerOverlapResolver.ForceDirectedMaxSteps` steps, stopping as soon as nothing overlaps.

---

## 6. Leader lines

- `MarkerLeaderLine` (on the `POI_Marker` root) asks `MarkerView.TryGetLeaderLineEnds` every `LateUpdate`
  (the billboard turns every frame; the cycle only hands over camera + settings via `RefreshLeaderLine`):
  - Label only: from the symbol's rim to the edge of the label's text (`EdgeDistance`, so the line never
    runs through the text).
  - Marker / Both: from the true point to the moved marker's rim.
  - Hidden when the marker is hidden by LOD, when its label is hidden, or when the move is shorter than
    `leader_line_min_distance_px` (screen px).
- Styles: **straight**; **dashed** (a 2-texel dash texture tiled along the line via `textureScale`, one dash
  + gap per `DashPeriodInWidths` widths, set through a `MaterialPropertyBlock`); **elbow** (straight up/down
  on screen first, then across -- `ElbowPoint` uses the camera's up, so the bend is a right angle on screen).
- Colour: the marker's own resolved category colour (no config field), times `leader_line_opacity`.
  Width: `leader_line_width` metres.
- Rendering: `LeaderLine.mat` (Sprites/Default: unlit, alpha-blended, multiplies vertex colour) on the
  prefab's LineRenderer, shadows off. Without a material URP draws magenta.

---

## 7. Who gives way (tiebreak), clusters

`displacement_tiebreak`: **symmetric** (every member moves) or **lower_priority_only** (the unique most
important member stays exactly in place, the others move away; a shared lowest priority falls back to
symmetric for that group -- `DisplacementTieBreakStrategy`). Note that with Force Directed a marker
surrounded symmetrically can stay put even under Symmetric (the pushes cancel); Fixed Axis always moves
every member.

Clusters: not displaced (section 2). A cluster can still visually crowd a lone neighbour; accepted for now.

---

## 8. Wiring

- Step 8 of `LODController.Evaluate()`, never a second timer (two loops would observe each other's
  half-states). The algorithm lives in `MarkerOverlapResolver`; `LODController` only orchestrates.
- `WallSession.DisplacementSettings` is read every frame by reference; `WallSession.ApplyDisplacementSettings`
  swaps it (live Play Mode).
- No spawn-time displacement call exists; the first cycle runs within one evaluation interval of spawn.

---

## 9. Hysteresis

`CommitGroupMembership` (pure, mirrors `LODController.CommitDensityState`): membership commits after two
consecutive agreeing cycles; a committed marker holds its snapshot offset (`committedOffset`) through the
first uncrowded cycle so its own applied offset never reads back as "no overlap". Entries of markers that
left the visible set are pruned.

## 10. Data model (`WallConfigData.cs`)

```csharp
public class DisplacementSettings           // displacement_settings
{
    public bool enabled = true;
    public float overlap_threshold_px = 40f;                // "Overlap Distance (px)"
    public string displace_target = "label_only";           // "label_only" | "marker" | "both"
    public string displacement_algorithm = "force_directed";// "fixed_axis" | "candidate_position" | "force_directed"
    public float max_displacement_px = 120f;                // "Max Move (px)"
    public bool leader_lines_enabled = true;
    public string leader_line_style = "straight";           // "straight" | "dashed" | "elbow"
    public float leader_line_min_distance_px = 15f;         // "Min Length (px)"
    public float leader_line_width = 0.01f;                 // metres
    public float leader_line_opacity = 1f;
    public string displacement_tiebreak = "symmetric";      // "symmetric" | "lower_priority_only"
    // + const slider limits (MinOverlapPx, MaxOverlapPx, MaxMovePxLimit, MaxLeaderMinLengthPx, Min/MaxLeaderWidthM)
}

public class DisplacementDemoSettings       // displacement_demo (dev-only, section 12)
{
    public bool enabled = false;
    public int markers_per_group = 4;       // 2..8
    public float spread_cm = 4f;            // 0..30
    public float distance_m = 3f;           // 0.3..6
    public bool show_labels = true;
    public string reference_copies = "side_by_side"; // "side_by_side" | "overlay" | "off"
    public bool run_lod = false;
}
```
No per-POI fields: a POI's displacement priority is its hierarchy level's Priority (a new POI copies its
source's level, so nothing else needs copying).

## 12. The displacement demo (Displacement > Test > "Add displacement demo")

Why a dedicated demo: displacement depends on the real camera's screen crowding, and on a real wall it
is hard to see what moved. The demo makes every setting's effect visible and measurable.

- **Where:** its own empty stage (`DemoFieldStage.DisplacementDemoStagePosition`, 4200 m up; the LOD demo
  field uses 3500 m). In the Editor the camera moves there and back; a development build uses the pose in
  front of the camera. The wall's own POIs pause; only the demo's live markers run through LOD/displacement.
- **What:** four scenarios on a flat demo wall facing the camera (`DisplacementDemoLayout`, pure):
  top-left **Same** (all on the middle-priority level: only the algorithm decides), top-right **Mixed**
  (levels by priority: shows who gives way), bottom-left **Big/Small** (one top-level marker among the
  lowest level), bottom-right **Lone** (control: must never move). Members sit on a golden-angle spiral
  (irregular like a real wall; a symmetric ring cancels every Force Directed push).
- **Reference copies:** faded copies (alpha `ReferenceAlpha`) at the true places that are NOT handed to
  LOD/displacement, so they never move: side by side (copy to the left), overlay (copy underneath) or off.
- **Controls:** Markers per Group, Spread (cm), Distance (m) (spacing scales with it, marker size does not:
  farther = more crowding), Show labels (forced on/off for every demo marker), Reference copies, Run LOD on
  the demo (off: `WallSession.LodSettings` hands LODController a fixed LOD-off object while the demo runs).
- **Readout:** "Live Displacement Readout" prints `LastDisplacementStats` in Play Mode.
- **Safety:** off by default; `DisplacementDemoSpawner.IsAllowed` (Editor + development builds);
  registered in `DevFeatureBuildGuard` ("Add displacement demo"); mutually exclusive with the other demo
  views (`MakeThisTheOnlyActiveDemoView`); if the LOD demo field is also on, the LOD field wins.

## Design history

Kept because it explains the current design (thesis-relevant).

- **Priority is an explicit field** (section 3), not the row index: reordering rows must not change behaviour.
- **Label only is the default** because it is correct by construction on a billboarded root; Marker/Both
  needed the camera-basis conversion (section 4), sequenced last and pinned by a shallow-angle regression test.
- **`displacement_tiebreak` moved here from `LodSettings`** (it was a reserved placeholder there).
- **Continuous step 8, spawn-time call deleted** (a one-shot result was overwritten within one interval).
- **2026-09-25 review (bugs found and fixed):** (1) leader lines never drew in the default Label-only mode
  (the line was configured only when the ROOT had moved); (2) the prefab's LineRenderer had no material
  (magenta in URP) and cast shadows; (3) "dashed" was identical to straight, "elbow" bent along world axes;
  (4) with LOD on, hidden and capped markers and cluster aggregates (placed at screen 0,0) took part and
  pushed visible labels; (5) switching displacement off never restored anything (the clear branch was
  unreachable); (6) switching What Moves live left the previous target's offset; (7) several (i) texts
  contradicted the code ("tiebreak deferred", "shared with the LOD density radius") or named code.
- **Relaxation Steps removed (2026-09-25).** `force_directed_iterations` was measured on 4-12 member groups
  (equal and mixed priorities, spreads 0-16 px, symmetric and irregular layouts): 1 to 20 steps changed a
  result by at most a few pixels, because one summed push step already separates a group and the loop
  then stops. A knob with no visible effect was removed; `ForceDirectedMaxSteps` (50) is an internal
  ceiling. Averaging the pushes instead (so steps would matter) was tried and rejected: at the old default
  it separated the real lamp family worse (smallest gap 1.3 px vs > 5 px).
- **Demo instead of a gallery scene.** The Phase-A `DisplacementGalleryHarness` had no scene and no users
  and was deleted; `DisplacementGalleryDefinitions` still drives `DisplacementGalleryTests`. The demo lives
  in the Editor Tab, is live-tunable and uses the real pipeline; "reference copies" replace ghost drawing.
- **OPEN -- size-aware overlap.** Overlap is a fixed centre-to-centre pixel distance, blind to marker size:
  at 1.5 m a 30 cm marker is ~180 px wide, so symbols overlap long before 40 px, and a moved label can end
  under a neighbour's symbol. The demo shows it at Distance 1-1.5 m. Making the threshold per pair from the
  projected footprints (`MarkerView.GetVisualRadiusWorld` exists) changes all three algorithms; awaiting a
  developer decision.
