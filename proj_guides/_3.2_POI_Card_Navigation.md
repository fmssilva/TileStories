# POI Detail Card -- Navigation (3.2)

How a visitor moves between the blocks of ONE open card: the ontology that groups blocks (families
and kinds), the card LAYOUT modes (scroll, tabs, pages, accordion, bento) and the NAVIGATION ELEMENTS
a developer can compose (tabs, bottom bar, floating button, in-flow nav blocks, edge scrubber...).
Builds on `_3.1_POI_Card_Blocks.md` (card container, block registry, block stack). Styling of every
element follows `_3.3`.

Design source: the Design canvas artboards "Block ontology" and "Navigation elements".

## 1. Scope

**In:** navigation INSIDE an open card for one POI. **Out:** anything that moves between POIs or
walls (circuits, guided tours, the AR orbit ring before a card opens, the search palette's cross-POI
results) -- Stage 3 scene-level features. The search/filter palette of the canvas (C5) is kept only
as an in-card "find a block" variant, deferred to the end.

## 2. Ontology (the thing every element navigates)

- **Family (level 1, tap 1):** declared on each `BlockKindDefinition.family` (`_3.1`). Eight
  framework families: `about`, `media`, `guides`, `stories`, `ar`, `play`, `visit`, `community`, plus
  `meta` (sources, credits -- always last, never in primary nav). Each family has an order, a label
  (localized), an icon key and a colour token (`_3.3`).
- **Kind (level 2, tap 2):** the block kind. Several instances of one kind on a POI are level 3.
- **Collapse rules (pure `NavOntologyRule`):** an empty family is hidden; a family with one block needs
  one tap (level 2 skipped); a kind with one instance skips level 3; more families than a bar's slots ->
  the last slot becomes "More".
- **Families are data, not an enum.** Built-ins registered like kinds; an app may add a family
  (`BlockRegistry.RegisterFamily`) -- same extension rule as `_3.1` step 11.
- **Facets (for the find-a-block variant and badges on nav items):** format (derived from the kind:
  read / look / watch / listen / 3D / interact), duration (optional per instance `minutes`), needs
  (camera, headphones, network -- declared on the kind). Only built when step "find a block" is.

## 3. Navigation model

Pure `CardNavModel` (Runtime/Blocks/Navigation/): from the rendered stack (`BlockStackBuilder`
output) -> families -> kinds -> instances, with a target index per node. Every element is a VIEW over
this one model plus one `NavController` that (a) scrolls / pages to a target, (b) reports the current
section from the scroll position (scroll-spy), (c) raises `CurrentChanged`. Elements never compute
structure themselves -- one model, many views, the `_2.6` "one result set every surface shows" rule
applied to navigation.

## 4. Config: `card_settings.navigation`

| Field (Editor label) | Default | What it does |
|---|---|---|
| `layout` (Layout) | `scroll` | `scroll`, `tabs`, `pages`, `accordion`, `bento` |
| `primary` (Primary Element) | `none` | one element key from section 5 |
| `secondary` (Second Level) | `none` | an element for level 2 (e.g. kind chips under family tabs) |
| `axis` (Group By) | `family` | `family` or `format` |
| `max_slots` (Bar Slots) | 5 | bar-type elements; overflow -> "More" |
| `labels` (Labels) | `icon_and_text` | `icon`, `text`, `icon_and_text` |
| `show_counts` (Show Counts) | false | family counts on nav items |
| `scroll_spy` (Follow Scroll) | true | the element highlights where the visitor is |
| `hide_on_scroll` (Hide While Scrolling) | `never` | `never`, `down`, `idle` |

In-flow nav blocks (section 5, group D) are ordinary block instances in a POI's stack, so they live in
`POIData.card.blocks`, not here.

## 6. Layout modes (step 9)

| Layout | What changes | Natural primary element |
|---|---|---|
| `scroll` | one ScrollView (built in `_3.1`) | any |
| `tabs` | one family visible at a time | `text_tabs` / `icon_tabs_chips` / `bottom_bar` |
| `pages` | one family per horizontal page, snap, next page peeks | `family_pager` |
| `accordion` | every block as a `compact` row that expands in place -- adds the `compact` display mode to every kind (`_3.1` section 5.4) | none needed |
| `bento` | family tiles sized per kind; tap opens full view | `grid_overlay` behaviour inline |

Layouts only re-arrange the same `BlockStackView` children; a kind's view never knows the layout.

## 7. Editor: Detail Card > Navigation

Rows for every field of section 4 (popups filled from the registered element keys and layouts),
a "Preset" popup that fills them (section 8), and a Test sub-foldout: "Preview navigation" opens the
demo card (`_3.1` 8.4) with the chosen layout + element on the fixture `lamp`. In Specific Marker >
Card Content, nav blocks appear in the "+ Add block" picker under a `navigation` group.

## 8. Presets (convenience, not new behaviour)

| Preset | layout | primary | secondary |
|---|---|---|---|
| Casual visitor | `scroll` | `text_tabs` | `kind_chips` |
| Deep dive | `scroll` | `drawer_tree` | `edge_scrubber` |
| Families | `scroll` | `dock` | -- (+ `nav_icon_grid` block) |
| Quick glance | `accordion` | `fab_dial` | -- |
| Story | `pages` | `family_pager` | `next_up` |

A preset only writes the fields; the developer can change any of them afterwards.

## 9. Testing

- `NavOntologyRuleTests`, `CardNavModelTests` (EditMode): collapse rules, More overflow, family order,
  format axis, app-registered family.
- `CardNavGalleryTests` (PlayMode, Phase A): every element x (few blocks, many blocks, one family,
  long labels) builds, fits at 390 px, tap targets >= 44 px, renders `Card_nav_<key>.png`.
- `CardNavSceneTests` (PlayMode, Phase B, real scene, fixture `lamp`): tapping each element's item
  scrolls or pages to the right block (assert the `ScrollView` offset / page index), scroll-spy marks
  the right family, More opens the overflow.
- Accessibility: every element keyboard / screen-reader reachable is a `_3.3` + Stage 7 check; the
  radial menu always has the dial as its accessible fallback.
