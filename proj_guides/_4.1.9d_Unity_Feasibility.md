# Unity feasibility of the hand-drawn kids' look (Unity 6.3 LTS, AR Foundation, iOS/Android)

Scope: what the Lab may prototype so that every visual has a known Unity implementation. Facts come from Unity 6.3 docs unless marked. Unity 6.7 (alpha) is noted where a missing feature is arriving. The Lab was audited, not edited.

## 1. UI Toolkit vs uGUI in Unity 6.3

**UI Toolkit covers the panel layer, and its USS is close to the Lab's CSS.** In 6.3 LTS the following are available ([USS supported properties](https://docs.unity.com/en-us/engine/6000.3/manual/uitoolkits/uielements/uie-uss/properties/supported-properties)):
- **9-slice:** `-unity-slice-left/top/right/bottom` (integers), `-unity-slice-scale`, and `-unity-slice-type: sliced | tiled`. Tiled lets a wobbly edge repeat instead of stretching. Slice scale is multiplied by sprite PPU/100, so keep the PPU consistent.
- **Backgrounds:** `background-image`, `-unity-background-scale-mode` and `-unity-background-image-tint-color`. One grey sprite can be tinted to any token colour.
- **Variables:** USS custom properties (`var(--x)`) work, but there is no `calc()`. Every `calc(n * var(--u))` in the Lab becomes a fixed px value at the panel's reference resolution, with the Panel Settings scale mode handling density.
- **Masking:** `border-radius` (no elliptical `/` syntax; clamped to half the size) and `overflow: hidden` clip children, which gives rounded-rect masks. There is no soft or alpha masking; it is on Unity's list for after 6.7 ([UI Toolkit status, Nov 2025](https://discussions.unity.com/t/ui-toolkit-development-status-and-next-milestones-november-2025/1698009)).
- **Opacity:** `opacity` multiplies down the hierarchy.
- **Custom materials:** `-unity-material` assigns a custom material, and children inherit it.
- **Transitions** ([USS transitions](https://docs.unity.com/en-us/engine/6000.6/manual/uitoolkits/uielements/uie-uss/properties/uie-transitions)): `transition-property/duration/timing-function/delay`. Easing is named curves only: ease, linear, and the sine/cubic/circ/elastic/back/bounce variants. **There is no `cubic-bezier()` and no `@keyframes`.** A transition goes from one state to another. `translate/rotate/scale/opacity/color` take a fast path; other properties re-layout.
- **Transforms:** `translate`, `rotate`, `scale` and `transform-origin`. **There is no `perspective` or `preserve-3d`.**
- **Filters (new in 6.3):** `filter:` supports `blur, grayscale, invert, opacity, sepia, tint, hue-rotate, contrast`, plus custom filters ([built-in filters](https://docs.unity.com/en-us/engine/6000.3/manual/uitoolkits/uielements/uie-uss/uss-filter/built-in-filters)). There is **no `drop-shadow()`, `brightness()` or `saturate()`**. Each filter renders the element's own subtree to a texture, so it never blurs the backdrop.
- **Custom shaders (6.3, URP only):** a UI Shader Graph target with a Render Type Branch node ([get started](https://docs.unity.com/en-us/engine/6000.6/manual/uitoolkits/uielements/uie-uss/ui-shader-graph/get-started-with)). Paper grain, dithered gradients, wobble and camera-blur glass all go here.
- **Text** ([text effects](https://docs.unity.cn/Manual/UIE-text-effects.html)): `text-shadow` (one shadow, offset + blur + colour) and `-unity-text-outline-width/color`. Both need an **SDF FontAsset**, and their size is limited by the atlas padding. Custom fonts are imported as FontAssets (Fredoka and Fraunces are fine).
- **Vector images:** SVG imports natively as a *UI Toolkit Vector Image* without the package, antialiased through Painter2D ([Vector Graphics in UI Toolkit](https://discussions.unity.com/t/vector-graphics-in-ui-toolkit/1683117)).

**Not in 6.3 USS:**
- `box-shadow`, gradients, `backdrop-filter`, `mix-blend-mode`, `clip-path`, `mask-image`, `outline`, `border-image`, `color-mix()` and `calc()`.
- Gradients (`linear-/radial-gradient`) landed in **6.7a4** ([thread](https://discussions.unity.com/t/uss-gradients-linear-gradient-and-image-gradients/934218?page=2)). Dark gradients show banding, and the workaround is a dither shader ([thread](https://discussions.unity.com/t/visible-banding-in-ui-toolkit-css-gradients/1733843)).
- Drop shadows and backdrop blur are "in active development, by 6.7 LTS".

**uGUI is still the better fit for two things:**
- **Spine:** `SkeletonGraphic` is official for uGUI, while the UI Toolkit integration is experimental ([Spine components](https://esotericsoftware.com/spine-unity-main-components), [forum](https://discussions.unity.com/t/working-with-spine-files-and-ui-toolkit/950186)).
- **Particles:** ParticleSystems in UI use [UIParticle (MIT)](https://github.com/mob-sakai/ParticleEffectForUGUI). UI Toolkit can't host particles or 3D objects; that is also planned for after 6.7.

**What maps 1:1:** flex layout, radius, solid borders, solid colours, tinted sprites, 9-slice, opacity, 2D transforms, transitions with named easings, single text shadows and outlines, SDF fonts, and blur/grayscale on an element's own content.

**What needs a sprite:** soft shadows, glows, gradients (on 6.3), wobbly or sketchy outlines, doodles and paper textures.

**What needs a shader:** backdrop glass, soft-edge masks, shimmer text, animated wobble and dithering.

## 2. Hand-drawn asset pipeline

- **Panels and buttons:**
  - Paint each wobbly frame once, export it as a PNG and 9-slice it. Put the irregularity in the corners and use `-unity-slice-type: tiled` on long edges so the wobble doesn't stretch.
  - Ship at least 3 frame variants per size class, so repeated cards don't look identical.
  - The fill is the same sprite, or a separate tintable sprite, so the colour still comes from tokens.
- **Hard offset "sticker" shadow:** no sprite is needed for rounded rects. Add a sibling element with the same radius in solid `--hs`, offset with `translate`. It is free, and pressing animates `translate` on the fast path. For wobbly shapes, reuse the frame sprite tinted ink, offset by 3–4 pt. Bake it into the art only for static illustrations.
- **Soft shadow:** a 9-sliced blurred-rect sprite behind the element, one shared texture.
- **Icons:**
  - SVG becomes a UI Toolkit Vector Image when a clean line is wanted. Line art imported as a Vector Image stays crisp at any density, but it can't be animated cheaply because changing it means re-tessellating.
  - For a hand-inked look, use PNGs in an atlas.
  - Unity's best-practice guide still recommends raster for UI ([asset preparation](https://docs.unity.com/en-us/engine/6000.6/manual/best-practice-guides/bpg-uiad-index/graphic-and-font-assets-preparation)).
- **Doodles and stickers:**
  - Atlased PNGs placed as absolute-positioned elements.
  - Author at 3× the reference resolution and let mipmaps or a second @2× atlas variant serve low-density phones. Don't upscale.
- **Paper texture:** a single tileable 256–512 px greyscale grain. Apply it either as a tiled background layer element with low opacity, or, better, sample it in one UI Shader Graph material on panel fills. Multiply blend is only possible in a shader.
- **Painted panel backgrounds:** full illustrations are single textures, one per screen. Load them per screen (Addressables) and don't keep them resident.
- **Atlases and memory:**
  - Group atlases by screen or feature, at 2048² maximum, compressed ASTC 6×6. That is about 1.9 MB per atlas, versus 16 MB uncompressed RGBA32 (arithmetic: 2048²×3.56 bpp).
  - Leave elements that aren't packed in a Sprite Atlas to the dynamic atlas set in Panel Settings.
  - Budget: about 20–30 MB of UI textures on top of AR. Camera images and tracking already consume a large share on 3–4 GB phones.

## 3. Motion

- **UI Toolkit transitions:** state changes such as press, select, show/hide, sheet slide and pop-in with `ease-out-back`. They are cheap when limited to transform, opacity and colour. Set `UsageHints.DynamicTransform` on animated elements before they are added to the panel.
- **Loops and sequences** (pulses, spins, staggered entrances): a tween library driving `style.translate/scale/rotate`.
  - [DOTween](https://dotween.demigiant.com/) works through its generic `DOTween.To` getter/setter.
  - PrimeTween is a zero-allocation alternative.
  - Or `schedule.Execute().Every()` / chained `TransitionEndEvent`.
- **Animation and Timeline:** good for 3D mascot and collectible choreography and for onboarding cut-scenes. Keyframing VisualElements in the Animation window is not in 6.3; it is in development.
- **Lottie:** community only.
  - [unity-lottie-player](https://github.com/gilzoide/unity-lottie-player) (rlottie, Unlicense, iOS/Android, v1.1.1) rasterises on the CPU, Job System capable, into a texture that can feed a UI Toolkit background.
  - Each frame costs CPU time plus a texture upload, so keep players few and small (≤256 px) and pause them off-screen.
  - Treat it as optional and don't make it a pillar of the look.
- **Mascot:**
  - In AR it is a 3D rigged model with an Animator.
  - In the 2D UI it is a sprite sheet (cheapest: swap the sprite on a timer) or Spine through a uGUI `SkeletonGraphic` island. Spine-in-UI-Toolkit is experimental.
- **Parallax:**
  - UI layers move `translate` from the Input System attitude/gyro or the AR camera rotation, clamped to a few pt and low-pass filtered.
  - 3D layers get true parallax by living in world space.
- **Celebration bursts:**
  - Over AR content, use a world-space ParticleSystem. That is the cheapest option and it's lit by the scene.
  - Over UI Toolkit, use about 30–60 pooled confetti VisualElements tweened in C#, or a custom mesh via `generateVisualContent`.
  - UIParticle only if the screen is uGUI. Its own table shows it is slow without mesh sharing.
- **Performance while AR runs (mid-range):**
  - Target 30 fps steady with no thermal throttling.
  - Avoid filters and render textures in persistent UI, because each one is an offscreen pass ([guide](https://docs.unity.com/en-us/engine/6000.6/manual/best-practice-guides/bpg-uiad-index/graphic-and-font-assets-preparation)).
  - Keep animated elements as leaves, keep custom materials few, since they break batching, and profile on a device from the Snapdragon 7-series or iPhone 11 class.

## 4. 3D in the UI

- **World-space UI Toolkit (6.2+)** puts panels in the scene next to AR anchors ([world space UI](https://docs.unity3d.com/6000.2/Documentation/Manual/ui-systems/world-space-ui.html)): tags and labels on tiles, plus the mascot's speech bubble. Known issue: `overflow: hidden` clipping fails in world space ([issue](https://issuetracker.unity3d.com/issues/ui-toolkits-visualelement-with-overflow-hidden-property-fails-to-clip-its-child-element-when-render-mode-is-set-to-world-space)), so avoid masks in world panels.
- **3D models** (mascot, collectibles, badges) render as normal URP objects over the AR background. Spinning badges and the Lab's CSS cube are real meshes.
- **3D inside a 2D panel** (a badge spinning in a reward sheet): a second camera renders to a small RenderTexture (≤512²) shown as a background, active only while visible. The alternative is a pre-rendered sprite-sheet turntable, which costs nothing at runtime.

## 6. Audit of css/ds.css (823 lines) and css/tap.css (364 lines)

Counts (ds / tap) and replacements:
- **backdrop-filter (37 / 17).** Glass on `.g`, `.ds-main`, `.ds-sheet`, `.s-card`, chips (`tap.css:5,168,178,344,349`; `ds.css:118,248`). This becomes the planned camera-blur shader: one downsampled blurred copy of the AR background per frame, sampled in screen UV by a shared UI Shader Graph material. It is not a USS `filter`, because that blurs the element's own content. The Playful look sets glass: solid; `.glass-solid` (`ds.css:359–360`) already strips blur, so it is safe.
- **filter: brightness/saturate/grayscale** for pressed and disabled states (`ds.css:24,25,246,302,679`; `tap.css:359`). Replace with token colours: `--btn-pressed` and a disabled palette. `ds.css:471–472` already does this.
- **filter: drop-shadow:**
  - `ds.css:105` (tab glow) and `ds.css:764` (favourite marker glow): baked glow sprite.
  - `ds.css:437,439` (nav shape): the nav bump becomes a Vector Image or 9-slice sprite, with a separate shadow sprite.
- **mask-image (2 / 8)** fades on scroll rows (`tap.css:145,204,350`). Replace with a fade-overlay sprite in the sheet colour at the edge, or an alpha-ramp shader. `ds.css:655` already removes one.
- **clip-path (1):** `ds.css:398`, `inset()` on the raised-nav bump. Use an `overflow:hidden` wrapper, or fold it into the nav sprite.
- **mix-blend-mode, conic-gradient:** none.
- **box-shadow (86 / 18):**
  - Hard `sh-hard` shadows (`ds.css:785–790`) map to the sibling offset element. `sh-hard` also stacks a soft halo (`ds.css:787`); that becomes a second soft sprite, or should be dropped.
  - Soft shadows (`.g`, `.ds-solid`, `ds.css:199–202,271,365`) become 9-slice sprites.
  - Inset rings (`ds.css:44,48,227,300,536,599,640`) become real borders.
  - `0 0 0 999px` scrim (`tap.css:214`) becomes a full-screen scrim element.
- **Gradients:**
  - Radial (8 / 2): `.mazu.mascot` (`tap.css:223,236`) becomes mascot artwork; `ds.css:399` becomes the nav sprite.
  - Linear (17 / 13): scrims (`ds.css:34,307,513,586,648,688`; `tap.css:37`) use one shared alpha-ramp texture.
  - Slider fill (`ds.css:59–61,486`): two elements.
  - Shimmer and skeleton (`ds.css:84,256,493`): tween the opacity or translate of a highlight sprite.
- **background-clip:text** (`ds.css:84`, `.shimmer`): text shader, or an opacity pulse.
- **text-shadow (18 / 15):**
  - Single shadows are fine.
  - The stacked halo (`ds.css:700–701`) becomes an SDF outline.
- **outline** (`ds.css:784`): inner border element.
- **3D:** `perspective` (`tap.css:49`) and `preserve-3d` cube (`tap.css:100–101`, `@keyframes tspin`): real 3D or render texture.
- **@keyframes (10 / 10)** and **cubic-bezier (7 / 2):** each loop needs a `tween:` tag. `--spring` and the overshoot beziers map to `ease-out-back`.
- **color-mix (33 / 1):** precompute at export.

Not app UI: `lab.css:246,253` `.ph .room` blur simulates the camera feed. The `kids_*.css` files are empty stubs.

## Summary

1. **UI stack:** UI Toolkit for all screen-space UI on 6.3 LTS with URP.
2. **uGUI islands** only for Spine `SkeletonGraphic` or UIParticle, if those are adopted.
3. **World-space UI Toolkit** for AR labels and bubbles; real URP meshes for the mascot, collectibles and badges.
4. **Wobbly frames** are painted 9-slice PNGs: tiled edges, at least 3 variants, tintable, PPU fixed.
5. **Sticker shadow** is a sibling element (radius + `translate`), or the frame sprite tinted ink. Never `box-shadow`.
6. **Doodles, glows, soft shadows and gradients** are atlased sprites: ASTC 6×6, 2048² atlases grouped by screen, authored at 3×.
7. **Paper grain** is one tileable texture sampled in a single shared UI Shader Graph material.
8. **Motion stack:** USS transitions for state changes, DOTween/PrimeTween for loops and sequences, Animator/Timeline for 3D, sprite sheets for the 2D mascot. Lottie is optional and small.
9. **Celebrations:** world-space ParticleSystem in AR; pooled VisualElement confetti in UI.
10. **Performance:** 30 fps with AR, no persistent filters or render textures, and only transform/opacity/colour animated.
11. **Lab DO:** radius, solid borders, `border-image` 9-slice, sprites/SVG, one text-shadow, opacity, 2D transforms, named easings.
12. **Lab DO, tagged:** soft shadows (`unity: sprite`), gradients (`unity: ramp`), keyframes (`tween:`), glass (`unity: camera-glass`; `backdrop-filter: none` resets are fine).
13. **Lab DON'T:** `drop-shadow`, `brightness/saturate`, `mask-image`, `mix-blend-mode`, `clip-path`, `perspective`/3D CSS, `cubic-bezier`, `background-clip:text`, `outline`, stacked text-shadows.
14. **Lab DON'T:** `backdrop-filter` anywhere except the camera-glass tag. Playful stays glass: solid.
15. **Revisit at 6.7 LTS:** USS gradients, drop shadows and backdrop blur may become native.
