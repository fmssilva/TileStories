future notes for the user guide to do this:
This combination — "the file is textually correct, but Unity still throws the exact same error" — is a well-documented Unity behavior, not a mystery. I searched for it specifically: Unity's own tooling ecosystem has dedicated "refresh the AssetDatabase" utilities built specifically because "file changed outside of Unity's own API" (exactly your workflow — an agent editing files directly, not through a running Editor) isn't always picked up automatically. And there's a documented real-world case on Unity's own forums of a prefab reference showing correctly in Prefab Edit mode but showing as lost/missing everywhere else, traced to a stale Library cache after external changes — the standard fix there was a forced reimport.

So, concretely, in order:
In the Assts tab → Reimport All. This forces Unity to throw away whatever it cached and rebuild every asset reference from the actual files on disk.
