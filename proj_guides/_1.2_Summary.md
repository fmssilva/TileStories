## How the Positioning System Works (Short Version)

Every POI has two ways to get its 3D position:
1. **Captured position** (precise): a hand-placed XYZ coordinate in the scene. Takes priority when has_captured_position = true.
2. **x_norm/y_norm fallback** (approximate): a percentage position on a flat reference photo (0,0 = bottom-left, 1,1 = top-right). Interpolated between calibration anchors (known reference points with captured positions). If no anchors exist, projects onto a default 4x3m plane.

The displacement system then resolves overlapping markers in screen-space: when two markers screen positions are closer than overlap_threshold_px, one or both are displaced (label only, marker root, or both) using one of three algorithms. Leader lines can connect displaced markers back to their true positions.

## 1. POSITION RESOLUTION (POIPositionResolver)

### 1.1 - Captured Position Precedence
- **What:** When has_captured_position = true, the POI uses its captured_position XYZ directly, ignoring x_norm/y_norm.
- **Code:** POIPositionResolver.TryResolvePosition() lines 23-36
- **Editor UI:** Specific Marker tab -> per-POI Position foldout -> Use captured position toggle + X/Y/Z float fields
- **How to test:** Toggle Use captured position on a POI, set X/Y/Z, save, populate rig. Marker should appear at that exact position.

### 1.2 - x_norm/y_norm Fallback Interpolation
- **What:** When no captured position, interpolates x_norm/y_norm between calibration anchors sorted by x_norm, with vertical offset from y_norm.
- **Code:** POIPositionResolver.InterpolateBetweenAnchors() lines 73-110
- **Editor UI:** Specific Marker tab -> per-POI Position foldout -> X norm / Y norm sliders (0-1)
- **How to test:** Clear captured position on a POI, set x_norm=0.5/y_norm=0.5, save, populate rig. Marker should appear at the interpolated midpoint.

- **How to test:** See 1.2 above.

## 3. DISPLACEMENT / OVERLAP RESOLUTION (MarkerOverlapResolver)

### 3.1 - Enable/Disable Displacement
- **What:** Master switch for the entire displacement system.
- **Code:** DisplacementSettings.enabled
- **Editor UI:** Global Scene tab -> Displacement foldout -> Enable Displacement toggle
- **How to test:** Toggle off, verify no displacement occurs even with overlapping markers.

### 3.2 - Overlap Threshold (px)
- **What:** Screen-space distance in pixels below which two markers are considered overlapping.
- **Code:** DisplacementSettings.overlap_threshold_px (default 40)
- **Editor UI:** Global Scene -> Displacement -> Overlap Threshold (px) float field
- **How to test:** Set to a large value (e.g., 200), verify even distant markers get displaced.

### 3.3 - Displace Target (label_only / marker / both)
- **What:** What gets displaced when markers overlap: only the label, only the marker root, or both.
- **Code:** DisplacementSettings.displace_target
- **Editor UI:** Global Scene -> Displacement -> Displace Target popup
- **How to test:** Create overlapping markers, cycle through all three options, verify correct element moves.

### 3.4 - Displacement Algorithm (fixed_axis / candidate_position / force_directed)
- **What:** The algorithm used to compute displacement offsets.
- **Code:** DisplacementSettings.displacement_algorithm
- **Editor UI:** Global Scene -> Displacement -> Displacement Algorithm popup
- **How to test:** Cycle through algorithms, verify different offset patterns.

### 3.5 - Relaxation Steps (force_directed only)
- **What:** Number of iterations for the force_directed algorithm. Only applicable when algorithm is force_directed.
- **Code:** DisplacementSettings.force_directed_iterations (default 5)
- **Editor UI:** Global Scene -> Displacement -> Relaxation Steps int field (visible only when algorithm = force_directed)
- **How to test:** Select force_directed, change steps, verify different convergence.

### 3.6 - Max Displacement (px)
- **What:** Clamps the maximum displacement offset in pixels.
- **Code:** DisplacementSettings.max_displacement_px (default 100)
- **Editor UI:** Global Scene -> Displacement -> Max Displacement (px) float field
- **How to test:** Set to a small value (e.g., 20), verify offsets are clamped.

### 3.7 - Leader Lines Enable/Disable
- **What:** Toggles leader lines connecting displaced markers to their true positions.
- **Code:** DisplacementSettings.leader_lines_enabled (default true)
- **Editor UI:** Global Scene -> Displacement -> Enable Leader Lines toggle
- **How to test:** Toggle off, verify no lines appear on displaced markers.

### 3.8 - Leader Line Style (straight / dashed / elbow)
- **What:** Visual style of leader lines.
- **Code:** DisplacementSettings.leader_line_style
- **Editor UI:** Global Scene -> Displacement -> Style popup (visible when leader lines enabled)
- **How to test:** Cycle through styles, verify visual change.

### 3.9 - Leader Line Min Distance (px)
- **What:** Minimum screen-space distance before a leader line is drawn.
- **Code:** DisplacementSettings.leader_line_min_distance_px (default 15)
- **Editor UI:** Global Scene -> Displacement -> Min Distance (px) float field
- **How to test:** Set to a high value (e.g., 200), verify lines only appear for large displacements.

### 3.10 - Leader Line Width (world)
- **What:** World-space width of the leader line.
- **Code:** DisplacementSettings.leader_line_width (default 0.01)
- **Editor UI:** Global Scene -> Displacement -> Line Width (world) float field
- **How to test:** Increase width, verify thicker lines.

### 3.11 - Leader Line Opacity (0-1)
- **What:** Alpha multiplier on the category color for the leader line.
- **Code:** DisplacementSettings.leader_line_opacity (default 1.0)
- **Editor UI:** Global Scene -> Displacement -> Line Opacity (0-1) float field
- **How to test:** Set to 0.5, verify semi-transparent lines.

### 3.12 - Tiebreak Mode (symmetric / lower_priority_only)
- **How to decide which marker stays put when displacing. symmetric displaces all; lower_priority_only keeps the highest-priority marker anchored.
- **Code:** DisplacementSettings.displacement_tiebreak
- **Editor UI:** Global Scene -> Displacement -> Tiebreak popup
- **How to test:** Create overlapping markers with different priorities, verify correct anchoring.

### 3.13 - Hysteresis (Anti-Flicker)
- **What:** Once a marker is committed to displacement, it stays displaced for a few cycles even if the overlap clears, preventing visual flicker.
- **Code:** DisplacementStabilityState in MarkerOverlapResolver
- **Editor UI:** N/A (automatic, not configurable)
- **How to test:** Move markers in/out of overlap, verify displacement does not flicker.

### 3.14 - Label Hide Fallback (2.5-h)
- **What:** When displacement hits the max clamp and markers still crowd, the lower-priority marker label is hidden (label_only mode only).
- **Code:** MarkerOverlapResolver.ResolveLabelsToHide() lines 815-870
- **Editor UI:** N/A (automatic when max_displacement_px is reached)
- **How to test:** Set max_displacement_px very low, create dense overlap, verify labels hide.

## 6. EDITOR RIG LIFECYCLE (Positioning Workflow)

### 6.1 - Populate Rig from JSON
- **What:** Spawns one marker per POI at its resolved position under POIAuthoringRig. Uses the same POIPositionResolver as runtime.
- **Code:** POIAuthoringToolWindow.PopulateRig() in RigLifecycle.cs
- **Editor UI:** Top action bar -> Load & Populate Rig button
- **How to test:** Click button, verify markers appear at correct positions in Scene view.

### 6.2 - Capture Positions to JSON
- **What:** Writes each rig marker position back to config as captured_position with has_captured_position=true.
- **Code:** POIAuthoringToolWindow.CapturePositions() lines 407-463
- **Editor UI:** Automatic on Save All to JSON (calls CapturePositions first)
- **How to test:** Populate rig, move markers, save, reload JSON, verify captured_position values updated.

### 6.3 - Clear Rig
- **What:** Destroys all marker instances under POIAuthoringRig.
- **Code:** POIAuthoringToolWindow.ClearRig() in RigLifecycle.cs
- **Editor UI:** Top action bar -> Clear Rig button
- **How to test:** Click button, verify all rig markers removed from hierarchy.

### 6.4 - Focus in Scene
- **What:** Selects and frames a POI rig marker in the Scene view.
- **Code:** POIAuthoringToolWindow.FocusPoiInScene() lines 551-572
- **Editor UI:** Specific Marker tab -> per-POI Focus in Scene button
- **How to test:** Populate rig, click Focus on a POI, verify Scene view frames it.

### 6.5 - Edit Rotation (Dev-Only Yaw)
- **What:** Rotates the rig marker in the Scene view for placement preview. Does NOT affect runtime (billboard always faces camera).
- **Code:** POIAuthoringToolWindow.PositionTabs.cs ApplyPoiEditorRotation() lines 84-95; UI slider at end of DrawPositionTabs (always visible below Draft/Precise tabs).
- **Editor UI:** Specific Marker tab -> Position foldout -> Edit Rotation slider below the Draft/Precise tabs (0-360 degrees). Single always-on control, not split per tab.
- **How to test:** Populate rig, drag slider, verify marker rotates in Scene view.

### 6.6 - PlacementCorrectionAnchor Support
- **What:** If a PlacementCorrectionAnchor transform exists, positions are converted via InverseTransformPoint/TransformPoint for accurate capture/populate.
- **Code:** POIAuthoringToolWindow.PopulateRig() and CapturePositions() in RigLifecycle.cs
- **Editor UI:** Scene Configuration foldout -> Correction anchor object field
- **How to test:** Assign a moved/rotated anchor, populate rig, verify markers appear at correct world positions.

### 6.7 - OnSceneGUI Handles
- **What:** Cyan sphere handles drawn at each POI resolved position in the Scene view.
- **Code:** POIAuthoringToolWindow.OnSceneGUI() lines 478-500
- **Editor UI:** N/A (automatic when config is loaded)
- **How to test:** Load config, look for cyan spheres in Scene view at POI positions.

### 6.8 - Rig Sync Status Indicator
- **What:** Shows whether the rig markers match the config.json positions (green = in sync, red = out of sync).
- **Code:** POIAuthoringToolWindow.IsRigInSyncWithConfig() in RigLifecycle.cs
- **Editor UI:** Bottom of window -> Rig matches config.json / Rig OUT OF SYNC label
- **How to test:** Populate rig, move a marker, verify indicator turns red.
