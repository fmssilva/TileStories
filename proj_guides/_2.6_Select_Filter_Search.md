# Select, Filter & Search (2.6)

How a visitor finds points of interest: tap a marker (or a minimap dot, or a results row) to select it,
type or say what they look for, filter by the wall's own taxonomy, and see the one result set as a list,
on a minimap or on the markers themselves. Plus a deliberately minimal detail card that proves
selection -> detail end to end (the full content card is a later domain).

The first build (blocks 1-6, archived verbatim in `_2.6.4_Select_Filter_Search_Archive.md`) produced
every piece with green unit tests, but the visitor UI was never put in any scene; the 2026-09-25 review
composed it, rebuilt the config ontology and the engine, and proved every setting on the real scene. The
2026-09-26 round 2 made the keyword list one source (index = Editor preview), made the summary editable,
made Keyword Fields filters, gave the demo self-judging test cases and proved every field one by one.
What changed and why: "Design history" at the end.

## 1. The visitor's flow

1. The wall loads; nothing covers the camera view except the search bar (and the Map button when the
   minimap is on "Button").
2. **Select:** tapping a marker selects its POI -- the card opens at the bottom, every other marker dims
   (Highlight Selection), a marker inside a crowd zooms the camera in (Zoom on Select). Tapping it again, or
   the card's X, clears. A minimap dot or a results row selects the same way.
3. **Search:** typing (or speaking) ranks POIs; the list, the minimap dots and the markers all show the same
   result set; everything outside it hides (or dims). Clearing the text clears the search.
4. **Filter:** the Filters button opens the tray: chips per taxonomy row, OR within a group, AND across
   groups; the Filters button counts active filters. No results with 2+ filters: one "Remove filter: X"
   button.
5. **Views:** while results are active, List / Map / Highlight chooses where they show.
6. **Suggestions:** the empty focused field offers the wall's categories and (Recent first) the device's
   recent searches.

## 2. Architecture

- **Data:** `Runtime/Core/SelectFilterSearchSettings.cs` -- the block and `SelectFilterSearchOptions` (every
  option string + parser, shared by the runtime and the Editor Tab dropdowns).
- **Engine (pure):** `POISearchIndex` (inverted index), `SearchTokenizer`, `SearchTextDistance`, `SynonymGroup`.
- **Rules (pure):** `ResultSetCoordinator` (search + filters -> one `ResultSetState`), `FilterFacetEvaluator`
  (`FacetSelection`, relax), `SearchPanelsRule` (which panel shows), `SelectionAlphaRule`, `MinimapLayout`,
  `ZoomOnSelectController.ComputeZoomTarget / CountNeighbours`, `ViewModeParser`.
- **Runtime wiring:** `WallSession` builds the index over the RUNNING markers' POIs (`SearchPois`,
  `SearchConfig`, `SearchIndex`), raises `SearchDataChanged`, owns the selection responders
  (`SelectionHighlightController` = the only writer of the selection alpha channel, `ZoomOnSelectController`)
  and the live seams `ApplySearchSettings` / `ApplySearchDemo`.
- **Selection bus:** `SelectionEventBus.Select(id)` (re-selecting clears -- decided before any listener runs),
  `Clear()`, `SelectCluster(ids)`, `CurrentPoiId`. Tap targets: `MarkerSelectable` (POI_Marker),
  `MarkerClusterSelectable` (POI_Cluster).
- **Visitor UI (UI Toolkit, screen space):** plain C# views, each built into the parent element it is handed --
  `SearchOverlayView` (bar + suggestions), `FilterTrayView`, `ViewModeControl`, `ResultsListView` (virtualised
  ListView), `MinimapView`, `DetailCardView` -- composed by ONE thin MonoBehaviour, `SearchUIHost`, on the
  scene's `SearchUI` object (its own `UIDocument`, sort order 1, the shared `PanelSettings`). Every size and
  colour lives in `SearchUI.uss` (colours as USS variables); the views only name elements and add classes.
- **Why plain view classes:** the views used to be MonoBehaviours that each grabbed
  `FindFirstObjectByType<UIDocument>()` -- which in a scene with the zoom buttons' document could attach to the
  wrong panel -- and hid the shared root to hide themselves. Plain classes are testable without a scene and
  own only their own container.

|---|---|---|---|

| `selection.zoom` | `enabled` (Zoom on Select), `trigger` (Zoom Trigger: marker/cluster/both), `neighbour_radius_px` (Crowd Radius), `min_neighbours` (Min Neighbours), `factor` (Zoom Factor) | true, marker, 60, 2, 2 | a crowded tap (or a cluster tap) zooms the camera |
| `search` | `mode` (Search Mode: dynamic/explicit), `match_mode` (Match Words: all/any), `prefix_matching` (Partial Words: off/name_only/all_fields), `typo_tolerance` (0-2), `no_results_message`, `no_results_filters_message` (No-Results (Filters): no text typed, the filters alone leave nothing) | dynamic, all, all_fields, 1, "No matches for {query}...", "Nothing matches these filters..." | how a query matches |
| `filter` | `category_facet`, `badge_facet`, `status_facet`, `hierarchy_facet` (the four Filter toggles), `mismatch` (Filtered-Out Markers: hide/dim), `dim_alpha` (Dim Filtered To), `relax_suggestion` | all on, hide, 0.3, on | which facets exist, what happens to the rest |
| `results` | `default_view` (list/minimap/camera_highlight), `remember_last_view`, `recent_count` (0-20), `suggestions_enabled`, `suggestion_source` (category_distribution/recent_first) | list, off, 5, on, category_distribution | how results show |
| `minimap` | `enabled`, `visibility` (always/toggle), `icon_style` (dots_only/category_colored_dots/mini_icons), `dot_size_px`, `tap_target_px`, `projection` (auto/wall/floor), `bounds_mode` (auto/manual), `bounds_min`, `bounds_max` | on, toggle, category_colored_dots, 20, 44, auto, auto | the overview map |
| `voice` | `enabled` (Enable Voice Search), `indicator_style` (mic_text/listen_bar) | off, mic_text | speech input |

The keyword **vocabulary** stays wall-level next to the tables it belongs to: `search_fields` (custom search
axes: `key`, `label`, `forced` = Required, `filterable` = Filter, `details`), `synonym_groups`, and every
taxonomy row's `search_keywords`. Per POI: `summary`, `search_keywords` (Others), `search_keyword_fields`.
Dev-only: `search_demo` (Test foldout).

**Filters from Keyword Fields.** A Keyword Field with Filter ticked becomes a facet group of its own
(`FacetGroup.Field(key)`, titled by the field's label): one chip per distinct keyword the running POIs hold in
it (case and spaces ignored, A-Z), OR within the field, AND with the other groups, included in the relax
suggestion. `FacetGroup` is a small value type (the four taxonomy groups as static members + `Field(key)`),
compared by id -- no longer a closed enum.

## 4. Keyword ontology (authoring tree -> runtime flat index)

`SearchKeywordSources.Collect(config, poi)` is the ONE flattening of the authoring tree: it returns every word
a POI is found by, with its source, rank and origin ("Name", "Others", a field's label, "Summary", "Category",
"Badge", "Status", "Level", "Synonyms"). `POISearchIndex.Build` indexes exactly that list and Specific Marker >
Summary & Keywords shows it read-only as **Found by**, so the preview cannot drift from the search (it had: the
old Editor list missed names / labels and showed outline keywords for POIs without a status). A POI's searchable
words come from five places, ranked by source:

| Source | Where it is authored | Rank |
|---|---|---|
| its name | Specific Marker header (rename) | 1.0 |
| its own keywords: Others (`search_keywords`) + each Keyword Field (`search_keyword_fields`) | Specific Marker > Summary & Keywords | 0.7 |
| synonyms of any word it already has (computed per POI from its own words; groups do not chain) | Select, Filter & Search > Keywords & Synonyms | 0.6, never above the word it came from |
| its summary | Specific Marker > Summary & Keywords > Summary | 0.4 |
| its taxonomy rows: category name, badge label, outline label (only with a status), level name, and each row's Search Keywords | the Category / Badge / Outline / Hierarchy tables | 0.3 |

At `Build` the tree is flattened into `token -> (POI, rank, source)`; a query word meets each indexed word
exactly (x1), as a prefix (x0.9, 2+ letters, forward only) or with typos (x0.8 one edit, x0.6 two; 4+ letters
for one, 8+ for two; optimal string alignment, a swapped pair = one edit). A POI's score is its best word
score; Match Words = all requires every query word to match. Each result carries its `Reason`
("keyword, typo") -- shown in the Live Search Readout. Filters narrow by id BEFORE ranking (null = no filter,
an empty set = nothing). Synonym groups are equivalence sets, applied inside `Build` so a rebuild can never lose
them.

Considered and rejected: stemming/NLP (not needed at a wall's scale, language-specific), BM25 / TF-IDF (scores
by term frequency, meaningless for short keyword lists), a strategy interface with weighted fields (the first
build's `weighted_fields` idea was removed: one ranked model is enough and explainable).

## 5. Selection and the one alpha channel

`MarkerView` has three independent alpha channels (LOD visibility, selection, crowding). The selection channel
has exactly ONE writer, `SelectionHighlightController`, which combines two inputs through `SelectionAlphaRule`:

- the selected marker: always full;
- outside an active result set: the filter's mismatch alpha (0 = hidden), whether or not something is selected;
- otherwise, while another marker is selected and Highlight Selection is on: Dim Others To;
- otherwise full.

The coordinator never writes alpha; it hands the controller the result set (`SetResultSet`). This is what
makes "select while filtering" and "clear the selection while filtering" correct (both used to break).

Zoom-on-select counts the other VISIBLE markers within Crowd Radius of the tapped one, on screen, at their
true (undisplaced) places, at tap time -- independent of LOD. A cluster tap counts as a crowd. The zoom is a
digital zoom around the screen centre (`fov = base / zoom`), so Zoom Factor is capped by
`MaxZoomKeepingOnScreen`: the tapped point (a cluster: its members' centre) must stay inside 85% of the
half-screen; a cap under x1.1 means no zoom at all. A marker that
starts fading out (hidden by LOD, merged into a cluster, filtered out) stops taking taps at the START of the
fade (`MarkerView.FadeCoroutine`).

## 6. Minimap

`MinimapLayout`: the projection picks two world axes (Wall = x/y, Floor = x/z, Auto = the two with the widest
spread of the markers -- LivingRoom is a room, so Auto draws its floor plan), the bounds fit every marker with a
10% margin (or the manual box), never smaller than 0.5 m. Dots are placed from the RUNNING markers' true world
positions (so a demo stage or a calibrated wall is drawn as it is), by percent (resolution independent); a tap
selects the nearest SHOWN dot; outside the result set a dot hides; the selected dot grows, the others fade.
Dot styles: plain (the stylesheet's colour), category colour, category colour + icon (the wall's icon library).

## 10. Open items

- **Real speech backend:** `TranscriberFactory` returns none on a device, so the mic stays hidden. Adding
  yasirkula/UnitySpeechToText = one adapter class implementing `ITranscriber` + one line in the factory; needs
  a device session (`_2.6.2_Human_Tests.md`).
- **Visitor-facing strings:** the search UI's button labels ("Filters", "Map", "List", ...) are English literals
  in the views. `30-ui-content.md` asks for a strings table; the project has no localization system yet --
  when it gets one, these move there.
- **Screen-reader roles:** Unity 6000.3 exposes no accessibility-node API on `VisualElement`; controls carry
  names + tooltips. Revisit when the Accessibility module is available.
- **Observed, other domain:** in the search demo's clump a Displacement leader line runs far from the clump to
  an empty spot (probably a line kept for a label Max Move hid). Not changed here (Displacement's scope); worth a
  look in that domain.
- **The filter tray covers the results list.** With the tray open, a filter set that leaves nothing shows its
  "Remove filter" button only once the tray is closed (seen in `Search_Field_filter_relax_on.png`'s first
  capture). Candidate fix: repeat the relax button (or a "N results" line) at the tray's bottom. Judge on a
  phone first (`_2.6.2_Human_Tests.md`), not changed here.
- **Zoom-on-select is a centre zoom.** It is now capped so the tapped point stays on screen; a zoom TOWARD the
  point (off-centre crop) would need the AR camera image to crop too -- a Zoom domain (`_2.4`) question.
- **Flaky once:** `SearchSceneTests.ARealMarkerTap...` failed twice (tap reached a Symbol, nothing selected),
  then passed every run. Its failure message now says what the tap aimed at, hit and selected, so a repeat is
  diagnosable.

## Design history

Decisions of the 2026-09-25 review, and why (the first build's narrative: `_2.6.4_Select_Filter_Search_Archive.md`).

1. **The UI was never composed.** Six UI Toolkit views had ~280 green tests between them but no scene contained
   them and no production code created them (`40-testing.md` 4.2.1's failure class). Fixed by `SearchUIHost` in
   the scene; every PlayMode test now runs on the real scene.
2. **Config ontology.** ~25 flat `WallConfigData` fields (the int-serialized trigger, dead toggles) became one
   block with six sub-blocks mirroring the Editor sub-foldouts; configs migrated by script, no compatibility shim.
   Dead fields made real or removed: `zoom_on_select_enabled`, `show_suggested_categories`, `minimap_enabled`,
   `minimap_visibility` were read by nothing; the "inert" search modes were offered but did nothing (removed);
   `mini_icons` was a colour dot (now real icons); the "Cluster" trigger had no cluster tap (now real);
   `wall_bounds` (all zero in the shipped config, stacking every dot in a corner) became auto bounds + projection.
3. **Engine bugs fixed:** hierarchy keywords and badge / outline labels were never indexed (the editor even
   listed hierarchy keywords as "auto-included"); a reverse name prefix made "de" match "desk"; no prefix on
   keywords (search-as-you-type could not complete "chu"); an active filter matching nothing searched everything;
   results mapped to POIs by list index; synonyms one-way and lost on rebuild; typed search ignored the match mode.
4. **One alpha writer.** Selection and filtering both wrote the selection channel (last writer won: "hide"
   became 0.3, a tap resurrected filtered markers, clearing the selection wiped the filter). Chosen over a second
   channel or event priorities: a pure rule + one writer is the smallest correct structure.
5. **Re-tap at the source.** The highlight controller used to raise a clear from inside a select event
   (re-entrant; the card could reopen). `SelectionEventBus.Select` decides it before any listener runs.
6. **Zoom-on-select independent of LOD.** It read LOD's cached neighbour counts (stale with LOD off); now it
   counts on demand at the tap. Default Crowd Radius 60 px (about a fingertip and a half; LOD's crowding radius is
   40 px).
7. **Taps on leaving markers.** A marker fading out kept taking taps for its fade (a cluster tap selected a
   hidden member). Raycasts now switch off at the start of a fade-out.
8. **Voice honesty.** The debug transcriber used to be returned on devices too (a fake mic). Now the Editor only.
9. **Styling.** All six `.uxml` / `.uss` files were unused (styles hard-coded in C#). One `SearchUI.uss` with
   colour variables replaced them and `UIPalette`; contrast is now tested on the laid-out panel (`resolvedStyle`).
10. **Deferred WordNet / AI synonym tiers** (spec's optional tiers): manual groups, now bidirectional, cover the
    need; a WordNet extract is a multi-MB editor asset for English only, and the AI tier needs keys and network --
    both remain possible later without changing the data (they would only fill `synonym_groups`).
11. **Lessons worth keeping (UI Toolkit):** a `ChangeEvent` only dispatches on an element attached to a live
    panel (set state directly + `SetValueWithoutNotify` for programmatic changes); flex children shrink by
    default (`flex-shrink: 0` for wrapped chip groups, a `ScrollView` for tall panels); the default theme pads
    every `Label` (zero it inside fixed-height rows); read `worldBound` after a layout pass to measure tap targets
    (a 44 px button in a padded 52 px bar measured 43.85).

Round 2 (2026-09-26):

12. **One keyword list (`SearchKeywordSources`).** The Editor's "Auto-included from taxonomy" list re-implemented
    the index's taxonomy step and had drifted (no names / labels; outline keywords for POIs without a status).
    Chosen over "keep two copies and test them against each other" and "an Editor-only helper": a pure runtime
    function both use, pinned by a test that searches every listed word. Synonyms moved inside it (per POI, from
    its own words; a held word is raised only when the synonym ranks it higher, as before).
13. **Summary editable.** It was searched, shown on the card and pushed live, yet only editable in the JSON.
    The per-POI section became "Summary & Keywords".
14. **Keyword Fields as filters.** A custom field (Period, Architect) is the natural structured facet of a wall.
    `FacetGroup` went from a closed enum to a value type with `Field(key)` (existing call sites unchanged) --
    chosen over an enum member + side key, or a second filter system.
15. **Self-judging demo.** Test cases carry `Expected(settings)`; `SearchDemoCheck` judges them on the real index
    for the readout and for the tests (18 setting combinations). Chosen over visual-only cases (the developer had
    to know what each setting should do) and PlayMode-only asserts (invisible to the developer).
16. **Zoom-on-select keeps the tapped point on screen.** Renders showed a x3 zoom on the demo's corner clump
    losing the clump (a centre zoom scales every offset). `MaxZoomKeepingOnScreen` solves the exact FOV maths;
    the clump moved to the demo's centre, where a full zoom is right.
17. **Every field one by one.** `SearchSettingsFieldTests` + `[CoversField]` + a reflection guard: a new field
    without a real-scene test fails the suite (demonstrated by removing one tag).
18. **Editor mic phrase.** The Editor mic always heard 'cathedral' (matching nothing). It now hears the Try a
    Query text -- no config field, Editor path only.
19. **No-Results (Filters).** A render showed `No matches for "" - try removing a filter.` for filters with no
    text. A second, data-driven message (rule 30: visitor strings are data) rather than string surgery on the
    query message.
