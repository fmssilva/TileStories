## 1. Scope


Build a marker rendering system where a wall's `config.json` selects **how** POIs
render (one style + one shape for the whole wall) while POI content stays per-POI
data. Concretely:

- `marker_style`: 3 built-in ways to encode destruction status (gold ring / same-hue
  fade / corner badge).
- `marker_shape`: 5 base silhouettes (circle / rounded square / hexagon / diamond /
  star).
- Category → fill colour + icon (any wall-defined category string, not a fixed enum),
  with an optional explicit override per category so a dev can hand-pick a colour/icon
  for specific categories while everything else still gets the automatic fallback.
- Status (0–100% destroyed) → ring, fill-fade, or badge, depending on style — never
  fades to invisible.
- A third, genuinely distinct status state — `status_unknown` — for a POI whose fate
  is a real historical unknown, rendered identically (a neutral-grey "?" badge)
  regardless of `marker_style`, never conflated with "this wall has no status axis."
- Hero-tier POIs get a persistent label and optional pulse/sun emphasis.
- Any POI with high destruction is still expressed through the ring/fill/badge
  system; there is no fire/smoke cue in the final runtime.
- A dev-facing dropdown in the existing POI Authoring Tool to try all of this without
  hand-editing JSON.

### Non-goals for this stage (do not build)
- Tap-to-reveal label for standard-tier POIs (labels just stay hidden for now).
- TMP icon-font / sprite-atlas migration (plain Sprite icons are the shipped path).
- Per-POI shape override (shape is wall-level only).
- Shape-matched dashed rings for non-circle shapes (ring is always circular; see
  `MarkerShape.cs` comments in §7 Step 1).
- `MarkerParticleEffect` art content (prefab wiring only — no particle authoring).
- Any new `TileStoriesSettings.cs` — it doesn't exist yet in this project and this
  stage doesn't need it (see §5).

## 3. Hard rule for this stage: no backward-compatibility shims

This is a pre-release (v1) project. There is no shipped API to preserve. When a
signature needs to change (it does: `MarkerView.Initialise`), **change it in place
and update every call site** — do not add a second overload "for compatibility."
There are exactly two call sites in the whole project (enumerated in §6); both are
touched by this same change, so there is no ambiguity an overload would resolve.

The one place a small adapter is acceptable is *inside a test file*, if a test
specifically wants a convenience helper local to that test class — but that is a
test-only convenience, never a second production signature. This stage does not
need one even there: §6 shows the one-line fix to the one affected test.

Do not confuse this rule with the `has_status` / `has_captured_position` presence
guards used in `WallConfigData.cs` (§7 Step 2) — those are not compatibility shims,
they are correct data semantics (see the inline comments there). Keep them.

`Assets/Framework/Runtime/Core/MarkerStyle.cs`
```csharp
namespace TileStories
{
    // The three built-in ways a marker can encode its secondary (status) axis.
    // This is a framework rendering choice, not wall content -- unlike `category`
    // and per-POI status (free-form wall data confirmed by the LivingRoom test
    // wall's "furniture"/"art"/"test" categories, which share nothing with the
    // Panorama wall's "religious"/"military" taxonomy), a wall just picks one of
    // these three built-in renderers. That's why this is a fixed enum and
    // category/status stay plain strings.
    public enum MarkerStyle
    {
        // Category fill colour, achromatic gold->rust status ring (dash rhythm +
        // colour drift, never fades to invisible). Stage 2.3 prototype "System A".
        OutlineGold,

        // Category fill colour that itself drains toward black as status worsens;
        // icon fades in step. Thin same-hue echo ring reinforces. "System C".
        //
        // Worth knowing even though it isn't built this stage: this is also the
        // style best positioned for a future "filter by status" toggle (e.g. a
        // search UI where selecting "religious buildings" makes category the
        // dominant read and status secondary, or vice versa for "80%+ destroyed").
        // Because both axes already live on the same hue/lightness channel pair
        // here, swapping which one drives which is a small change to
        // StatusRamp.ShadeTowardBlack's call site, not a new rendering path. The
        // other two styles would need a structurally different toggle mechanism.
        OutlineSameHue,

        // Category fill colour, no ring at all. Status shown via a small
        // outside-overlap badge, top-right, coloured from the status ramp. "System B".
        Badge,
    }
}
```

`Assets/Framework/Runtime/Core/MarkerVisualsParser.cs`
```csharp
using UnityEngine;

namespace TileStories
{
    // Parses the wall config's freeform marker_style / marker_shape strings into
    // their enums. Kept as strings in JSON (see design principle 2 in
    // _2_2_Marker_Design.md §4). An unrecognised or missing value logs once and
    // falls back to a sane default rather than silently defaulting to enum value 0.
    public static class MarkerVisualsParser
    {
        public const MarkerStyle DefaultStyle = MarkerStyle.OutlineGold;
        public const MarkerShape DefaultShape = MarkerShape.Circle;

        public static MarkerStyle ParseStyle(string raw)
        {
            switch (raw)
            {
                case "outline_gold": return MarkerStyle.OutlineGold;
                case "outline_same_hue": return MarkerStyle.OutlineSameHue;
                case "badge": return MarkerStyle.Badge;
                default:
                    if (!string.IsNullOrEmpty(raw))
                        Debug.LogWarning($"[MarkerVisualsParser] Unknown marker_style '{raw}', falling back to {DefaultStyle}.");
                    return DefaultStyle;
            }
        }

        public static MarkerShape ParseShape(string raw)
        {
            switch (raw)
            {
                case "circle": return MarkerShape.Circle;
                case "rounded_square": return MarkerShape.RoundedSquare;
                case "hexagon": return MarkerShape.Hexagon;
                case "diamond": return MarkerShape.Diamond;
                case "star": return MarkerShape.Star;
                default:
                    if (!string.IsNullOrEmpty(raw))
                        Debug.LogWarning($"[MarkerVisualsParser] Unknown marker_shape '{raw}', falling back to {DefaultShape}.");
                    return DefaultShape;
            }
        }
    }
}
```

### Step 2 — `WallConfigData.cs` (full replacement)

Adds `marker_style`/`marker_shape` (wall-level) and `status_pct`/`has_status`/
`is_hero` (per-POI). The `has_status` guard mirrors the existing
`has_captured_position` pattern exactly and for the identical reason: a POI
legitimately at 0% ("fully intact") must never be indistinguishable from a POI whose
wall doesn't track status at all.

```csharp
using System;
using System.Collections.Generic;
using UnityEngine;

namespace TileStories
{
    [Serializable]
    public class WallConfigData
    {
        public string wall_id;
        public string wall_name;
        public int immersal_map_id;

        // "outline_gold" / "outline_same_hue" / "badge". Missing/unrecognised falls
        // back to MarkerVisualsParser.DefaultStyle -- unlike has_captured_position,
        // an absent value here has one unambiguous safe meaning ("use the framework
        // default"), so no separate has_* flag is needed.
        public string marker_style;

        // "circle" / "rounded_square" / "hexagon" / "diamond" / "star".
        public string marker_shape;

        // Optional, additive per-category colour/icon overrides. Any category not
        // listed here still falls through to CategoryPalette's deterministic hash
        // colour and KnownIcons lookup (§7 Step 3) -- this list is a hand-picked
        // exception list, not a replacement taxonomy.
        public List<CategoryStyleEntry> category_styles = new();

        public List<POIData> pois = new();
        public List<CalibrationAnchor> calibration_anchors = new();
    }

    [Serializable]
    public class CategoryStyleEntry
    {
        public string category;   // must match POIData.category exactly

        // "#RRGGBB". Empty/omitted -> this category keeps the hash-generated colour.
        public string color_hex;

        // Matches an entry key in IconLibrary.asset. Empty/omitted -> no icon
        // (colour-only circle), same as any other unlisted category.
        public string icon_key;
    }

    [Serializable]
    public class POIData : ISerializationCallbackReceiver
    {
        public string id;
        public string name;
        public string category;
        public float x_norm;
        public float y_norm;

        public CapturedPosition captured_position;
        public bool has_captured_position;
        public string captured_position_source;
        public long captured_position_timestamp;
        public string summary;

        // Destruction status, 0-100. Same has_* guard as captured_position and for
        // the same reason: a POI legitimately at 0% ("fully intact") must never be
        // indistinguishable from a POI whose wall doesn't track status at all (e.g.
        // a mural has no "destroyed" axis). MarkerView must check has_status before
        // reading status_pct for anything.
        public float status_pct;
        public bool has_status;

        // A genuinely separate third state from either of the above: this wall DOES
        // track status, AND this specific POI's fate is a real historical unknown
        // (not simply undocumented in this dataset -- actually unknown). Only
        // meaningful when has_status is true; ignored otherwise. Rendered
        // identically across all three MarkerStyle values as a single neutral-grey
        // "?" badge, overriding the style-specific ring/fade/badge rendering for
        // that one POI (see MarkerView.ApplyStatus, §7 Step 7).
        public bool status_unknown;

        // Marks this POI as a hierarchy "hero": persistent label and any enabled
        // marker effects (pulse/sun) are only shown for hero POIs. Defaults to
        // false when absent -- a safe default here (unlike status) because "not a
        // hero" is an ordinary, unsurprising fallback, not a data-loss risk.
        public bool is_hero;

        public void OnBeforeSerialize()
        {
            if (!has_captured_position)
            {
                captured_position = null;
            }
        }

        public void OnAfterDeserialize()
        {
            if (!has_captured_position)
            {
                captured_position = null;
                if (string.IsNullOrEmpty(captured_position_source))
                {
                    captured_position_source = null;
                }

                if (captured_position_timestamp < 0)
                {
                    captured_position_timestamp = 0;
                }
            }

            if (!has_status)
            {
                status_pct = 0f;
                status_unknown = false;
            }
        }
    }

    [Serializable]
    public class CapturedPosition
    {
        public float x;
        public float y;
        public float z;

        public Vector3 ToVector3() => new(x, y, z);
    }

    [Serializable]
    public class CalibrationAnchor
    {
        public string id;
        public float x_norm;
        public float y_norm;
        public CapturedPosition captured_position;
    }
}
```

`Assets/Framework/Runtime/POI/CategoryPalette.cs`
```csharp
using System.Collections.Generic;
using UnityEngine;

namespace TileStories
{
    // Resolves a wall-defined `category` string into a fill colour and (optionally)
    // an icon key. See _2_2_Marker_Design.md §4-5 for why this stays domain-owned
    // data, not a framework-wide palette. A wall may optionally call Configure()
    // once (WallSession does this automatically, §7 Step 8) to hand-pick specific
    // categories' colours/icons; anything not explicitly configured still falls
    // through to the deterministic hash / KnownIcons lookup below.
    public static class CategoryPalette
    {
        // Opt-in icon keys for the Panorama-style building taxonomy from the
        // Stage 2.3 prototypes. Just a lookup table, not an enforced schema -- add
        // entries here (and a matching sprite in IconLibrary.asset) as new named
        // categories get real icons drawn for them.
        private static readonly Dictionary<string, string> KnownIcons = new()
        {
            { "religious", "temple" },
            { "royal", "crown" },
            { "military", "shield" },
            { "civic", "columns" },
            { "maritime", "anchor" },
            { "infra", "bridge" },
            { "landscape", "leaf" },
            { "commerce", "scale" },
        };

        private static readonly Color DefaultColor = new Color(0.35f, 0.33f, 0.30f);

        // The one piece of mutable static state in this class -- everything else
        // here is a pure function of its arguments. Populated once per wall session
        // by WallSession.Configure (§7 Step 8), immediately after config load and
        // before any marker spawns. Acceptable because this app loads exactly one
        // wall at a time; ClearOverrides() exists specifically so tests (and, if
        // ever needed, a future multi-wall session) don't leak state between calls.
        private static Dictionary<string, Color> _colorOverrides;
        private static Dictionary<string, string> _iconOverrides;

        // Call once per wall, right after config load. overrides may be null or
        // empty -- both mean "no overrides, hash/KnownIcons decide everything,"
        // identical to never calling this at all.
        public static void Configure(IEnumerable<CategoryStyleEntry> overrides)
        {
            _colorOverrides = new Dictionary<string, Color>();
            _iconOverrides = new Dictionary<string, string>();
            if (overrides == null) return;

            foreach (var entry in overrides)
            {
                if (entry == null || string.IsNullOrEmpty(entry.category)) continue;

                if (!string.IsNullOrEmpty(entry.color_hex) &&
                    ColorUtility.TryParseHtmlString(entry.color_hex, out var parsedColor))
                {
                    _colorOverrides[entry.category] = parsedColor;
                }

                if (!string.IsNullOrEmpty(entry.icon_key))
                {
                    _iconOverrides[entry.category] = entry.icon_key;
                }
            }
        }

        // Resets to "no overrides configured." Call in test [SetUp]/[TearDown] and
        // whenever a new wall session starts, so one wall's/test's overrides never
        // leak into the next.
        public static void ClearOverrides()
        {
            _colorOverrides = null;
            _iconOverrides = null;
        }

        public static Color ResolveColor(string category)
        {
            if (string.IsNullOrEmpty(category)) return DefaultColor;

            if (_colorOverrides != null && _colorOverrides.TryGetValue(category, out var overrideColor))
                return overrideColor;

            int hash = StableHash(category);
            float hue = (hash % 360) / 360f;

            // Fixed soft/desaturated saturation & value so every generated category
            // colour reads as "adult museum," never neon -- matches the
            // Stage 2.3 HTML prototypes' manually-tuned range.
            return Color.HSVToRGB(hue, 0.38f, 0.55f);
        }

        public static string ResolveIconKey(string category)
        {
            if (string.IsNullOrEmpty(category)) return null;

            if (_iconOverrides != null && _iconOverrides.TryGetValue(category, out var overrideIcon))
                return overrideIcon;

            return KnownIcons.TryGetValue(category, out var key) ? key : null;
        }

        // FNV-1a: deterministic across runs/platforms/.NET versions, unlike
        // string.GetHashCode(), which .NET explicitly does not guarantee is stable.
        // Public (not internal): CategoryPaletteTests lives in a separate asmdef
        // with no InternalsVisibleTo configured, and adding one is more moving
        // parts than making the method public.
        public static int StableHash(string s)
        {
            unchecked
            {
                uint hash = 2166136261;
                foreach (char c in s)
                {
                    hash ^= c;
                    hash *= 16777619;
                }
                return (int)(hash & 0x7FFFFFFF);
            }
        }
    }
}
```

`Assets/Framework/Runtime/POI/StatusRamp.cs`
```csharp
using UnityEngine;

namespace TileStories
{
    public readonly struct StatusLevel
    {
        public readonly float Pct;
        public readonly Color RingColor;
        public readonly string RingSpriteKey; // solid/dash_long/dash_medium/dash_short/dotted
        public readonly float RingWidth;

        public StatusLevel(float pct, Color ringColor, string ringSpriteKey, float ringWidth)
        {
            Pct = pct;
            RingColor = ringColor;
            RingSpriteKey = ringSpriteKey;
            RingWidth = ringWidth;
        }
    }

    // The single condition palette used everywhere a marker shows destruction
    // status: OutlineGold's ring, OutlineSameHue's ring+fill, and Badge's badge
    // fill all read from this same table -- the three styles never disagree about
    // colour. Every level, including 100%, is fully opaque (see _2_2_Marker_Design.md
    // §4 principle 3 for why).
    public static class StatusRamp
    {
        // Deliberately a cool, neutral grey -- outside the warm gold->rust family
        // used for known status levels below, so "unknown" reads as a genuinely
        // different kind of signal ("we don't know") rather than an extra point on
        // the destruction scale. Used for the universal "?" badge (§7 Step 7),
        // never blended with RingColor values.
        public static readonly Color UnknownColor = new Color(0.55f, 0.56f, 0.58f);

        public static readonly StatusLevel[] Levels =
        {
            new StatusLevel(0,   new Color(0.890f, 0.741f, 0.447f), "solid",       3.2f),
            new StatusLevel(20,  new Color(0.812f, 0.624f, 0.369f), "dash_long",   2.8f),
            new StatusLevel(40,  new Color(0.733f, 0.522f, 0.322f), "dash_medium", 2.4f),
            new StatusLevel(60,  new Color(0.651f, 0.416f, 0.271f), "dash_short",  2.0f),
            new StatusLevel(80,  new Color(0.549f, 0.302f, 0.235f), "dotted",      1.7f),
            new StatusLevel(100, new Color(0.431f, 0.200f, 0.169f), "dotted",      1.8f),
        };

        // Snaps an arbitrary 0-100 destruction percentage to the nearest authored
        // level. Callers MUST check POIData.has_status before calling this at all.
        public static StatusLevel Resolve(float pct)
        {
            var closest = Levels[0];
            float bestDist = float.MaxValue;
            foreach (var level in Levels)
            {
                float dist = Mathf.Abs(level.Pct - pct);
                if (dist < bestDist)
                {
                    bestDist = dist;
                    closest = level;
                }
            }
            return closest;
        }

        // Used by MarkerStyle.OutlineSameHue: drains saturation/value toward a
        // near-black neutral as status worsens, never reaching pure black.
        public static Color ShadeTowardBlack(Color baseColor, float pct)
        {
            Color.RGBToHSV(baseColor, out float h, out float s, out float v);
            float t = Mathf.Clamp01(pct / 100f);
            float s2 = s * (1f - 0.72f * t);
            float v2 = Mathf.Lerp(v, 0.09f, t * 0.92f);
            return Color.HSVToRGB(h, Mathf.Max(s2, 0.04f), Mathf.Max(v2, 0.07f));
        }
    }
}
```

```csharp
using System.Collections.Generic;
using UnityEngine;

namespace TileStories
{
    // A plain "key -> Sprite" lookup asset. Used as TWO separate .asset instances
    // in the project: IconLibrary.asset (key = "temple", "crown", ...) and
    // ShapeLibrary.asset (key = "circle", "hexagon", ...). Same data shape, one
    // class -- see _2_2_Marker_Design.md §4 principle 4.
    [CreateAssetMenu(fileName = "SpriteKeyLibrary", menuName = "TileStories/Sprite Key Library")]
    public class SpriteKeyLibrary : ScriptableObject
    {
        [System.Serializable]
        public struct Entry
        {
            public string key;
            public Sprite sprite;
        }

        [SerializeField] private List<Entry> entries = new();

        private Dictionary<string, Sprite> _lookup;

        public Sprite Get(string key)
        {
            if (string.IsNullOrEmpty(key)) return null;

            if (_lookup == null)
            {
                _lookup = new Dictionary<string, Sprite>();
                foreach (var e in entries)
                {
                    if (!string.IsNullOrEmpty(e.key) && e.sprite != null)
                        _lookup[e.key] = e.sprite;
                }
            }

            return _lookup.TryGetValue(key, out var sprite) ? sprite : null;
        }
    }
}
```

`Assets/Framework/Runtime/UI/Markers/MarkerRingView.cs`
```csharp
using UnityEngine;
using UnityEngine.UI;

namespace TileStories
{
    // Renders the outline ring for MarkerStyle.OutlineGold/OutlineSameHue. Dash
    // patterns are pre-made sprites swapped by key -- uGUI cannot draw a dashed
    // circle procedurally without a custom shader; this is the same low-tech
    // sprite-swap pattern used elsewhere in the project.
    public class MarkerRingView : MonoBehaviour
    {
        [SerializeField] private Image ringImage;
        [SerializeField] private RingSpriteSet spriteSet;

        public void Apply(StatusLevel level)
        {
            if (ringImage == null) return;
            ringImage.enabled = true;
            ringImage.color = level.RingColor;
            ringImage.sprite = spriteSet != null ? spriteSet.Get(level.RingSpriteKey) : null;
        }

        public void Hide()
        {
            if (ringImage != null) ringImage.enabled = false;
        }
    }

    [System.Serializable]
    public class RingSpriteSet
    {
        public Sprite solid;
        public Sprite dashLong;
        public Sprite dashMedium;
        public Sprite dashShort;
        public Sprite dotted;

        public Sprite Get(string key)
        {
            switch (key)
            {
                case "solid": return solid;
```

### Step 5 — Proportional layout (new file)

`Assets/Framework/Runtime/UI/Markers/MarkerLayout.cs`
```csharp
using UnityEngine;

namespace TileStories
{
    // Proportions, not pixels. Every offset is relative to the Symbol's own size,
    // so resizing the Symbol (Inspector, or later at runtime for LOD) re-derives
    // ring/badge/label correctly instead of drifting out of position. Defaults
    // match the Stage 2.3 HTML prototype ratios (ring 44 vs symbol 40 = 1.1x,
    // badge ~0.36x) so the browser prototype and shipped markers agree.
    [System.Serializable]
    public class MarkerLayoutProportions
    {
        [Range(1f, 1.3f)] public float ringSizeRatio = 1.1f;
        [Range(0.2f, 0.5f)] public float badgeSizeRatio = 0.36f;

        // Normalised direction from Symbol centre to Badge centre. (0.7, 0.7) =
        // outside-overlap, top-right -- the composition chosen after comparing all
        // four in the interactive prototype (see the HTML file's badge section).
        public Vector2 badgeDirection = new Vector2(0.7f, 0.7f);

        public float labelGap = 0.015f; // world units, symbol bottom edge -> label top
    }

    // Pure function of (symbol size, proportions) -> (ring/badge/label rects). No
    // MonoBehaviour state -- easy to unit test, safe to call from both Awake()
    // (runtime) and OnValidate() (live Editor preview without Play mode).
    public static class MarkerLayout
    {
        public static void Apply(
            RectTransform symbol,
            RectTransform ring,
            RectTransform badge,
            RectTransform label,
            MarkerLayoutProportions proportions)
        {
            if (symbol == null || proportions == null) return;

            Vector2 symbolSize = symbol.sizeDelta;
            float symbolRadius = symbolSize.x * 0.5f;

            if (ring != null)
            {
                ring.sizeDelta = symbolSize * proportions.ringSizeRatio;
                ring.anchoredPosition = symbol.anchoredPosition;
            }

            if (badge != null)
            {
                Vector2 badgeSize = symbolSize * proportions.badgeSizeRatio;
                badge.sizeDelta = badgeSize;
                badge.anchoredPosition = symbol.anchoredPosition
                    + Vector2.Scale(proportions.badgeDirection, new Vector2(symbolRadius, symbolRadius));
            }

            if (label != null)
            {
                Vector2 pos = label.anchoredPosition;
                pos.x = symbol.anchoredPosition.x;
                pos.y = symbol.anchoredPosition.y - symbolRadius - proportions.labelGap;
                label.anchoredPosition = pos;
            }
        }
    }
}
```

**Outer container — do not build a new one.** `POI_Marker`'s root GameObject already
serves as the container: it carries the World Space `Canvas` component *and* is the
Transform `WallSession`/`POIPositionResolver` move in AR space (confirmed by reading
the current prefab). Unity resolves a child RectTransform's rendered size as its own
`sizeDelta` scaled by the cumulative `lossyScale` of every parent Transform (Unity
Technologies, *RectTransform* / *Transform* Manual pages) — so scaling the root
`transform.localScale` already scales Symbol, Ring, Badge, Label, and any effects
together, automatically, with zero new code. `MarkerView.SetOverallScale(float)`
(added in Step 7 below) is the one clean handle for "resize the whole marker" — do
not add a second wrapper GameObject around the existing hierarchy.

```csharp
using UnityEngine;
using UnityEngine.UI;

namespace TileStories
{
    // Cheap, low-tech destruction-intensity cue: cycles a small set of pre-drawn
    // flame/smoke sprites on a plain Image. Same sprite-swap philosophy as
    // MarkerRingView -- no per-marker particle system, so safe to enable on every
    // burning marker on a wall at once on mobile AR. See MarkerParticleEffect for
    // the heavier opt-in alternative.
    //
    // Driven by status, not is_hero: MarkerView wires this from ApplyStatus, not
    // ApplyHeroState. A standard-tier POI at 90% destroyed still burns; a hero POI
    // with no status axis shows no fire.
    public class MarkerFireEffect : MarkerEffect
    {
        [SerializeField] private Image flameImage;
        [SerializeField] private Sprite[] emberFrames;  // status 40-59
        [SerializeField] private Sprite[] blazeFrames;  // status 60-79
        [SerializeField] private Sprite[] smokeFrames;  // status 80-100
        [SerializeField, Min(1f)] private float framesPerSecond = 6f;

        private Sprite[] _currentFrames;
        private float _timer;
        private int _frameIndex;
        private bool _active;

        public override void SetActive(bool active)
        {
            _active = active;
            if (flameImage != null) flameImage.enabled = active;
        }

        // Called from MarkerView.ApplyStatus alongside ring/badge - same status_pct
        // drives all three, so there is one destruction reading, expressed 3 ways.
        public void SetIntensity(float statusPct)
        {
            if (statusPct < 40f)
            {
                SetActive(false);
                return;
            }

            _currentFrames = statusPct < 60f ? emberFrames
                            : statusPct < 80f ? blazeFrames
                            : smokeFrames;

            bool hasFrames = _currentFrames != null && _currentFrames.Length > 0;
            SetActive(hasFrames);
            _frameIndex = 0;
            _timer = 0f;
            if (hasFrames && flameImage != null) flameImage.sprite = _currentFrames[0];
        }

        private void Update()
        {
            if (!_active || _currentFrames == null || _currentFrames.Length == 0 || flameImage == null) return;

            _timer += Time.deltaTime;
            float frameDuration = 1f / framesPerSecond;
            if (_timer >= frameDuration)
            {
                _timer -= frameDuration;
                _frameIndex = (_frameIndex + 1) % _currentFrames.Length;
                flameImage.sprite = _currentFrames[_frameIndex];
            }
        }
    }
}
```

### Step 7 — `MarkerView.cs` (full replacement)

```csharp
using TMPro;
using UnityEngine;

namespace TileStories
{
    // Visual representation of a POI marker in AR space (uGUI World Space Canvas
    // prefab). Wires label text, category fill/icon/shape, status ring-or-badge,
    // and hero-tier effects -- decides none of the actual colours, icons, or
    // sprites itself (see CategoryPalette, StatusRamp, IconLibrary, ShapeLibrary).
    //
    // v1 project: exactly one signature for Initialise (see _2_2_Marker_Design.md §3).
    public class MarkerView : MonoBehaviour
    {
        [Header("Text")]
        [SerializeField] private TextMeshProUGUI labelText;

        [Header("Shared circle+icon views (Symbol always present, Badge only for MarkerStyle.Badge)")]
        [SerializeField] private MarkerCircleGlyphView symbol;
        [SerializeField] private MarkerCircleGlyphView badge;
        [SerializeField] private MarkerRingView ring;

        [Header("Libraries (assign the shared project assets)")]
        [SerializeField] private SpriteKeyLibrary iconLibrary;
        [SerializeField] private SpriteKeyLibrary shapeLibrary;

        [Header("Layout - proportional, auto-adjusts to Symbol size")]
        [SerializeField] private MarkerLayoutProportions layout = new();

        [Header("Optional hero-tier effects (leave empty if this prefab variant has none)")]
        [SerializeField] private MarkerEffect[] heroEffects;

        [Header("Optional status-driven effect (leave unassigned if unused)")]
        [SerializeField] private MarkerFireEffect fireEffect;

        [Header("Overlap resolution")]
        [SerializeField] private float overlapOffsetAmount = 0.15f;

        private static readonly Color IconTint = new Color(0.949f, 0.925f, 0.827f); // cream

        private POIAnchor _anchor;
        private Vector3 _baseLocalPosition;
        private bool _hasBasePosition;

        public string PoiId { get; private set; }

        private void Awake() => ApplyLayout();

        private void OnValidate() => ApplyLayout();

        private void ApplyLayout()
        {
            RectTransform symbolRect = symbol != null ? symbol.RectTransform : null;
            RectTransform ringRect = ring != null ? (RectTransform)ring.transform : null;
            RectTransform badgeRect = badge != null ? badge.RectTransform : null;
            RectTransform labelRect = labelText != null ? (RectTransform)labelText.transform : null;
            MarkerLayout.Apply(symbolRect, ringRect, badgeRect, labelRect, layout);
        }

        public void Initialise(POIAnchor anchor, MarkerStyle markerStyle, MarkerShape markerShape)
        {
            _anchor = anchor;
            var data = anchor != null ? anchor.Data : null;
            PoiId = data != null ? data.id : string.Empty;
            if (data == null) return;

            ApplyLabel(data);
            ApplyCategory(data, markerStyle, markerShape);
            ApplyStatus(data, markerStyle);
            ApplyHeroState(data);
        }

        private void ApplyLabel(POIData data)
        {
            if (labelText == null) return;

            string name = data.name ?? string.Empty;
            if (name.Length > 29) name = name.Substring(0, 26) + "...";
            labelText.text = name;

            // Persistent label is a hero-tier privilege; standard POIs stay
            // label-free until a tap/selection interaction reveals it (not built
            // yet -- see §15).
            labelText.gameObject.SetActive(data.is_hero);
        }

        private void ApplyCategory(POIData data, MarkerStyle markerStyle, MarkerShape markerShape)
        {
            Color categoryColor = CategoryPalette.ResolveColor(data.category);
            string iconKey = CategoryPalette.ResolveIconKey(data.category);
            Sprite shapeSprite = shapeLibrary != null ? shapeLibrary.Get(ShapeKey(markerShape)) : null;
            Sprite iconSprite = iconLibrary != null ? iconLibrary.Get(iconKey) : null;

            // OutlineSameHue drains the FILL toward black as status worsens; the
            // other two styles keep the fill as a pure, constant category colour.
            // Skipped when status_unknown -- there's no known percentage to drain
            // toward, so the fill stays the plain category colour and the universal
            // "?" badge (ApplyStatus below) carries the whole signal instead.
            bool knownStatus = data.has_status && !data.status_unknown;

            Color fill = (markerStyle == MarkerStyle.OutlineSameHue && knownStatus)
                ? StatusRamp.ShadeTowardBlack(categoryColor, data.status_pct)
                : categoryColor;

            float iconOpacity = (markerStyle == MarkerStyle.OutlineSameHue && knownStatus)
                ? Mathf.Lerp(1f, 0.28f, Mathf.Clamp01(data.status_pct / 100f))
                : 1f;

            if (symbol != null)
            {
                symbol.SetBackground(shapeSprite, fill);
                symbol.SetIcon(iconSprite, IconTint, iconOpacity);
            }
        }

        private void ApplyStatus(POIData data, MarkerStyle markerStyle)
        {
            bool hasStatus = data.has_status;
            bool isUnknown = hasStatus && data.status_unknown;
            bool knownStatus = hasStatus && !isUnknown;

            if (ring != null)
            {
                // Unknown suppresses the normal ring entirely -- the "?" badge below
                // is the sole indicator in that case, across all three styles.
                bool useRing = knownStatus && markerStyle != MarkerStyle.Badge;
                if (useRing) ring.Apply(StatusRamp.Resolve(data.status_pct));
                else ring.Hide();
            }

            if (badge != null)
            {
                bool useOrdinalBadge = knownStatus && markerStyle == MarkerStyle.Badge;
                bool useUnknownBadge = isUnknown;
                badge.SetVisible(useOrdinalBadge || useUnknownBadge);

                // Badge is always circular regardless of the wall's chosen
                // marker_shape (see MarkerShape.cs) -- explicitly request "circle"
                // from ShapeLibrary rather than passing null. A uGUI Image with
                // sprite == null still renders a filled rectangle tinted by
                // Image.color (Unity's documented null-sprite behaviour), not an
                // empty or circular shape, so passing null here would silently
                // produce a square-ish badge.
                Sprite badgeShape = shapeLibrary != null ? shapeLibrary.Get("circle") : null;

                if (useUnknownBadge)
                {
                    // Same treatment regardless of markerStyle: a neutral-grey "?"
                    // badge, deliberately outside the gold->rust status family
                    // (StatusRamp.UnknownColor), so "we don't know" never reads as
                    // an extra point on the destruction scale.
                    Sprite questionIcon = iconLibrary != null ? iconLibrary.Get("unknown") : null;
                    badge.SetBackground(badgeShape, StatusRamp.UnknownColor);
                    badge.SetIcon(questionIcon, IconTint);
                }
                else if (useOrdinalBadge)
                {
                    var level = StatusRamp.Resolve(data.status_pct);
                    badge.SetBackground(badgeShape, level.RingColor);
                    badge.SetIcon(null, IconTint);
                }
            }

            if (fireEffect != null)
            {
                if (knownStatus) fireEffect.SetIntensity(data.status_pct);
                else fireEffect.SetActive(false);
            }
        }

        private void ApplyHeroState(POIData data)
        {
            if (heroEffects == null) return;
            foreach (var effect in heroEffects)
            {
                if (effect != null) effect.SetActive(data.is_hero);
            }
        }

        private static string ShapeKey(MarkerShape shape)
        {
            switch (shape)
            {
                case MarkerShape.Circle: return "circle";
                case MarkerShape.RoundedSquare: return "rounded_square";
                case MarkerShape.Hexagon: return "hexagon";
                case MarkerShape.Diamond: return "diamond";
                case MarkerShape.Star: return "star";
                default: return "circle";
            }
        }

        // Runtime hook for a future LOD system. This transform IS the outer
        // container (§7 Step 5) -- scaling it scales everything for free.
        public void SetOverallScale(float scale) => transform.localScale = Vector3.one * scale;

        public void ApplyOverlapOffset(float offsetIndex)
        {
            if (_anchor == null) return;
            if (!_hasBasePosition)
            {
                _baseLocalPosition = _anchor.transform.localPosition;
                _hasBasePosition = true;
            }
            Vector3 newPos = _baseLocalPosition;
            newPos.y += offsetIndex * overlapOffsetAmount;
            _anchor.transform.localPosition = newPos;
        }
    }
}
```

```csharp
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

namespace TileStories
{
    public class WallSession : MonoBehaviour
    {
        [Tooltip("Path inside StreamingAssets, e.g. 'LivingRoom/config.json'")]
        [SerializeField] private string configPath = "LivingRoom/config.json";

        [Tooltip("Prefab with a POIAnchor component. Required for runtime spawn.")]
        [SerializeField] private GameObject poiAnchorPrefab;

        [SerializeField] private Transform correctionAnchor;

        private IWallTracker _tracker;
        private WallConfigData _config;
        private MarkerStyle _markerStyle;
        private MarkerShape _markerShape;
        private readonly List<GameObject> _spawnedPOIs = new();
        private bool _didSpawn;
        private bool _configLoaded;

        private void Awake()
        {
            _tracker = GetComponent<IWallTracker>();
            if (_tracker == null)
                Debug.LogError("[WallSession] No IWallTracker component found on this GameObject.");

            if (poiAnchorPrefab == null)
                Debug.LogWarning("[WallSession] POI anchor prefab is not assigned.");

            if (correctionAnchor == null)

            StartCoroutine(LoadConfigCoroutine());
        }

        private void OnEnable()
        {
            if (_tracker != null) _tracker.OnWallLocalised += HandleWallLocalised;
        }

        private void OnDisable()
        {

        }

        private IEnumerator LoadConfigCoroutine()
        {
            yield return WallConfigLoader.LoadFromStreamingAssets(configPath, loaded => _config = loaded);
            if (_config == null) yield break;

            _configLoaded = true;
            _markerStyle = MarkerVisualsParser.ParseStyle(_config.marker_style);
            _markerShape = MarkerVisualsParser.ParseShape(_config.marker_shape);
            CategoryPalette.Configure(_config.category_styles);
            Debug.Log($"[WallSession] Loaded '{_config.wall_name}' - {_config.pois?.Count ?? 0} POIs. " +
                      $"marker_style={_markerStyle}, marker_shape={_markerShape}, " +
                      $"category overrides={_config.category_styles?.Count ?? 0}.");

            if (!_didSpawn && _tracker != null && _tracker.IsLocalised)
                HandleWallLocalised(_tracker.CurrentPose);
        }

        private void HandleWallLocalised(UnityEngine.Pose wallPose)
        {
            if (_didSpawn) return;
            if (!_configLoaded || _config == null || _config.pois == null)
            {
                Debug.Log("[WallSession] Localized before config loaded. Waiting for config...");
                return;
            }

            Debug.Assert(_config.pois.Count > 0, "[WallSession] POI list is empty.");
            Debug.Assert(_config.pois.TrueForAll(p => !string.IsNullOrEmpty(p.id)), "[WallSession] Empty POI id found.");

            Debug.Log($"[WallSession] Wall localised. Spawning {_config.pois.Count} POIs.");
            SpawnPOIs();
            _didSpawn = true;
        }

        private void SpawnPOIs()
        {
            CalibrationAnchor[] anchors = _config.calibration_anchors?.ToArray() ?? System.Array.Empty<CalibrationAnchor>();
            var stopwatch = System.Diagnostics.Stopwatch.StartNew();
            var spawnedMarkerViews = new List<MarkerView>();

            foreach (var poi in _config.pois)
            {
                if (!POIPositionResolver.TryResolvePosition(poi, anchors, out Vector3 localPos))
                {
                    Debug.LogWarning($"[WallSession] Skipping POI '{poi.id}' - position could not be resolved.");
                    continue;
                }

                var go = poiAnchorPrefab != null
                    ? Instantiate(poiAnchorPrefab, correctionAnchor != null ? correctionAnchor : transform)
                    : CreateAnchorOnlyObject(correctionAnchor != null ? correctionAnchor : transform, poi.id);

                go.transform.localPosition = localPos;
                go.transform.localRotation = Quaternion.identity;
                go.name = poi.id;

                var anchor = go.GetComponent<POIAnchor>() ?? go.AddComponent<POIAnchor>();
                anchor.Initialise(poi);

                var markerView = go.GetComponentInChildren<MarkerView>();
                if (markerView != null)
                {
                    markerView.Initialise(anchor, _markerStyle, _markerShape);
                    spawnedMarkerViews.Add(markerView);
                }

                _spawnedPOIs.Add(go);

                var cam = Camera.main;
                if (cam != null)
                {
                    Vector3 worldPos = go.transform.position;
                    var toMarker = worldPos - cam.transform.position;
                    var distance = toMarker.magnitude;
                    var forwardDot = Vector3.Dot(cam.transform.forward, toMarker.normalized);
                    Debug.Log($"[WallSession] POI ready id={poi.id} localPos={localPos} dist={distance:F2}m inFront={forwardDot > 0f} dot={forwardDot:F3}");
                }
                else
                {
                    Debug.Log($"[WallSession] POI ready id={poi.id} localPos={localPos} (no Camera.main found)");
                }
            }

            MarkerOverlapResolver.ApplyOverlapOffsets(spawnedMarkerViews, Camera.main);

            stopwatch.Stop();
            Debug.Log($"[WallSession] Ready {_spawnedPOIs.Count}/{_config.pois.Count} POIs in {stopwatch.ElapsedMilliseconds}ms.");
        }

        private static GameObject CreateAnchorOnlyObject(Transform parent, string poiId)
        {
            var go = new GameObject($"POI_{poiId}_Anchor");
            go.transform.SetParent(parent);
            return go;
        }
    }
```

## 11. Prefab wiring (manual Editor steps — cannot be scripted safely)

Unity's prefab `.yaml` format uses Editor-generated file IDs/GUIDs; hand-editing
that file outside the Editor risks a corrupted prefab. Do this in the Editor
directly, ~10 minutes:

Current `POI_Marker.prefab` hierarchy:
```
POI_Marker (Canvas, World Space)
├── Ring (Image)
├── Symbol (Image + child "Icon" Image)
├── Badge (duplicate of Symbol, inactive)
├── Label (TextMeshProUGUI)
└── Optional hero effect components on the root:
    ├── MarkerPulseEffect
    ├── MarkerSunEffect
    └── MarkerGlowEffect (legacy/optional, currently kept inactive)
```

Steps:
1. **Symbol**: add child Image `Icon`, RectTransform stretched to fill Symbol,
   `Image.Type = Simple`, sprite empty (set at runtime). Add `MarkerCircleGlyphView`
   to Symbol itself; drag Symbol's own Image into `Background`, the new `Icon` Image
   into `Icon`.
2. **Badge**: duplicate the whole Symbol GameObject (with its Icon child), rename to
   `Badge`, set inactive. Its `MarkerCircleGlyphView` wiring carries over from the
   duplicate.
3. **Ring**: new Image GameObject `Ring`, sibling of Symbol, earlier in the
   hierarchy (renders underneath). Add `MarkerRingView`, drag Ring's Image into
   `Ring Image`, assign the 5 `ring_*.png` sprites under `Sprite Set`.
4. On **POI_Marker** root, `MarkerView`'s Inspector fields: assign `Symbol`,
   `Badge`, `Ring` (steps 1-3), `Icon Library`/`Shape Library` (§10).
5. **Optional hero effects**: add `MarkerPulseEffect` and `MarkerSunEffect`
    components to POI_Marker. `MarkerView` wires both to the Symbol's RectTransform
    and toggles them via composable `HeroEffectMode` flags (`Pulse`, `SunCircles`,
    `SunContours`, and mixed `Pulse+Sun...` modes). `MarkerGlowEffect`
   may remain present as legacy wiring, but it is not part of the supported hero
   variants in the final runtime.
6. Save. Sanity-check with the example config below.

### 17.0 (P0, addendum after round 2 — read this first)

After the corrections below were handed to the agent, the same crash was reported
again. Re-auditing a fresh export found **two separate things true at once**:

1. **The agent's proposed Icons/Shapes `.meta` fix was never actually applied.**
   All 9 icon `.meta` files and all 4 non-circle shape `.meta` files still show
   `spriteMode: 0, textureType: 0` (Default texture, not Sprite) — the agent's own
   diagnosis was correct, but ended in "Would you like me to proceed with this fix?
   You'll need to toggle to Act mode" and, from the evidence in the files, that step
   never actually ran. Only `Rings/` got genuinely corrected. Right now
   `IconLibrary.asset` (9 entries) and `ShapeLibrary.asset` (4 of 5 entries) hold
   sprite references that resolve to nothing, because a Default-imported texture has
   no Sprite sub-object at `fileID: 21300000` at all.

2. **That is not what's causing the current crash.** The Symbol Image — the one
   actually enabled on every marker instance, the one from the original report — was
   independently re-checked and genuinely does say
   `m_Sprite: {fileID: 21300000, guid: 5d0eb3736734d354785c36452f21f5bf, type: 3}`,
   and `SymbolCircle.png.meta` genuinely has the correct
   `spriteMode: 1, textureType: 8, alphaIsTransparency: 1`. On paper, this exact
   reference — the one the original crash was about — is now correct on both ends.

**"The file is textually correct, but Unity throws the identical error" is a known,
documented Unity behaviour, not a contradiction.** Unity's own AssetDatabase does
not always detect and fully re-resolve changes made to `.meta`/`.prefab` files by a
process other than a live, running Unity Editor session — this is exactly why
Editor-scripting utilities exist specifically to force a manual `AssetDatabase`
refresh/reimport for "a file changed outside of Unity's own API." There is also a
documented real case (Unity Discussions) of a prefab reference displaying correctly
inside Prefab Edit mode while showing as lost everywhere else, traced to a stale
`Library/` cache after changes made outside the normal Editor workflow — resolved by
a forced reimport. Given every file edit in this whole workflow happens via an
agent operating on disk, not through a running Unity Editor, this is the most
likely explanation and should be tried before assuming the reference itself is
wrong again.

**Do this, in order:**
1. In the Unity Editor: right-click `Assets` (or just the `Markers` folder) →
   **Reimport**. This forces Unity to discard whatever it has cached for these
   assets and rebuild the artifacts from the files actually on disk.
2. If the error persists: **Assets → Reimport All** (forces every asset in the
   project through the importer again).
3. If it *still* persists: close the Unity Editor, delete the local `Library/`
   folder (this is a fully regenerable cache, not source data — safe to delete),
   reopen the project. This guarantees zero stale cached artifacts, at the cost of
   a slower first load while Unity rebuilds everything.
4. **Separately, and regardless of whether steps 1–3 fix the crash**: actually apply
   the Icons/Shapes `.meta` correction this time — all 13 files, not just `Rings/`.
   `spriteMode: 1`, `textureType: 8`, `alphaIsTransparency: 1` for every PNG in
   `Icons/` and `Shapes/`. This isn't the cause of today's crash, but it is a live
   landmine: the moment a category resolves to a known icon (see
   `CategoryPalette.KnownIcons`) or a wall picks a non-circle `marker_shape`, this
   exact exception will fire again from that new spot, and it will look like a
   brand new bug if this note isn't remembered.
5. **Going forward**, treat any agent-driven edit to a `.meta`/`.prefab`/`.asset`
   file as needing a Reimport pass *before* testing in Play Mode — this specific
   "fix looks correct in the text, error persists identically" confusion is the
   textbook symptom of skipping that step, not evidence the fix was wrong.

This section is what the crash looked like on the *first* pass, before anything had
been touched. Keeping it because it explains the underlying mechanics precisely and
because the Editor-based remediation in it is still the right way to fix the
reference by hand if 17.0's reimport steps don't resolve it.

**Root cause, precisely:** `POI_Marker.prefab`'s **Symbol** GameObject's `Image`
component has:
```
m_Sprite: {fileID: 2800000, guid: 5d0eb3736734d354785c36452f21f5bf, type: 3}
```
`fileID: 2800000` is Unity's fixed internal ID for the **Texture2D** sub-object of an
imported image — not the **Sprite** sub-object, which is `fileID: 21300000` for a
single-sprite-mode texture. `Image.sprite` is typed `Sprite`; pointing it at a
Texture2D is a type-mismatched reference, which Unity reports as exactly this error
("the variable m_Sprite of Image doesn't exist anymore") the moment anything touches
it — first in `Image.OnEnable()` → `TrackSprite()` (your first error), then again
every time the canvas rebuilds the mesh, in `OnPopulateMesh()` → `GetDrawingDimensions()`
→ `Sprite.GetPadding()` (your second error — **same root cause, different call
stack**, not a new problem).

Proof this is the right diagnosis: `ShapeLibrary.asset`'s own `circle` entry
references the *exact same* `guid: 5d0eb373...` but correctly uses
`fileID: 21300000` — so the correct reference for this exact sprite is sitting right
next to the broken one in your own project.

**Why the agent's fix didn't help:** `Image.OnEnable()` fires synchronously the
instant `Instantiate()` creates the GameObject — this is *before* `WallSession` ever
calls `MarkerView.Initialise()`. The agent's null-checks live inside
`MarkerCircleGlyphView.SetBackground()`/`SetIcon()`, which only run once
`Initialise()` reaches them. By the time that code executes, the crash has already
happened during instantiation. The null-checks are reasonable defensive code in
general, but they were never going to fix a bad reference baked into the prefab's
own serialized data — that data is wrong before any of your C# runs at all.

**The fix (do this in the Unity Editor, not by hand-editing YAML again):**
1. Open `POI_Marker.prefab` in Prefab isolation mode.
2. Select **Symbol** → its `Image` component → the `Source Image` field currently
   shows a broken/missing reference (or shows `SymbolCircle` but is actually broken
   underneath — check by clicking the field's object picker; a genuinely-broken
   reference usually still shows the last-known name greyed out).
3. Clear the field, then drag `SymbolCircle` sprite from the Project window back
   into `Source Image`. Dragging through the Editor always writes the correct
   `fileID: 21300000` — this sidesteps the whole class of hand-edited-YAML fileID
   mistakes going forward.
4. Save the prefab. Enter Play Mode — the `MissingReferenceException` should be gone.

If you'd rather not use the Editor for this one field, the direct YAML fix is
changing `fileID: 2800000` to `fileID: 21300000` in that one line — but **verify by
opening the prefab in the Editor afterward** and confirming the Symbol's Image shows
`SymbolCircle` correctly in the Inspector before trusting it, precisely because a
hand-edited fileID is how this bug got introduced in the first place.

### 17.2 (P0, will surface immediately after 17.1) — Ring renders as a solid rectangle

**Root cause:** `MarkerRingView`'s `spriteSet` (all five dash-pattern sprites —
`solid`/`dashLong`/`dashMedium`/`dashShort`/`dotted`) are **all unassigned**
(`fileID: 0`) in the prefab. `MarkerRingView.Apply()` correctly only reassigns
`ringImage.sprite` when the looked-up sprite is non-null — but since every entry in
`spriteSet` is null, the ring `Image` component's sprite is *never set at all*,
while `ringImage.enabled = true` and `ringImage.color = level.RingColor` still run.

An Unity `Image` with `sprite == null` still renders — as a **filled rectangle**
tinted by `Image.color` (this is Unity's documented behaviour for a null-sprite
Image, not a bug in your code). So once 17.1 lands, every marker with
`has_status: true` and `marker_style` other than `badge` will show a solid colored
rectangle sized by `ringSizeRatio` behind the Symbol — not a ring, not dashed,
just a block of colour. This will look like a new bug; it's actually the same root
issue as 17.3 below (missing sprite assets), just showing up here first because
`outline_gold` is the current `marker_style` in your test config.

**Fix:** covered by 17.3 — importing the ring sprites and wiring
`MarkerRingView`'s `spriteSet` fields resolves this.

### 17.6 (P2) — shape key lookup will break for every multi-word shape

**Current code:** `shapeLibrary?.Get(_shape.ToString().ToLowerInvariant())`. For
`MarkerShape.Circle` this happens to work (`"circle"`), but for
`MarkerShape.RoundedSquare` it produces `"roundedsquare"` — no underscore — which

```csharp
private static string ShapeKey(MarkerShape shape) => shape switch

    MarkerShape.RoundedSquare => "rounded_square",
    MarkerShape.Hexagon => "hexagon",
    MarkerShape.Diamond => "diamond",
    MarkerShape.Star => "star",
    _ => "circle",
};
```
and call `shapeLibrary?.Get(ShapeKey(_shape))` instead of the `.ToString()` version.

## 18. Marker Gallery — verification testing strategy

Added after the "brown square" report made clear that config.json-driven testing
alone wasn't catching rendering problems fast enough. One data-driven test-case list
feeds two consumers: a Play Mode scene a human eyeballs, and a PlayMode test suite
an agent runs via Unity MCP with zero screenshots involved. Both use the real
`POI_Marker` prefab and the real `MarkerView`/`WallSession` code path — this is not
a reimplementation, it's the same system fed fabricated data instead of
`config.json`.

### 18.1 Two tiers, not one

**Tier 1 — offline gallery scene.** Plain Unity scene, plain camera, no Immersal,
no tracking. Every style/shape/status/effect combination laid out in a labeled
grid. A `Quad` with a real wall photo behind the grid gets the "does this stay
legible against a noisy background" check — the original point of the HTML
prototypes' simulated AR view — without needing a phone or a real wall.

**Tier 2 — the real app.** If Tier 1 already proved every combination renders
correctly in isolation, Tier 2 only needs to prove the *real* pipeline wiring
(tracking → position → spawn) works, using the handful of real POIs already in
`config.json`. Nothing new to build for Tier 2 — it's the app already built.

### 18.2 Mandatory build order — read this before writing any code

**Do not build the full gallery in one pass and then debug 46 markers at once.**
Build in the phases below, strictly in order, and do not start phase *N+1* until
phase *N*'s checklist is fully green. Each phase adds a small, attributable amount
of new surface area — if something breaks, it's whatever was *just* added, not a
needle in a haystack of simultaneous changes. This is the direct fix for exactly
the debugging experience this project already had with markers: everything built
at once, then a long, confusing hunt through many possible causes at the same time.

| Phase | What | Gate before continuing |
|---|---|---|
| 0 | Empty scene + camera + backdrop, **zero markers** | Scene loads clean, no console errors |
| 1 | **One** marker, simplest possible case | MCP structural test green + one quick human glance |
| 2 | Remaining groups, **one group at a time** (7 steps) | MCP tests green after *each* group before adding the next |
| 3 | Full 46-entry gallery | Full MCP suite green + one full human visual pass |
| 4 | Apply/confirm against the real AR app (Tier 2) | Real `config.json` POIs render correctly too |

### 18.3 Where the backdrop image goes

`Assets/Dev/MarkerGallery/Backdrops/` — colocated with the gallery scene itself
(§18.4), clearly separated from both `Framework/` (reusable code) and `Apps/`
(real wall content), so there's never any ambiguity about whether it's production
content.

**The user will provide the actual image path in a follow-up message when this
document is handed over — do not block Phase 0 on it.** If the path hasn't been
given yet: use a plain dark-grey placeholder material on the backdrop `Quad`,
finish Phase 0 with that, and swap in the real texture (one field, one drag)
whenever the path arrives — this never blocks anything downstream, since nothing
about marker rendering depends on what the backdrop looks like.

`Assets/Framework/Runtime/DevTools/MarkerGalleryHarness.cs` — this file is written

```csharp
using System.Collections.Generic;
using TMPro;
using UnityEngine;

namespace TileStories
{
    // Play Mode only, lives in MarkerGalleryScene.unity (never added to Build
    // Settings). Spawns every MarkerGalleryDefinitions.Entries through the exact
    // same POI_Marker prefab and MarkerView.Initialise call WallSession uses --
    // no config.json, no WallConfigLoader, no tracking.
    public class MarkerGalleryHarness : MonoBehaviour
    {
        [SerializeField] private GameObject poiMarkerPrefab;
        [SerializeField] private TextMeshProUGUI groupLabelPrefab; // optional, world-space TMP text
        [SerializeField] private float columnSpacing = 0.25f;
        [SerializeField] private float rowSpacing = 0.45f;

        private void Start()
        {
            CategoryPalette.Configure(MarkerGalleryDefinitions.Overrides);

            string currentGroup = null;
            int row = -1;
            int col = 0;

            foreach (var entry in MarkerGalleryDefinitions.Entries)
            {
                if (entry.Group != currentGroup)
                {
                    currentGroup = entry.Group;
                    row++;
                    col = 0;
                    if (groupLabelPrefab != null)
                    {
                        var groupText = Instantiate(groupLabelPrefab, transform);
                        groupText.text = currentGroup;
                        groupText.transform.localPosition = new Vector3(-0.3f, -row * rowSpacing, 0f);
                    }
                }

                SpawnEntry(entry, row, col);
                col++;
            }

            Debug.Log($"[MarkerGallery] Spawned {MarkerGalleryDefinitions.Entries.Count} entries across {row + 1} groups.");
        }

        private void SpawnEntry(MarkerGalleryEntry entry, int row, int col)
        {
            var go = Instantiate(poiMarkerPrefab, transform);
            go.transform.localPosition = new Vector3(col * columnSpacing, -row * rowSpacing, 0f);
            go.name = $"Gallery_{entry.Group}_{entry.Label}";

            var poiData = new POIData
            {
                id = go.name,
                name = entry.Label,
                category = entry.Category,
                status_pct = entry.StatusPct,
                has_status = entry.HasStatus,
                status_unknown = entry.StatusUnknown,
                is_hero = entry.IsHero,
                has_captured_position = true,
            };

            var anchor = go.GetComponent<POIAnchor>() ?? go.AddComponent<POIAnchor>();
            anchor.Initialise(poiData);

            var markerView = go.GetComponentInChildren<MarkerView>();
            markerView.Initialise(anchor, entry.Style, entry.Shape);

            LogResult(entry, go);
        }

        // Structured, greppable, MCP-queryable -- one line per marker, every
        // field an agent needs to verify correctness without seeing anything.
        private void LogResult(MarkerGalleryEntry entry, GameObject go)
        {
            var images = go.GetComponentsInChildren<UnityEngine.UI.Image>(includeInactive: true);
            var parts = new List<string>();
            foreach (var img in images)
            {
                parts.Add($"{img.gameObject.name}(active={img.gameObject.activeInHierarchy}," +
                          $"enabled={img.enabled},sprite={(img.sprite != null ? img.sprite.name : "NULL")}," +
                          $"color=#{ColorUtility.ToHtmlStringRGBA(img.color)})");
            }
            Debug.Log($"[MarkerGallery] {entry.Group} | {entry.Label} || " + string.Join(" ", parts));
        }
    }
}
```

### 18.12 Sun effect still renders as a square in the human visual pass (2026-08-01)

Despite 18.11.6's diagnostics reporting green (21/21 PlayMode, including
`HeroSunVariants_RenderCircularSprites_NotSquareQuads`), the human screenshot
pass over `MarkerGalleryScene` shows `SunInner`/`SunMiddle`/`SunOuter` as hard,
axis-aligned rectangles behind the marker for every hero entry with a sun
effect active — both `Contours` and `FilledCircles`, across all four hero style
groups. `Pulse`-only entries (no sun) render correctly. This is the exact
failure mode Tier 1 in §6.5 exists to catch: an automated pass and a human
pass disagreeing means the automated pass isn't measuring the thing the human
is actually looking at — not that the human is wrong.

**Do not re-run the existing assertions expecting a different answer.** They
are checking real data and passing honestly. The gap is *what* they check.

#### 18.12.1 Why the passing test doesn't cover this

`HeroSunVariants_RenderCircularSprites_NotSquareQuads` (and the harness's
`[SUNCHECK]` logging) reads `image.sprite.texture.GetPixel(...)` at each
corner, on the sprite that is live *at that instant, in that Play session*.
`BuildRingSprite`/`BuildFilledCircleSprite` are genuinely correct — the alpha
math (`d <= outer && d >= inner`, radial distance from center) produces a
properly transparent-cornered circle every time they run. That was verified
by hand, not just trusted: re-deriving the math independently gives the same
result. So the *data* is fine, and the test correctly says so. What it cannot
see is whether the sprite `image.sprite` points to *at render time, in the
person's own Play session* is still that same freshly-built sprite, or a
stale reference to one Unity already destroyed.

#### 18.12.2 Leading hypothesis — stale static sprite cache surviving across Play sessions

```csharp
private static Sprite s_contourInnerSprite;
...
private static Sprite GetContourInnerSprite() => s_contourInnerSprite ??= BuildRingSprite(256, 0.86f, 0.58f);
```

`s_contourInnerSprite`/`Middle`/`Outer`/`s_filledSprite` are `static`, so they
outlive any single `MarkerSunEffect` instance and persist for the life of the
C# domain. Two Unity facts combine to make this specific pattern break exactly
the way the screenshot shows:

1. Any object created at runtime via `Sprite.Create`/`new Texture2D` (not an
   imported asset) is destroyed by the Editor when Play Mode is exited.
2. If **Edit → Project Settings → Editor → Enter Play Mode Settings → Reload
   Domain** is **disabled** (a common perf setting for faster iteration, and
   worth checking directly rather than assuming), C# `static` fields are
   *not* reset when Play Mode is re-entered. `s_contourInnerSprite` keeps
   pointing at the same `Sprite` object it always did — except that object
   was destroyed when the previous Play session ended.

The catch is `??=`. The C# `??`/`??=` null-coalescing operators perform a raw
CLR reference-null check — they do **not** call `UnityEngine.Object`'s
overloaded `==`/`!=`, which is the operator Unity relies on to make a
destroyed-but-not-`null` object ("fake null") report as `null`. So after a
Stop → Play cycle with Reload Domain off, `s_contourInnerSprite ??= ...` sees
a non-null C# reference, skips regeneration, and hands back a destroyed
`Sprite`. Assigning a destroyed sprite to `Image.sprite` is functionally
equivalent to assigning `null` — Unity's `Image` falls back to filling the
raw `RectTransform` rect with the graphic's tint colour, no shape masking at
all, i.e. exactly the sharp-cornered rectangle in the screenshot.

This also explains the specific pattern of evidence, not just the bug itself:
a single, continuous Play session (which is what the batch-mode/MCP test run
is) never crosses that boundary, so the sprite is built once, stays valid,
and the assertions pass honestly. The manual visual-verification pass happens
in the same long-running interactive Editor session where Play Mode had
already been entered and exited at least once before (per §18.5/§18.8, at
least two manual glances happen before this point) — the exact "fresh
batch-mode process vs. long-running Editor session" asymmetry §6.3 already
calls out for stale caches, just at the C#-static-field layer instead of the
AssetDatabase layer.

#### 18.12.3 Confirm before fixing — cheap checks, in order

Per §6.2's rule (write out the fix candidates, don't guess-and-check), confirm
which of these is actually happening before editing code:

## 19. Modular effects expansion, richer test config, and Editor-tab live preview (2026-08-01)

This section covers three connected asks: more, better-spread test POIs in
`config.json`; four new marker capabilities that must work on *any* marker,

### 19.0 The modularity questions, answered directly

Before designing anything new, it's worth confirming what's already correct,
so nothing gets needlessly rebuilt:

- **"Should Symbol and Badge be one file with a flag for size/position?"**
  Already exactly this. `MarkerCircleGlyphView` (`Assets/Framework/Runtime/UI/
  Markers/MarkerCircleGlyphView.cs`) is one class — "renders one 'coloured
  shape + centred icon' element," per its own header comment — reused at two
  sizes/positions by `MarkerView` for both Symbol and Badge. No change
  needed; this is the pattern to imitate, not replace.
- **"Should the gold/hue contour be one file with a flag/colour?"** Already
  exactly this too. `MarkerRingView` takes a `StatusLevel` and an optional
  colour override and swaps a dash-pattern sprite by key — one class, no
  gold/hue duplication. `rotate_contour` (§19.6) is a small addition to this
  *same* file, not a new one.
- **"Should each new effect be its own file, importable/composable onto any
  marker?"** Yes for the animation/behaviour layer (`MarkerAccentEffect`,
  §19.5) — one new file, not three, since Simple Sun / Ring Pulse / Beacon
  turn out to be the same class with two small enum choices (shape × motion),
  not three unrelated effects. But the expensive, fragile part —
  `Texture2D`/`Sprite` generation and its caching — should live in exactly
  **one** shared place (`MarkerCircleSpriteFactory`, §19.3), used by both
  `MarkerSunEffect` and `MarkerAccentEffect`, so §18.12's fix only has to
  exist once. This is the general rule going forward for this domain: share
  the part that's fragile/expensive to get right twice; keep separate the
  parts that are genuinely different behaviours (a 3-layer staggered
  composition vs. a single layer is a real behavioural difference, not
  duplication for its own sake).
- **"Is a per-frame animation formula (Sin breathing, sawtooth beacon) worth
  its own shared helper too?"** No — deliberately left inline in each
  effect class. It's 2-3 lines, already mirrors `MarkerPulseEffect`'s and
  `MarkerSunEffect`'s existing per-frame math almost verbatim, and forcing a
  shared abstraction for a two-line formula used by 2-3 call sites adds
  indirection without reducing risk the way the sprite-cache sharing does.

### 19.3 Shared circle/ring sprite factory — new file `MarkerCircleSpriteFactory.cs`

New file: `Assets/Framework/Runtime/UI/Markers/MarkerCircleSpriteFactory.cs`.
This supersedes §18.12.4's fix-in-place sketch — **apply the domain-reload
fix here, once, not separately inside `MarkerSunEffect`.** If §18.12 hasn't
been implemented yet when this section is picked up, do both fixes as one
step by writing this file directly (skip patching `MarkerSunEffect` in place
per 18.12.4 and instead do §19.4's delegation below).

```csharp
using System.Collections.Generic;
using UnityEngine;

namespace TileStories
{
    // Single shared source of runtime-generated circle/ring sprites for every
    // marker accent effect (MarkerSunEffect, MarkerAccentEffect). Centralising
    // this means the domain-reload-safety fix from §18.12 only has to exist in
    // one place -- do not reimplement sprite generation or its caching in any
    // individual effect file; call in here instead.
    public static class MarkerCircleSpriteFactory
    {
        private const int TextureSize = 256;

        private static readonly Dictionary<(int outer, int inner), Sprite> s_ringCache = new();
        private static readonly Dictionary<int, Sprite> s_filledCache = new();

        // §18.12: explicit null checks (not ??=) -- UnityEngine.Object's overloaded
        // == correctly reports a destroyed sprite as null; ??='s raw CLR check does
        // not, which is exactly how the original square-render bug happened.
        public static Sprite GetRing(float outerScale, float innerScale)
        {
            var key = (Quantize(outerScale), Quantize(innerScale));
            if (s_ringCache.TryGetValue(key, out var sprite) && sprite != null)
                return sprite;

            sprite = BuildRingSprite(TextureSize, outerScale, innerScale);
            s_ringCache[key] = sprite;
            return sprite;
        }

        public static Sprite GetFilled(float radiusScale)
        {
            var key = Quantize(radiusScale);
            if (s_filledCache.TryGetValue(key, out var sprite) && sprite != null)
                return sprite;

            sprite = BuildFilledCircleSprite(TextureSize, radiusScale);
            s_filledCache[key] = sprite;
            return sprite;
        }

        // Forces the cache empty at the start of every logical run -- fires on
        // every Play Mode entry and process start, whether or not domain reload
        // ran. This is the actual fix for §18.12's stale-static-cache bug; the
        // explicit null checks above are defence in depth for the same class of
        // problem within a single session.
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
        private static void ResetCaches()
        {
            s_ringCache.Clear();
            s_filledCache.Clear();
        }

        private static int Quantize(float scale) => Mathf.RoundToInt(scale * 1000f);

        private static Sprite BuildRingSprite(int size, float outerRadiusScale, float innerRadiusScale)
        {
            var texture = new Texture2D(size, size, TextureFormat.RGBA32, false, true);
            texture.wrapMode = TextureWrapMode.Clamp;
            texture.filterMode = FilterMode.Bilinear;

            float center = (size - 1) * 0.5f;
            float outer = center * outerRadiusScale;
            float inner = center * innerRadiusScale;

            for (int y = 0; y < size; y++)
            {
                for (int x = 0; x < size; x++)
                {
                    float dx = x - center;
                    float dy = y - center;
                    float d = Mathf.Sqrt(dx * dx + dy * dy);
                    float alpha = d <= outer && d >= inner ? 1f : 0f;
                    texture.SetPixel(x, y, new Color(1f, 1f, 1f, alpha));
                }
            }

            texture.Apply(false, false);
            return Sprite.Create(texture, new Rect(0, 0, size, size), new Vector2(0.5f, 0.5f), size);
        }

        private static Sprite BuildFilledCircleSprite(int size, float radiusScale)
        {
            var texture = new Texture2D(size, size, TextureFormat.RGBA32, false, true);
            texture.wrapMode = TextureWrapMode.Clamp;
            texture.filterMode = FilterMode.Bilinear;

            float center = (size - 1) * 0.5f;
            float radius = center * radiusScale;

            for (int y = 0; y < size; y++)
            {
                for (int x = 0; x < size; x++)
                {
                    float dx = x - center;
                    float dy = y - center;
                    float d = Mathf.Sqrt(dx * dx + dy * dy);
                    float alpha = d <= radius ? 1f : 0f;
                    texture.SetPixel(x, y, new Color(1f, 1f, 1f, alpha));
                }
            }

            texture.Apply(false, false);
            return Sprite.Create(texture, new Rect(0, 0, size, size), new Vector2(0.5f, 0.5f), size);
        }
    }
}
```

### 19.5 New file `MarkerAccentEffect.cs` — Simple Sun / Ring Pulse / Beacon in one class

New file: `Assets/Framework/Runtime/UI/Markers/MarkerAccentEffect.cs`. One
reusable single-ring-or-disc accent, usable on *any* marker. Two independent
choices — `AccentShape` (what it looks like) and `AccentMotion` (how it
animates) — cover all three requested effects:

| Requested effect | AccentShape | AccentMotion |
|---|---|---|
| "Sun effect simple" (big semi-transparent disc, always visible, pulses) | `FilledCircle` | `Breathe` |
| "Ring pulse" (thin line, grows/shrinks a bit, colour/alpha constant) | `Contour` | `Breathe` |
| "Beacon" (grows more, fades to transparent, resets to small+solid) | `Contour` | `Beacon` |

```csharp
using UnityEngine;
using UnityEngine.UI;

namespace TileStories
{
    // Single reusable accent ring/disc, usable on ANY marker (not hero-gated) --
    // covers SimpleSun (filled, breathing), RingPulse (thin contour, breathing),
    // and Beacon (thin contour, grow+fade sawtooth) from one class + two enums,
    // rather than three near-identical effect files. Shares sprite generation
    // with MarkerSunEffect via MarkerCircleSpriteFactory (§19.3) -- this class
    // never builds a Texture2D itself.
    public class MarkerAccentEffect : MarkerEffect
    {
        public enum AccentShape { FilledCircle, Contour }
        public enum AccentMotion { Breathe, Beacon }

        [SerializeField] private RectTransform target;
        [SerializeField] private Image accentImage;
        [SerializeField] private AccentShape shape = AccentShape.FilledCircle;
        [SerializeField] private AccentMotion motion = AccentMotion.Breathe;
        [SerializeField] private Color baseTint = new Color(0.949f, 0.792f, 0.443f, 1f);
        [SerializeField, Range(0f, 1f)] private float baseAlpha = 0.28f;
        [SerializeField] private float size = 0.24f;
        [SerializeField, Range(0.72f, 0.98f)] private float contourOuterScale = 0.90f;
        [SerializeField, Range(0.5f, 0.9f)] private float contourInnerScale = 0.80f;
        [SerializeField, Range(0.85f, 1f)] private float filledRadiusScale = 0.84f;

        // Breathe: gentle, always-visible scale oscillation, constant alpha.
        [SerializeField, Range(0f, 0.4f)] private float breatheAmplitude = 0.15f;
        [SerializeField, Min(0.1f)] private float period = 2.0f;

        // Beacon: sawtooth grow+fade, resets to small+solid each cycle. Same
        // shape of animation as MarkerSunEffect.AnimateCircle, deliberately
        // not factored into a shared helper -- see §19.0's reasoning.
        [SerializeField] private float beaconStartScale = 1.0f;
        [SerializeField] private float beaconEndScale = 1.8f;

        private bool _active;
        private Vector3 _baseScale = Vector3.one;

        public bool IsActive => _active;

        public void Configure(RectTransform configuredTarget, AccentShape accentShape, AccentMotion accentMotion)
        {
            target = configuredTarget;
            shape = accentShape;
            motion = accentMotion;
            if (target == null) return;
            _baseScale = target.localScale;
            EnsureImage();
        }

        public override void SetActive(bool active)
        {
            _active = active;
            EnsureImage();
            if (accentImage == null) return;
            accentImage.enabled = active;
            if (!active) ResetVisual();
        }

        private void Update()
        {
            if (!_active || accentImage == null) return;

            if (motion == AccentMotion.Breathe)
            {
                float wave = Mathf.Sin(Time.time * Mathf.PI * 2f / period) * 0.5f + 0.5f;
                float scale = 1f + breatheAmplitude * wave;
                accentImage.rectTransform.localScale = _baseScale * scale;
                var c = baseTint;
                c.a = baseAlpha;
                accentImage.color = c;
            }
            else // Beacon
            {
                float t = Mathf.Repeat(Time.time / period, 1f);
                float smooth = t * t * (3f - 2f * t);
                float scale = Mathf.Lerp(beaconStartScale, beaconEndScale, smooth);
                float fade = Mathf.Lerp(baseAlpha, 0f, smooth);
                accentImage.rectTransform.localScale = _baseScale * scale;
                var c = baseTint;
                c.a = fade;
                accentImage.color = c;
            }
        }

        private void ResetVisual()
        {
            if (accentImage == null) return;
            accentImage.rectTransform.localScale = _baseScale;
            var c = baseTint;
            c.a = motion == AccentMotion.Breathe ? baseAlpha : 0f;
            accentImage.color = c;
        }

        private void EnsureImage()
        {
            if (target == null) return;

            if (accentImage == null)
            {
                var existing = transform.Find("Accent");
                if (existing != null)
                {
                    accentImage = existing.GetComponent<Image>() ?? existing.gameObject.AddComponent<Image>();
                }
                else
                {
                    var go = new GameObject("Accent", typeof(RectTransform), typeof(CanvasRenderer), typeof(Image));
                    var rect = (RectTransform)go.transform;
                    rect.SetParent(transform, false);
                    rect.SetSiblingIndex(0);
                    rect.anchorMin = new Vector2(0.5f, 0.5f);
                    rect.anchorMax = new Vector2(0.5f, 0.5f);
                    accentImage = go.GetComponent<Image>();
                }
            }

            accentImage.rectTransform.sizeDelta = new Vector2(size, size);
            accentImage.raycastTarget = false;
            accentImage.preserveAspect = true;
            accentImage.type = Image.Type.Simple;
            accentImage.sprite = shape == AccentShape.FilledCircle
                ? MarkerCircleSpriteFactory.GetFilled(filledRadiusScale)
                : MarkerCircleSpriteFactory.GetRing(contourOuterScale, contourInnerScale);
            accentImage.enabled = false;
        }
    }
}
```

Defaults above (size, alpha, scale ranges) are first-pass numbers, same
status as any other new visual in this project — tune them during the
Phase A visual pass (§19.10) if they read wrong, don't treat them as final
just because they're written down.

```csharp
bool simpleSunActive = HasEffect(effectFlags, MarkerEffectFlags.SimpleSun);

    accentEffect?.Configure(symbol.RectTransform, MarkerAccentEffect.AccentShape.Contour, MarkerAccentEffect.AccentMotion.Breathe);
else if (simpleSunActive)
    accentEffect?.Configure(symbol.RectTransform, MarkerAccentEffect.AccentShape.FilledCircle, MarkerAccentEffect.AccentMotion.Breathe);
else if (beaconActive)
    accentEffect?.Configure(symbol.RectTransform, MarkerAccentEffect.AccentShape.Contour, MarkerAccentEffect.AccentMotion.Beacon);
```

### 19.8 `MarkerVisualsParser.cs` — `ParseEffectFlags`

Same pattern as the existing `ParseStyle`/`ParseShape` — comma-separated
tokens, unknown token warns and is skipped rather than silently dropped:

```csharp
public const MarkerEffectFlags DefaultEffects = MarkerEffectFlags.None;

// effect_mode is a comma-separated list, e.g. "pulse,sun_contours" or just
// "beacon". Empty/missing -> None (no effects) -- a safe, unsurprising
// default (same reasoning as is_hero in WallConfigData.cs).
public static MarkerEffectFlags ParseEffectFlags(string raw)
{
    if (string.IsNullOrWhiteSpace(raw))
        return DefaultEffects;

    var result = MarkerEffectFlags.None;
    foreach (var token in raw.Split(','))
    {
        switch (token.Trim())
        {
            case "pulse": result |= MarkerEffectFlags.Pulse; break;
            case "sun_contours": result |= MarkerEffectFlags.SunContours; break;
            case "sun_circles": result |= MarkerEffectFlags.SunCircles; break;
            case "ring_pulse": result |= MarkerEffectFlags.RingPulse; break;
            case "simple_sun": result |= MarkerEffectFlags.SimpleSun; break;
            case "beacon": result |= MarkerEffectFlags.Beacon; break;
            case "": break; // tolerate trailing commas
            default:
                Debug.LogWarning($"[MarkerVisualsParser] Unknown effect_mode token '{token}', ignoring.");
                break;
        }
    }
    return result;
}
```

```csharp
            // fact that Pulse/Sun*/RingPulse/SimpleSun/Beacon can combine
            // (per §19.2's mutual-exclusion note for the last three).
            EditorGUILayout.LabelField("Effects");
            using (new EditorGUI.IndentLevelScope())
            {
                var current = MarkerVisualsParser.ParseEffectFlags(poi.effect_mode);
                var tokens = new List<string>();
                if (EditorGUILayout.Toggle("Pulse", current.HasFlag(MarkerEffectFlags.Pulse))) tokens.Add("pulse");
                if (EditorGUILayout.Toggle("Sun Contours", current.HasFlag(MarkerEffectFlags.SunContours))) tokens.Add("sun_contours");
                if (EditorGUILayout.Toggle("Sun Circles", current.HasFlag(MarkerEffectFlags.SunCircles))) tokens.Add("sun_circles");
                if (EditorGUILayout.Toggle("Ring Pulse", current.HasFlag(MarkerEffectFlags.RingPulse))) tokens.Add("ring_pulse");
                if (EditorGUILayout.Toggle("Simple Sun", current.HasFlag(MarkerEffectFlags.SimpleSun))) tokens.Add("simple_sun");
                if (EditorGUILayout.Toggle("Beacon", current.HasFlag(MarkerEffectFlags.Beacon))) tokens.Add("beacon");
                poi.effect_mode = string.Join(",", tokens);
            }

            poi.rotate_contour = EditorGUILayout.Toggle("Rotate contour", poi.rotate_contour);

            EditorGUILayout.Space();
        }
    }

    EditorGUILayout.EndScrollView();

    if (EditorGUI.EndChangeCheck())
    {
        RefreshRigVisuals();
    }
}

// Re-applies MarkerView.Initialise to every existing rig child, matched by
// id, without destroying/recreating anything -- this is what makes style/
// effect edits appear instantly in the Scene view (static composition only,
// see 19.13's Update()-in-Edit-Mode caveat).
private void RefreshRigVisuals()
{
    if (_config == null || _config.pois == null) return;

    Transform rig = GetOrCreateRig();
    if (rig == null) return;

    var style = MarkerVisualsParser.ParseStyle(_config.marker_style);
    var shape = MarkerVisualsParser.ParseShape(_config.marker_shape);
    CategoryPalette.Configure(_config.category_styles);

    foreach (var poi in _config.pois)
    {
        var child = rig.Find(poi.id);
        if (child == null) continue;

        var anchor = child.GetComponentInChildren<POIAnchor>() ?? child.gameObject.AddComponent<POIAnchor>();
        anchor.Initialise(poi);

        var markerView = child.GetComponentInChildren<MarkerView>();
        var effects = MarkerVisualsParser.ParseEffectFlags(poi.effect_mode);
        markerView?.Initialise(anchor, style, shape, effects);
    }
}
```

Same principle applies to the wall-level `marker_style`/`marker_shape`
dropdowns already in `DrawConfigSection` -- wrap that section's two `Popup`
calls in the same `BeginChangeCheck`/`EndChangeCheck`/`RefreshRigVisuals()`
pattern so changing the wall style updates every already-placed marker
instantly too, not just newly-populated ones.

### 19.14 What belongs at which level -- confirmed

Directly answering the layering question:

- **Symbol/icon**: per-POI, via `category` (existing `CategoryPalette`/
  `category_styles` mechanism) -- no new field needed, already per-marker.
- **Ring/badge/outline *style*** (`outline_gold` / `outline_same_hue` /
  `badge`) **and marker *shape*** (`circle`/`hexagon`/etc.): wall-level,
  exactly as already implemented (`WallConfigData.marker_style`/
  `marker_shape`, one dropdown pair for the whole wall in the Editor tool).
  Confirmed correct -- no change.
- **Contour rotation**: per-POI (`rotate_contour`), since it's cheap and
  there's no strong reason a whole wall needs to commit to it uniformly.
- **Effects** (`Pulse`/`SunContours`/`SunCircles`/`RingPulse`/`SimpleSun`/
  `Beacon`): per-POI (`effect_mode`), fully decoupled from `is_hero` as of
  this section -- exactly the "beacon on smaller markers, sun+label on hero
  markers" pattern described in the request is now directly expressible in
  `config.json`, one POI at a time.
- **`is_hero`**: unchanged in meaning, narrowed in *effect* -- now controls
  only the persistent label, nothing else.

If a genuine need for a *second*, independent per-POI icon/symbol axis (on
top of `category`) surfaces later, that's a small additive field
(`icon_override`, falling back to the category-derived icon) -- flagged here
as a clarifying option rather than built now, since the current request's
wording on this point was ambiguous and `category` already covers the
common case cleanly.

## 20. Extensible background shape and ring line styles (2026-08-02)

Three small, related runtime changes that the Editor-tab upgrade in
`_5.1_Editor_Tab.md` depends on. Read that file's new implementation section
alongside this one — this section owns the runtime/rendering half, that file
owns the editor UI half, and the mapping between them is explicit in both
places so neither can drift out of sync with the other.

### 20.1 `MarkerShape.None` -- a marker or badge with no background shape

Add `None` to the existing enum:

```csharp
public enum MarkerShape
{
    Circle,
    RoundedSquare,
    Hexagon,
    Diamond,
    Star,
    None,
}
```

`ShapeKey` in `MarkerView.cs` needs the matching case:

```csharp
private static string ShapeKey(MarkerShape shape) => shape switch
{
    MarkerShape.Circle => "circle",
    MarkerShape.RoundedSquare => "rounded_square",
    MarkerShape.Hexagon => "hexagon",
    MarkerShape.Diamond => "diamond",
    MarkerShape.Star => "star",
    MarkerShape.None => "none",
    _ => "circle",
};
```

`"none"` is never looked up in `shapeLibrary` -- it's a sentinel, not a real
key. `MarkerCircleGlyphView` needs a way to hide *just* the background while
keeping the icon visible (today, `SetVisible` hides the whole glyph,
icon included -- not what "no background shape" means):

```csharp
public void SetBackgroundVisible(bool visible)
{
    if (background != null)
        background.enabled = visible;
}
```

`MarkerView.ApplyVisuals` -- replace the symbol block:

```csharp
if (_shape == MarkerShape.None)
{
    symbol?.SetBackgroundVisible(false);
    if (_applyCategoryVisuals && hasConfiguredCategory)
        symbol?.SetIcon(iconSprite, IconTint, iconOpacity);
}
else if ((_applyCategoryVisuals && hasConfiguredCategory) || _applyShapeVisuals)
{
    symbol?.SetBackgroundVisible(true);
    if (_applyShapeVisuals && hasConfiguredCategory && shapeSprite != null)
        symbol?.SetBackground(shapeSprite, fill);

    if (_applyCategoryVisuals && hasConfiguredCategory)
        symbol?.SetIcon(iconSprite, IconTint, iconOpacity);
}
```

### 20.2 Per-wall `badge_shape` -- badges no longer forced to circle

`MarkerView.cs` currently hardcodes `shapeLibrary?.Get("circle")` for every
badge (§18's original design deliberately kept badges circular; that's now a
default, not a rule). Add a field and a parameter, following the exact same
pattern `_shape` already uses for the main symbol:

`WallConfigData.cs`, next to `marker_shape`:

```csharp
// "circle" / "rounded_square" / "hexagon" / "diamond" / "star" / "none".
// Independent of marker_shape -- a wall can have a hexagon symbol with a
// circle badge, or a badge with no background shape at all. Missing/absent
// falls back to "circle", same as marker_shape's own default.
public string badge_shape;
```

`MarkerView.cs`: add a `_badgeShape` field alongside `_shape`, thread it
through every `Initialise` overload the same way `shape` already is (new
optional parameter defaulting to `MarkerShape.Circle` on the shortest
overloads, so existing call sites that don't care about badge shape keep
compiling unchanged), then in `ApplyVisuals`, replace:

```csharp
Sprite circleShape = shapeLibrary?.Get("circle");
```

with:

```csharp
Sprite badgeShapeSprite = _badgeShape == MarkerShape.None ? null : shapeLibrary?.Get(ShapeKey(_badgeShape));
```

and everywhere that currently does `badge?.SetBackground(circleShape, ...)`,
also call `badge?.SetBackgroundVisible(_badgeShape != MarkerShape.None)`
right before it, mirroring 20.1's symbol handling exactly.

### 20.3 Extensible ring line styles

Today `MarkerRingView`'s dash-pattern sprites come from a fixed 5-slot
`RingSpriteSet` struct (solid/dash_long/dash_medium/dash_short/dotted),
baked into the prefab. A developer can't add a 6th custom line (e.g. a
"wavy" style) without a code change. Generalize it to the same key-lookup
pattern `iconLibrary`/`shapeLibrary` already use -- this is the third reuse
of `SpriteKeyLibrary` in this codebase, not a new mechanism:

- `MarkerRingView` gains `[SerializeField] private SpriteKeyLibrary
  lineStyleLibrary;`, resolved the same way `MarkerView.iconLibrary` is
  (prefab default, overridable per-wall).
- The existing 5 keys (`solid`, `dash_long`, `dash_medium`, `dash_short`,
  `dotted`) get registered in that library under those exact string keys,
  pointing at the same 5 PNGs already imported and wired into the old
  `RingSpriteSet` -- this is a data migration, not new art.
- `MarkerRingView.Apply(StatusLevel level, ...)` resolves
  `lineStyleLibrary.Get(level.RingSpriteKey)` instead of switching on a
  fixed struct field.
- **Reuse the same wall icon library asset for line-style sprites too**,
  under distinctly-prefixed keys if a wall wants custom ones (e.g.
  `line_wavy`) -- one `SpriteKeyLibrary` asset per wall serving three
  purposes (icons, shapes, line styles) is simpler to manage than three
  separate wall-local assets, and nothing about the class assumes a single
  purpose per instance already (see its own header comment: "used as TWO
  separate .asset instances... same data shape, one class").
- `WallConfigData.OutlineLevelEntry.line_style` stays a plain string --
  it already is one, no change needed there. It's simply no longer
  constrained to 5 hardcoded values; any key present in the wall's icon
  library resolves.

**This touches load-bearing rendering code for every existing marker
style, not just new features.** Re-run the full §18 Phase A gate (gallery,
all rows, MCP-green) after this change, before touching Phase B -- don't
assume "it's just a lookup swap" is low-risk enough to skip verification.

## 21. Hero marker symbol override (2026-08-02)

The ask: a hero POI (e.g. the city's main castle or church) should be able to
show a distinctive, hand-picked icon instead of its category's generic icon
-- "a little castle" instead of the generic `civic`/`religious` glyph -- while
everything else about it (category fill colour, ring/status, badge) stays
exactly as it would for any other POI of that category.

### 21.1 Why this design, not an alternative rendering path

The obvious alternative -- a wholly separate "hero marker" visual system,
distinct from the category-driven one -- was considered and rejected: it
would duplicate the colour/ring/badge logic `ApplyVisuals` already handles
correctly for every other marker, for a feature that is really just "swap
one sprite." A hero castle marker should still visually read as "this wall's
civic-category, 40%-destroyed marker" at a glance, with the icon as the only
distinguishing detail -- consistent with how a viewer scans the rest of the
markers on the wall. Substituting only the icon, inside the same rendering
path every marker already goes through, is the minimal change that achieves
exactly what was asked for.

### 21.2 `POIData.hero_icon_key`

`WallConfigData.cs`, next to `is_hero`:

```csharp
// Optional icon key from IconLibrary.asset, overriding just the icon this
// hero POI's Symbol shows -- category fill colour, ring, and badge are
// unaffected. Only meaningful when is_hero is true; ignored otherwise, same
// pattern as effect_mode being independent of is_hero (section 19). A hero
// POI without this set falls through to its normal category-derived icon,
// same as any other marker.
public string hero_icon_key;
```

### 21.3 `MarkerView.ApplyVisuals` -- icon resolution

Replace the existing icon-sprite line:

```csharp
Sprite iconSprite = iconKey != null ? activeIconLibrary?.Get(iconKey) : null;
```

with:

```csharp
string resolvedIconKey = (_anchor.Data.is_hero && !string.IsNullOrWhiteSpace(_anchor.Data.hero_icon_key))
    ? _anchor.Data.hero_icon_key
    : iconKey;
Sprite iconSprite = resolvedIconKey != null ? activeIconLibrary?.Get(resolvedIconKey) : null;
```

If `hero_icon_key` is set but doesn't resolve in the active icon library
(typo, or the sprite was never added to the wall's library), `Get` returns
`null` and the icon simply doesn't render for that POI -- same "authored-only,
no silent fallback" strictness §9 in `_5.1_Editor_Tab.md` already establishes
for other optional visuals, not a special case invented for this feature.

Nothing else changes. Fill colour, ring, badge, effects, label all keep
reading from `poi.category`/`poi.status_pct`/`poi.is_hero`/`poi.effect_mode`
exactly as before -- this is a one-sprite override, not a new code path.

### 21.4 Editor exposure

Owned by `_5.1_Editor_Tab.md`'s new implementation section, not here --
a per-POI "Hero symbol (optional)" sprite field in the existing "Marker
Style" foldout, shown only when `is_hero` is checked, using the exact same
assign-to-wall-library-and-get-key flow the category table already uses.
