# POI Detail Card -- Styles and Sunlight Contrast (3.3)

How the card LOOKS and how a developer changes it: one design-token set, three style presets (Stone &
Gold Luxury, Candlelit Antiquarian, Glassmorphic Aurora), each in dark and light, each with a
high-contrast "sunlight" expansion for outdoor walls; per-block style overrides; and the Editor rows
that edit all of it with a live contrast check. Applies to everything `_3.1` (blocks) and `_3.2`
(navigation) draw.

Design source: the Design canvas artboards "3 styles x standard / sunlight" and "POI Editor - Card
tab". Style origin: the developer's prototype files (`app_main_style_luxury_*`,
`app_backup_style_candlelit_*`, `app_backup_style_2_aurora_*`), improved for contrast.

### R1. Decided by the developer (2026-10-22)

- **ONE main theme, built to the end first.** Premium heritage look ("art, heritage, modern, AR, minimal, well organised, not
  overwhelming, clear navigation and affordances"). More themes only after it is finished (`__mixed_TODOs.md` "Themes after the
  main one", incl. a children's theme and a runtime visitor profile).
- **Two modes, light and dark, BOTH high contrast. No separate "sunlight" / high-contrast variants** (drops the old 3 presets x
  2 modes x sunlight matrix, the sun button and the `sunlight` wall policy). **Light is the default**, with a visitor toggle.
- **Contrast is proven twice at every step: by arithmetic tests AND by looking at the render** (design quality, not only
  "nothing broken"). Neither replaces the other.
- **Developer review gates:** every phase / block ends by showing what was done and asking the developer SPECIFIC questions
  ("this is the block preview design and flow -- does it read right?"), not a generic "OK?".
- Block previews over accordions on the main page: a block opens its whole self in a page of its own (full view) and Back
  returns; the developer may still choose other layouts (`_3.2`'s five).

### R2. Research findings so far (verify each again in P0 / P2 before it becomes a rule)

**UI Toolkit, by Unity version** (project: **6000.3.19f1 LTS, URP 17.3**):

| Feature | Version | Notes for this domain |
|---|---|---|
| USS `filter:` (blur, grayscale, tint, opacity, sepia, invert, hue-rotate, contrast, custom) on an element's OWN subtree | **6.3** (have it) | Blurs the element itself, NOT what is behind it. Useful for a blurred picture, a disabled look, a transition |
| UI Shader Graph (URP UI material, UI nodes) | **6.3** (have it, URP) | The animated gradient border, gradients, a glow, a shimmer: possible today as a material. Cost: per-element material breaks batching -- use for ONE focal element |
| Vector images (SVG import, Painter2D AA) | **6.3** | Icons as SVG instead of USS-drawn lines |
| `aspect-ratio` | **6.3** | Picture frames by proportion, not fixed heights |
| Per-glyph text animation (`PostProcessTextVertices`) | **6.3** | Title reveals; use sparingly |
| `backdrop-filter` (real "liquid glass" over the camera) + `drop-shadow()` | **6.6** (non-LTS) | URP only, screen-space panels only, no USS transitions on it; a 6.6 forum report of grey instead of blur with a translucent background (IN-153404) |
| `linear-gradient()` / `radial-gradient()` backgrounds, `gap`, `z-index`, keyframed animation (released), ATG text default at runtime | **6.7 LTS** (announced for Q4 2026) | Most of the "wow" polish lands here. **Still in beta on 2026-10-22** |

Consequence: **design effects as progressive enhancement.** Tokens name the effect (`--ts-sheet-glass`, `--ts-elevation-1`); on
6.3 they resolve to a fallback (tinted translucent fill, a border + a 9-slice or Shader Graph shadow); after an upgrade to 6.7 LTS
the same tokens switch to `backdrop-filter` / `drop-shadow()` / gradients. Steps that depend on engine effects go LAST in the
build order so an upgrade can land before them. The upgrade itself is a decision for when 6.7 LTS ships (recommended: 6.7 LTS,
not 6.6, which is a short-support release).

**Fonts:** UI Toolkit uses TextCore `FontAsset`; markers use `TMP_FontAsset` (`FontKeyLibrary`). Not confirmed that one asset
serves both in 6.3 (TMP 4.0 docs mark `TMP_FontAsset` obsolete in favour of `FontAsset`; forum threads disagree). Safe plan: one
`.ttf` per type ROLE, two generated assets per key (TMP + TextCore), one library and one key per role. The P0 spike tests
whether a single asset works in both.

**OS accessibility:** `UnityEngine.Accessibility.AccessibilitySettings` (Android / iOS) gives `fontScale` and
`isBoldTextEnabled` with change events -- no reduce-motion flag. The OS "reduce motion" needs a small native read (iOS
`UIAccessibility.isReduceMotionEnabled`, Android `Settings.Global.ANIMATOR_DURATION_SCALE`) -- P0 confirms.

**USS variables:** `var()` cannot nest in functions (`rgb(var(--x))`) and USS has no math. Whether `--a: var(--b)` resolves is
NOT documented -- P0 tests it; the token tiers (R4) depend on it.

**Today's code:** card USS has zero literals (all `var(--ts-*)`), but `CardTokens.uss` is one flat list of ~150 tokens mixing
global, card and block values on `.ts-card`; the card sets NO font (theme default); `SearchUI.uss` has its own palette
(`--surface`, `--accent` ...), `ZoomControlView.uss` its own `--ts-zoom-*`; markers write colours in C#
(`MarkerHaloEffect` / `MarkerRippleEffect` gold tint, `MarkerClusterView` disc colours).

### R3. Critique of the Stitch light "immersive" prototype (direction kept, spec not)

Keep: white block surface on a tinted ground (common region), icon + title + format line per block, one rhythm between blocks,
the peek carousel, the drag-to-rotate and before/after handles as affordances, a serif for titles. Its motion (`code.html`) is
modest and buildable: reveal on scroll (opacity + translate, 0.45 s, cubic-bezier(0.16, 1, 0.3, 1)), press (0.2 s), one

### R4. Working proposals to settle in the phases (recommendation first)

- **Token tiers.** T1 primitives (palette ramps, spacing scale on 4/8 px, radius scale, type scale, durations, easings) and T2
  semantic roles (`surface`, `ink`, `accent`, `focus`, `elevation-n`, `motion-enter` ...) are APP-wide: one root class for every
  UI Toolkit panel (card, search, zoom, onboarding), and read by UGUI (markers, clusters, effects) from the same source. T3
  component tokens live in the component's OWN USS (`Media.uss` defines `--ts-hotspot-pin`), defaulting to T1/T2 values, so a
  global change reaches every component and one component can still diverge on purpose. Content colours (swatches, a wall's
  status rings) stay content. C# holds behaviour constants only.
- **Single source of truth for UGUI + UITK** (P4 decides): (a) a Theme asset (ScriptableObject) as the source, the Editor
  generating the theme USS from it, a test failing when the USS is stale; or (b) USS as the source, C# reading resolved values
  from a hidden themed root (the `CardTokenColours` pattern). Recommendation: (a), because markers render outside any panel.
- **Wall developer knobs (few, semantic):** display font, body font, accent colour, roundness (sharp / soft / round), default
  mode (light), motion level (full / reduced / off). NO free per-block token overrides (the old "Aa"): instead a closed list of
  per-block VARIANTS designed in the theme (emphasis: normal / featured / quiet; picture frame: rectangle / arch ...), which
  gives variety without breaking contrast.
- **Block `preview` display** (new, between `_3.2`'s one-line compact row and `inline`): capped at a FRACTION of the sheet's full
  height (~50-60 %, never a px value), cut with a fade, ending in an explicit affordance ("Read the whole story · 6 min ›") that
  opens the existing full view. Small kinds stay inline. Light interactions in place (swipe pictures, rotate the model, play
  audio, answer the quiz); deep ones in the full view. A gesture rule: horizontal drag belongs to the block, vertical to the card.
- **Previews that move:** default a slow Ken Burns on the first picture when the block enters view; auto-advance OFF by default
  (an Editor option, pauses on touch; WCAG 2.2.2); muted video preview only when >= 50 % visible, one at a time, an Editor
  option (AR already costs GPU and battery); audio never starts itself.
- **Domain separators:** a section header per family (icon + name), sticky in the scroll layout, more space before a section
  than between blocks.
- **Sheet over the camera:** blocks ALWAYS opaque; any text outside a block sits on its own plate. The sheet ground has a glass
  level: `solid` / `tinted` (translucent fill showing the raw camera, 6.3) / `frosted` (`backdrop-filter`, after the upgrade, or
  a blurred camera snapshot as fallback). The developer's idea (translucent sheet, raw camera visible, opaque blocks) is the
  `tinted` level; its risk is that a bright sunny wall behind a white block weakens the block's edge, so blocks carry a border
  + shadow whose contrast is measured against PHOTOS of sunny walls, not a grey test ground.
- **Contrast policy:** all text >= 7:1 in both modes (secondary and captions included); meaningful icons, input borders, focus
  >= 4.5:1; no ink made with alpha (today `--ts-ink-2/3` are alpha); no text on a picture without a solid plate; APCA Lc >= 75
  for body as a second check. Measured on the rendered pixel where something is translucent (LINEAR colour, see section 2).
- **Fonts (P4 decides by a bake-off render, recommendation):** display **Fraunces SemiBold** (heritage character, sturdier
  hairlines than Playfair), alternative Source Serif 4; body **Atkinson Hyperlegible Next** (designed for legibility, OFL),
  alternative Inter; no monospace. All OFL with Latin Extended (ã ç õ). Bake-off: three pairs on the real card, light mode, plus
  a simulated-glare render (contrast lowered, slight blur), the developer picks.

### R6. Motion catalogue (Architect proposal, 2026-10-22; the developer reviews it on recorded frames in P6)

The developer asked the Architect to propose the immersive / motion / micro-motion / parallax ideas and judge the result
later. Rules first: motion EXPLAINS (where a thing comes from, where it goes, what can be dragged), never moves text being read;
one moving thing at a time in view; only `translate` / `scale` / `rotate` / `opacity` (no layout properties) because the AR
camera runs at the same time; durations from the scale (fast ~120 ms, base ~220 ms, slow ~360 ms, emphasis ~500 ms); enter =
decelerate, exit = accelerate, a finger-driven thing = follows the finger then settles (spring). Three levels (wall knob +
visitor setting + the OS flag): `full` / `reduced` (no movement, cross-fades and state changes only) / `off`.

| # | Moment | Motion | Reduced |
|---|---|---|---|
| M1 | Card opens from a marker | the tapped marker pulses (existing effect), the sheet rises; the header, then the first two blocks, fade + rise 12 px, ~40 ms apart | sheet appears, no stagger |
| M2 | A block enters on scroll (first time per open) | fade + rise 16 px, slow; skipped when a navigation jump scrolls past it | none |
| M3 | Picture in a preview / the hero | parallax: the picture moves at ~0.85x the scroll inside its clipped frame (a window with depth); the hero scales 1.06 -> 1 and fades while the header collapses | static |
| M4 | Gallery preview in view | slow Ken Burns on the first picture (~12 s, scale 1 -> 1.06 + small pan), pauses off-screen | static |
| M5 | Preview -> full view and Back | container transform: the block's card grows from its own rect into the page, content cross-fades; Back shrinks it into the same slot (spatial continuity) | cross-fade |
| M6 | Press on anything tappable | scale 0.97 + surface tint (fast), springs back on release | tint only |
| M7 | Navigation follows the reader | the tab underline / marked chip SLIDES to the new section instead of jumping; the sticky section header swaps icon + words with an 8 px slide | instant swap |
| M8 | Affordance hints, once per session | the carousel nudges 24 px and back; the 3D model turns ~20 deg and back; the before / after handle sweeps a little | a static hint ("Swipe", "Drag") |
| M9 | Audio playing | bars / waveform move ONLY while playing; the mini-player slides in | static bars, state by icon |
| M10 | Quiz answer | right: the check draws + a small pop; wrong: a 6 px shake | colour + icon + words |
| M11 | The ONE "wow" focal point | an animated gradient contour (UI Shader Graph material) on the "See it here in AR" call to action, only while the visitor faces the wall | static gradient edge |
| M12 | Loading media | a soft shimmer on the picture's placeholder | static placeholder |

Not proposed: motion on body text, bouncing icons, autoplaying carousels by default, more than one glowing element per screen.

### R7. Liquid glass on 6.3, and the engine upgrade (2026-10-22)

- **Glass, closest to the real thing on 6.3** (P0 S5 decides by measurement): (1) **frosted by a low-resolution camera copy** --
  the AR camera image copied each frame (or every second frame) to a small RenderTexture (~1/8 size) and drawn under the sheet by
  a UI Shader Graph material in screen space: the low resolution IS the blur, plus the theme's tint on top; live, cheap, URP;
  (2) **tinted**: a translucent fill with the raw camera behind, no blur; (3) a blurred SNAPSHOT taken when the card opens (static,
  cheapest). Order of preference 1 > 2 > 3; in every case blocks stay opaque.
- **The camera is LIVE behind the sheet in every option** (the AR camera draws under the UI every frame): a translucent sheet
  already shows the wall moving as the visitor points the phone; only the BLUR needs the copy, and option (1) copies every frame
  (or every second frame), so it is live too. A copy every ~0.5 s was considered and rejected: the blurred image would step
  behind the live movement and read as lag. (3) is the only still image.
- **Developer idea (2026-10-22), to evaluate in P0 S5 as option (4):** tinted at ~50 % with a UI Shader Graph mask of irregular
  areas of more / less transparency (soft noise or a vertical gradient: clearer near the top where the sheet meets the camera
  view, more solid behind the reading area). Rules if chosen: static or very slow (one moving thing in view, R6), section headers
  and nav text on their own plates, block edges measured against the moving stand-in. NOT run in P0 (the addendum arrived after
  it closed): P7 evaluates it on the spike's existing `SpikeGlassRig`, with a MOVING stand-in, next to (1)-(3). P0's S5 already
  showed the real problem for every level: a white block's edge over a sunny wall stays at 1.2-1.6:1 (1 px border down to 1.00:1),
  so P4 / P7 must find the block edge elsewhere (a darker or tinted ground, a stronger border, or a block that is not white).
- **Upgrade: not now.** 6.7 LTS is still in beta (announced for Q4 2026) and 6.6 is a short-support release. When 6.7 LTS ships
  (ideally after its first patch), a separate trial block: a copy of the project (worktree), the AR Foundation / ARCore / ARKit /
  URP packages moved to their 6.7 versions, Immersal's SDK checked against 6.7, full EditMode + PlayMode runs (expect text-size
  shifts: 6.7 makes the Advanced Text Generator the runtime default, and many card tests measure text), then an AR + Immersal
  localisation check on a phone. Merged only if all of that is green.
- **Risk to fix before any upgrade:** `com.immersal.core` is pulled from the git repo's default branch with no tag or commit in

## 1. Rules (from `30-ui-content.md`, made concrete)

- No colour, size, radius, font or duration literal in C# or UXML. Views add CLASSES; USS files hold
  values as `--ts-*` variables. Enforced by a test that scans `Runtime/UI/Cards/**/*.cs` for colour /
  px literals (allow-list for layout-free constants like 0 and 1).
- Text contrast: standard presets >= 4.5:1 for body text and >= 3:1 for large text and UI borders
  (WCAG 2.1 AA, SC 1.4.3 and 1.4.11); sunlight presets >= 7:1 for ALL text including secondary
  (SC 1.4.6, AAA). Checked by tests, not by eye.
- Sunlight changes more than colour: solid surfaces (no glass / blur), no text over images (the hero
  ends in a hard edge, text starts below), body 17 px weight >= 500, no italic body, 2 px borders,
  accent used as a fill with black/white text, status keeps its dash pattern (never colour alone),
  48 px touch targets, thicker focus ring.

## 3. Spike first: runtime overrides in UI Toolkit (step 0)

USS custom properties (`var(--x)`) are defined in style sheets; UI Toolkit's C# `IStyle` has no setter
for a custom property (the read side is `ICustomStyle`). So a value typed in the Editor and saved in
`config.json` cannot simply be written as a variable at runtime. Options, to confirm against the
Unity 6.3 API BEFORE step 7:

| Option | How | Cost |
|---|---|---|
| A. Presets only | overrides = choosing another preset class | no free colour picking |
| **B. Presets in USS + a `TokenApplier` for overrides (proposed)** | presets set the variables; a small applier writes the handful of overridden tokens as INLINE styles on elements carrying token-role classes (`.ts-role-accent-bg`, `.ts-role-ink`...) | one mapping table role -> properties; inline styles beat the cascade, so overrides always win |
| C. Generate a StyleSheet asset in the Editor on save | the Editor writes a per-wall `.uss` from `card_settings.style` | runtime stays pure USS, but a build step and an asset per wall |

Spike: prove B on one token (accent) end to end (config -> applier -> rendered pixel) and check the
current Unity docs for a newer custom-property API; if one exists, prefer it and rewrite this section.

## 6. Sunlight expansion

- Visitor control: a sun button in the card header (always visible, 48 px) toggles `.ts-sunlight`;
  remembered on the device (`CardLocalState`).
- Wall policy (`card_settings.style.sunlight`): `visitor_toggle` (default), `always`, `never`,
  `auto_light_sensor` (Android only: Input System `LightSensor`; iOS has no public ambient-light API,
  so it falls back to the toggle -- verify on device before promising "auto").
- Glass blur: UI Toolkit has no backdrop blur; "glass" in standard presets is a translucent fill.
  Sunlight replaces it with the solid `--ts-surface`.
- Reduce motion and text size are visitor settings built in this step too, next to the sun button in
  the card's "Aa" menu (canvas "New blocks" 02-G).

## 7. Overrides

- **Wall level:** `card_settings.style` = `preset`, `mode` (dark / light / follow system),
  `sunlight` policy, `tokens` (list of `{token, value, sunlight_value}`; empty = preset value).
- **Block level:** `BlockInstanceData.style` = `inherit` (bool) + the same token list, applied to that
  block's root only. Sunlight value auto-derived when empty (lighten/darken until >= 7:1), shown as
  derived in the Editor.
- Order: preset < wall tokens < block tokens < sunlight rules for non-overridable properties
  (solid surfaces, borders, sizes -- a block cannot re-enable glass in sunlight).
