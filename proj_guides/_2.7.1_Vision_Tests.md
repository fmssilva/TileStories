# TileStories — Vision Test Handover Guide (Blocks 1-6)

Audience: a vision-capable agent reviewing screenshots. Read this before any screenshot pass.
Every item is a falsifiable yes/no tied to a specific observed pixel, per 40-testing.md sec 4.5 Tier 1.
Batch into as few screenshot calls as possible (one labeled gallery grid per surface). Do NOT accept
a holistic "looks fine" as an answer -- answer each numbered item with the concrete observation.

## How to run the scenes
- Open the relevant scene in the Editor (mock localization = Tier A, no device).
- Enter Play Mode. The MockLocalizationProvider fires instantly -> markers spawn.
- Capture with the SAME camera pose, crop only what the checklist asks. Name PNGs by checklist number.
- Levels/categories/hierarchy used below refer to the REAL LivingRoom config:
  Assets/Apps/LivingRoom/config.json (and the synced copy in StreamingAssets/LivingRoom/).

## A. LIVE POI families (ground truth for every checklist)
- Lamp family (6, one cluster): lamp, lamp_religious, lamp_military, lamp_residential,
  lamp_economic, lamp_infrastructure -- levels 1..5 (distinct priorities), reveal delays present.
- Painting family (6): painting, painting_religious, painting_military, painting_residential,
  painting_economic, painting_infrastructure.
- Camera family (6): camera, camera_religious, camera_military, camera_residential,
  camera_economic, camera_infrastructure.
- Dev displacement fixtures: dev_disp_eq_royal / dev_disp_eq_mil / dev_disp_eq_eco
  (equal-priority collocated triple), dev_disp_singleton (lone).
- Anchor: cal_left / cal_right.

## Block 1 -- LOD (2.4) -- Distance + density response

Scene: LivingRoomScene, mock localization. Stand at the default camera position, then walk closer/farther via WASD.

### Pass 1 -- Distance banding
1. At the default position, count visible markers. Walk closer (W key): the count should INCREASE as more markers are unlocked. [yes/no -- describe the count change]
2. Walk backward (S key): the count should DECREASE. [yes/no -- describe the count change]
3. No marker "flickers" (appears/disappears rapidly) while standing still at any distance. [flickers / stable]

### Pass 2 -- Density response (lamp family, closest approach)
4. At closest approach to the lamp family, the 6 collocated markers are NOT all full-size overlapping circles -- at least one of: shrink, fade, or aggregate (pie-chart cluster) is visible. [yes/no -- describe what you see]
5. Walk back to the default position: the lamp markers return to full size (density response relaxes). [returns to full / stays shrunk]

### Pass 3 -- Frustum culling
6. Turn the camera (right-mouse drag or arrow keys) so the lamp family is at the LEFT or RIGHT edge of the screen. Markers at the edge should fade/disappear (frustum cull), not render off-screen. [culled / still visible]

## Block 2 -- Selection (2.6 section 11) -- Highlight + zoom-on-select

Scene: LivingRoomScene, mock localization.

### Pass 1 -- Selection highlight
7. Tap a single marker (click in Game View). ALL OTHER markers should become visibly DIMMER (partial alpha), and the tapped marker stays full-alpha. [yes/no -- describe the dimming]
8. Tap the same marker again: all markers return to full alpha (highlight cleared). [yes/no]

### Pass 2 -- Zoom-on-select (dense marker)
9. Position the camera close to the lamp family (6 collocated). Tap one lamp marker: the camera should ZOOM IN (markers grow larger, FOV narrows). [zooms / no zoom]
10. Tap an isolated marker (e.g. cal_left anchor area, far from any cluster): NO zoom should fire (zoom-on-select only fires for dense markers). [no zoom / zooms]

## Block 3 -- Minimap + Filter + Results (2.6 sections 7-9)

Scene: LivingRoomScene, mock localization. Open the Search overlay (FAB -> Search).

### Pass 1 -- Minimap dots
11. Open the Minimap (toggle button). Each visible dot corresponds to a real POI still within the filtered result set. [yes/no -- count dots vs visible markers]
12. Dots are category-colored (not all white) when `minimap_icon_style = "category_colored_dots"`. [colored / all white]

### Pass 2 -- Filter toggles
13. In the Filter tray, toggle OFF one category (e.g. "religious"). The results list should update to show only non-religious POIs. [yes/no -- describe the change]
14. The minimap dots should also update: religious POI dots disappear, non-religious remain. [yes/no]
15. Scene markers for religious POIs should also disappear (or dim, per `filter_mismatch_behaviour`). [yes/no]

### Pass 3 -- Search query
16. Type a query in the search field (e.g. "lamp"). The results list shows only POIs matching the query. [yes/no]
17. Clear the search field: all POIs return to the results list. [yes/no]

## Block 4 -- Filtering composition (2.6-i) -- One result set

Scene: LivingRoomScene, mock localization. Open Search overlay + Filter tray + Minimap.

### Pass 1 -- Composition sync
18. Toggle a filter AND type a search query. The results list, minimap dots, and scene markers should ALL show the SAME filtered set (intersection of query + facet). [yes/no -- describe any mismatch]
19. Clear both filter and query: all three surfaces return to showing all POIs. [yes/no]

### Pass 2 -- filter_mismatch_behaviour
20. With `filter_mismatch_behaviour = "hide"` (default): non-matching markers are fully invisible (alpha 0). [hidden / dimmed]
21. Change `filter_mismatch_behaviour = "dim"` in config, restart Play Mode, repeat filter: non-matching markers are faintly visible (alpha ~0.3). [dimmed / hidden]

## Block 5 -- Zoom (2.4-l / 2.4-m) -- ONE consolidated pass, zoom 1x -> ~3x via the on-screen buttons
Scenes: LivingRoomScene, mock localization. After zoom, capture the SAME framing before/after.
1. Markers appear larger (symbol + label scale up with the view, not just the background).
   [yes/no -- describe the visible size change]
2. AR passthrough/framing tightens -- markers AND background zoom together, no separate "card on
   a static backdrop" effect. [yes/no -- confirm the whole frame reacts]
3. Inversion sanity: zoom-IN must narrow the camera FOV (markers look physically bigger because the
   lens narrowed). If zoom-in made everything appear WIDER, that is a bug -- flag it. [narrowed / widened]
4. Double-tap steps to the next discrete zoom level; the +/- buttons step 1.5x -> 2.25x (discrete),
   NOT a smooth continuous ramp. [discrete steps observed / smooth ramp]
5. No leftover UI artifacts: the 3 zoom buttons (zoom-in-button / zoom-out-button / zoom-reset-button)
   are each >= 44px tap targets and visually distinct from the AR marker buttons. [yes/no]

## Block 6 -- Displacement (2.5-g / 2.5-h) -- TWO gallery passes
Scene: Dev/DisplacementGallery (Phase A harness) OR LivingRoomScene for real-config P.O.I.s.
Likely one screenshot per algorithm (fixed_axis / candidate_position / force_directed).

### Pass 1 -- lower_priority_only tie-break visible behavior (2.5-g)
Take the same overlapping group under "symmetric" and then under "lower_priority_only".
1. Symmetric: ALL group members are visibly nudged apart (no single untouched anchor).
   [each member moved? -- list which ones you see displaced]
2. Lower_priority_only, distinct priorities: the HIGHEST-priority member stays at its original
   screen spot (untouched anchor); ONLY the lower-priority members have moved OUTWARD away from it.
   [yes/no -- point at which one stayed fixed]
3. Lower_priority_only, equal priorities (use dev_disp_eq_royal/mil/eco): NO single anchor is
   invented -- all three spread symmetrically (mirrors the "symmetric" look), no arbitrary
   asymmetrical winner. [symmetrical spread / one member falsely pinned]
4. Separation: after displacement, no two visible label rects overlap by more than the overlap
   threshold. No label sits ON TOP of another. [yes/no -- describe any residual overlap]

### Pass 2 -- max_displacement hide-fallback visible behavior (2.5-h, label_only only)
Configure an artificially tiny max_displacement_px (e.g. 5-10px) so a dense pair cannot separate.
Alternatively use the real lamp cluster if it genuinely exceeds the cap.
5. The LOWER-priority member's LABEL text is hidden (symbol may remain); the label does NOT render
   still-crowding its neighbour at the clamped offset. [label hidden / label still visible on top]
6. The HIGHER-priority member's label stays visible and readable. [yes/no]
7. When max_displacement_px is back at a large value, BOTH labels are visible again (hide is
   not permanent). [both visible after restore / still hidden]
8. Leader lines, if enabled: each leader line's color matches its OWN marker's category color,
   not one uniform color across all. [per-marker match / uniform]

## Block 1-4 -- supporting surfaces (only if a regression is suspected)
- DetailCard close button: the "X" is >= 44x44px and tap-reachable. [yes/no]
- Minimap: dots larger than fat-finger overlap collapse correctly; each visible dot corresponds to a
  real POI still within the filtered result set.
- camera_highlight view: non-matching markers are visibly dimmer than matching ones, NOT identical.

## Handoff rules
- Attach the numbered PNGs + a per-number yes/no + the ONE descriptive sentence each.
- State the scene, the zoom level / algorithm / max_displacement used in the filename.
- If anything is ambiguous, mark "unclear - see <file>" instead of guessing.
