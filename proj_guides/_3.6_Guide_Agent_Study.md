# The Guide's live agent ("Ask Azu") -- study (2026-11-03)

How the guide answers free questions and acts in the app: the architecture, the tools, the knowledge, the inputs and outputs, the
model, Unity, and the Editor panel. This is a study for its own domain: it records the options and a recommendation, and it is
not a build plan yet.
- **Related:**
  - `_3.4_The_Guide_Study.md` (the authored tour, the voice, the dock, the camera);
  - `_3.5_Audiences_Study.md`;
  - the spec `_3.3` section 11.
- **Research:** one subagent (2026-11-03) + the Architect.
- **Status of the facts:** prices are the vendors' pages on that date unless marked (unverified), and change. Nothing here is
  measured yet.

## 1. What the developer asked for
- The guide knows how to navigate the app and does things by itself: it opens a page or a block, finds a feature ("is there a 3D
  model of this point?") and opens it.
- An LLM agent receives the visitor's request: written, spoken, a photo, and the app's metadata (where the camera points).
- In development a fast, cheap model (Claude Haiku or Sonnet). In the Editor the developer chooses the model and which
  capabilities it has.
- **Its knowledge:** a library the developer builds (RAG: BM25 or a vector index, then a re-rank). When the library has no
  answer, general knowledge.
- **The app's structure:** the agent knows the app's pages and blocks, so it knows what exists.
- **Its outputs** (the developer chooses which are on):
  - text;
  - voice;
  - navigating by itself;
  - clickable links in the chat, ranked when there are several ("see a 3D model here", "Manueline points: A, B…").
- **Editor:** it says clearly what the app has: scripted guides only, or also the live agent. It has the fields for the services'
  keys and says what to do with them.
- Everything has to be buildable in Unity.

## 2. Recommended architecture
- **Our own small agent loop, in a serverless backend:** a Cloudflare Worker (an Azure Function is the same design). It streams
  to the phone (SSE).
- **The model behind an adapter:** the Vercel AI SDK provider layer, or a gateway such as OpenRouter or Cloudflare AI Gateway.
  The phone never holds a provider key.
- **The app's state goes up with the question**, instead of tool round trips to the phone: the points in view with their screen
  places, the open card and page, the audience, the lens, the language.
  - So UI actions are outputs: the server validates them and streams them down as events, and the model never waits on the phone.
  - Only the read-only knowledge tools (`search_library`, `find`) loop, on the server.

```
Phone (Unity)                         Worker (agent loop)                    Providers
[Ask Azu] --POST /ask (SSE)---------> session token, rate limit
  question + app context              prompt: [cached] persona + rules + manifest
  (points in view, page, audience,            [cached] the wall's library
   lens, language, manifest hash)             [live]   app context + question
                                      loop: at most 3 steps, 8 s -------------> Claude / Gemini / OpenAI
                                        server tools: search_library, find      (adapter / gateway,
                                        UI tools: ids checked against the        a fallback model)
                                        manifest; on an error, retry once
<--- SSE: text | citation | action | suggest | done | error
[Dispatcher] checks the ids again -> policy (Auto / Suggest / Confirm)
  -> the same UI-action executor the tour's timeline uses (it pauses the narration)
[Offline / timeout]: the on-device FTS5 find -> link cards
```

- **Tours and Ask Azu share one pattern:** the agent's tools are a subset of the timeline's action vocabulary, and the same
  executor runs both. The authored narration stays pre-rendered; the model never narrates the tour.
- **Compared:**
  - ElevenLabs Agents with client tools: low latency and voice-native, but no Unity SDK in its docs, the tools are configured in
    its dashboard, and about $0.08/min plus the LLM (unverified). Later, for a "voice conversation" mode.
  - OpenAI Realtime: about $10 / $20 per 1M audio tokens.
  - Gemini Live: about $0.005 / $0.018 per minute of audio, ephemeral tokens. The cheapest voice-native option, but not Azu's
    narrator voice.
  - MCP on the phone: no; the phone is not reachable inbound. The manifest is written in MCP's tool shape, so the same manifest
    can serve an Editor-side MCP server for tests, and later Android AppFunctions or Apple App Intents.
- **Timeouts:**
  - the first token by 2.5 s, else "thinking";
  - a hard stop at 8 s and 3 steps;
  - on a 429, a 5xx or a timeout, the fallback model;
  - with no network, the on-device search and link cards ("I can't reach the internet; this is what I found in the app").

## 3. The tool manifest: what the agent can do in the app
The Editor generates it from the content database, narrowed to the current wall and session, so the enums stay small.
- Strict schemas: every id is an enum of real ids, checked on the server and again in the app.
- At most 8 tools, set semantics (not toggles), nothing destructive.

| Tool | Arguments | Runs | Policy (default) |
|---|---|---|---|
| `search_library` | query, poi_id? | server, read-only | Auto |
| `find` | query, kinds?[] | server (an on-device copy offline) | Auto; returns target ids |
| `show_links` | items[≤4] {target_id, reason} | app | Auto: the default answer to "where / what can I see"; never navigates by itself |
| `highlight_points` | poi_ids[≤8], duration? | app | Auto (an empty list clears) |
| `open_feature` | poi_id, kind (3d_model, gallery, video, audio_guide, quiz, map: only those the point has) | app | Auto when the visitor asked for it, else Suggest |
| `navigate_to` | target_id (a page or block) | app | the developer's setting: Ask (a confirm chip) / Auto / Suggest only |
| `make_route` | poi_ids[2..8] in order | app | Suggest, then Confirm |
| `start_tour` | poi_id, audience, length | app: plays the authored timeline | always Confirm |

- **Precedents:**
  - Google's A2UI (open source, December 2025): the agent asks only for components from a catalogue the client trusts, as
    `show_links` does with its card vocabulary.
  - The Vercel AI SDK's client tools.
  - ElevenLabs client tools ("wait for response").
  - Android AppFunctions and Apple App Intents: schema-generated manifests.

## 4. Knowledge
- **Start without RAG:** each wall's curated library (the points' texts, source summaries, PDF extracts) goes in a cached prompt
  block.
  - Claude caches prefixes from 512 tokens, reads at about 0.1x the input price (unverified per model).
  - Gemini context caching: $0.075 per 1M tokens plus $0.50 per 1M tokens per hour of storage.
  - A few hundred documents per wall is about 20-100K tokens, which fits.
- **Retrieval only past about 100K tokens a wall, or with long PDFs:**
  - BM25 with SQLite FTS5 (`unicode61 remove_diacritics`; FTS5 has no Portuguese stemmer). The same index serves the on-device
    `find`.
  - Dense embeddings computed in the Editor at content build. For hundreds of chunks, a brute-force cosine search in the Worker is
    enough.
  - RRF fusion, then an optional re-rank (Cohere Rerank 4 Fast, about $0.001-0.0025 a search, unverified; or a self-hosted
    bge-reranker).
  - Embeddings to test on about 50 pt-PT questions (no pt-PT benchmark found; MTEB-PT varies by task): bge-m3,
    multilingual-e5-large-instruct, Gemini Embedding 2 ($0.20/1M), OpenAI text-embedding-3-small ($0.02/1M).
- **Grounding:**
  - every chunk has an id; answers cite `[src:id]`, and the server drops a citation whose id does not exist;
  - an answer carries `source: library | general`, and general knowledge shows a "general knowledge" badge;
  - with no library answer and general knowledge off, "I don't know" plus `show_links`.

## 5. Inputs and outputs (developer settings)
- **Inputs:**
  - text;
  - voice, through STT on the phone (free, no wait) or on a server (about +0.5 s, unverified);
  - a photo for a vision model (about 1-2K tokens, +0.5-1 s; only on "Look closer", with a privacy note);
  - app context (300-800 tokens, always on: it is what removes the round trips).
- **Outputs:**
  - text;
  - text + the narrator's voice (TTS streamed per sentence, about +0.3-0.6 s to the first audio, unverified);
  - UI actions and link cards (free: they are tokens);
  - a voice-native mode, a 5-50x cost step.

## 6. Models and cost
A question is taken as 2 model steps, about 3K uncached and 7.5K cached input tokens a step, and 400 output tokens.

| Model | $/1M in / out (cached) | ≈ per question | Note |
|---|---|---|---|
| Claude Haiku 5.5 | 0.10 / 0.50 (≈0.01) | ≈ $0.001 | as of 2026-10-06; check the pricing page |
| Claude Sonnet 5.5 | 2 / 10 (0.20) | ≈ $0.019 | quality tier |
| Gemini 3.8 Flash | 0.75 / 3.75 (0.075); doubles on 2027-01-01 | ≈ $0.007, then $0.014 | thinking billed as output |
| Gemini 3.1 Flash-Lite | 0.25 / 1.50 | ≈ $0.0025 | |
| gpt-5-mini | 0.25 / 2.00 | ≈ $0.003 | plus reasoning |
| gpt-oss-120b on Groq | 0.15 / 0.60 (unverified) | ≈ $0.003 | fastest; Portuguese untested |

- **The EEA rule:** the Gemini terms allow only Paid Services when API clients are offered to users in the EEA, Switzerland or
  the UK. The free tier is for development, and Google uses its data.
- **Recommended:**
  - development: Haiku 5.5 by default, with Gemini Flash and gpt-5-mini switchable to A/B the European Portuguese;
  - production: Haiku 5.5 with Gemini Flash as the fallback.
  - First, a 50-question pt-PT and EN eval of the answers and the tool calls.

## 7. Unity
1. **Manifest generator (Editor menu):** reads the points, pages and blocks and writes `agent_manifest.json` (MCP-shaped JSON
   Schema, enums, a content hash), the FTS5 index and the chunk embeddings.
2. **Transport:** UnityWebRequest POST with a `DownloadHandlerScript` that buffers SSE lines in `ReceiveData` (events split
   across chunks) and parses them on the main thread; `Awaitable` for cancelling.
3. **Token service:** the Worker issues a short-lived session JWT bound to an install id (App Attest / Play Integrity later),
   with a rate limit per token and per day. The provider keys are only Worker secrets.
4. **Dispatcher:** tool name -> `IAgentAction`. It checks the ids against the live content, applies the policy (Auto / Suggest /
   Confirm), pauses the narration and calls the timeline's executor.
5. **Voice:** STT on the phone first; TTS streamed per sentence in Azu's voice, reusing the bubble's word times.
6. **Safety:**
   - keys in EditorPrefs only for the Editor's direct test mode (`#if UNITY_EDITOR`);
   - a build preprocessor fails the build if an asset holds a key pattern.

## 8. The Editor panel ("Ask Azu")
1. **Guide mode:** Scripted / Scripted + Live agent, one line each.
2. **Model:** provider, model, fallback, effort, maximum output, and a live "≈ cost per question".
3. **Inputs:** Text, Voice (phone / server), Photo, App context (with a preview of the JSON sent).
4. **Tools:** one row per tool (on, Auto / Suggest / Confirm, the count of ids), and Regenerate manifest. Warnings name the points
   and pages, never ids.
5. **Knowledge:**
   - a library per wall / point, with its token count;
   - Prompt cache / RAG, and Rebuild index;
   - General knowledge allowed, with its badge.
6. **Outputs:** Text, Text + narrator voice, UI actions, Link cards.
7. **Services & keys:** the backend URL, the token service's status, Editor-only keys (masked, EditorPrefs, "never shipped").
8. **Limits & costs:** caps per session and per day, the timeout, the loop's steps, a monthly budget alert.
9. **Test console:**
   - a simulated app context (the points in view, the card, the audience, the language), a question and the streamed answer;
   - the actions as chips with valid / invalid marks;
   - latency and tokens / cost per step;
   - Save as eval case.

## 9. What the Lab shows today
- **Ask the guide** (`v6`): Claude through the published Lab's `sample` capability, with a `go_to_block` tool; offline search
  without it.
- **Ask about the view** (`v8p`): the points in view as text; `highlight_points` and `make_route`; answers offline from the same
  view.
- **Ask Azu** (`v8t`, 2026-11-03): the panel of section 8, built. The spec is `_3.3` section 11.
  - **One adapter, one live path.** Claude (published), Gemini or the Claude API (with this computer's key, `keys.local.js`) all
    share the `sample` call shape, so Ask the guide, Ask about the view and the Editor's drafts all run on whichever answers.
  - **One manifest of 8 tools** with policies:
    - `search_library`, `find`, `show_links`, `highlight_points`, `open_feature`, `navigate_to`, `make_route`, `start_tour`;
    - enums of real ids; a wrong id refused and logged.
  - **On the phone:** link cards, Suggest/Confirm buttons, a source line or a General knowledge badge.
  - **On failure:** the offline fallback on a timeout, a 429 or the session's cap.
  - **The test console**, with tokens, time and cost, and eval cases saved as JSON.
  - **Tested** with a test double and with fetch faked for Gemini and the Claude API (`test8t.js`). Mutation proofs: Suggest run
    by itself, the call id dropped, citations not checked, Off still offered; each is caught.
  - **Live** (`test8t_live.js`, by hand: it spends the key's quota). Gemini Flash-Lite with the current key, from a page opened
    from a file (CORS allows origin `null`):
    - **The card:** "O palácio tinha uma ópera?" was answered from the library (Fun fact cited) and Go to moved the card.
    - **The wall:** "Qual é o mais antigo que estou a ver?" answered Torre de Belém, 1514, and Light points lit it.
    - **With the photo:** a description of that part of the panel.
    - **"Where can I see it?":** link cards to Antes e depois and Galeria.
    - **Speed and cost:** the first words in 1.2-2.3 s, about 4K tokens in and 70 out, about $0.0013 a question.
  - **Learned live:**
    - Flash-Lite writes `[poi:belem|Torre de Belém]` as well as `[src:id]`, and does not always cite the app's data. So both
      citation forms are read, and a point in view that the answer names counts as its source.
    - The pt-PT address needs saying: an unprompted "tu", then "você", then "Vossa Excelência". The rule now asks for "the polite
      third person, as a museum guide does: Pode ver, para si".
  - **Tested in the prototype itself** (`v8u`): seven test scenes in the Editor's console. Each is set up as a visitor would
    be (the card or the Belém wall, a pan) and checked: a point named or lit that is not on the screen fails.
    - **Live with Gemini Flash-Lite:** all seven ✓, and a real drag then a typed question named only the points in view.
    - **Caught live:**
      - on a wall that is not the card's own, the model mixed in the card's texts, so each wall has its own library;
      - a point named after a place ("O Tejo") is matched by any mention of the river, so points are named for what is drawn;
      - the model writes markdown, so the rule asks for plain text and emphasis is stripped.
    - A **trace under each answer** (development) shows the model, the times, the tokens, the cost and the calls.
  - **The answer in a real voice** (`v9a`, 2026-11-04): Voice of the answers = Device / Azure (live) / ElevenLabs (live).
    - Azure's Speech SDK (loaded on demand) gives the audio, each word's boundary and the visemes; ElevenLabs'
      `/with-timestamps` gives the audio and each letter's time. Either plays as a recorded line (captions, the word light,
      pause, mute) and moves Azu's mouth with the voice's own timing, whatever the mascot source.
    - Live, one 10-word pt-PT answer: ElevenLabs Flash v2.5 1.9 s to the audio; Azure (Raquel) 2.6 s, 67 visemes.
    - The keys are this computer's; the published Lab speaks with the device voice. In the app, the Worker synthesizes a
      sentence at a time and streams the audio and its timings, so the first words come sooner.
  - **Not in the Lab yet:**
    - RAG (the library fits in the prompt);
    - streaming the answer a sentence at a time (the Lab makes the whole answer's audio, then plays it);
    - the Claude API run with a real key (only faked so far);
    - files as input;
    - a 3D model as a feature (the card has none).
