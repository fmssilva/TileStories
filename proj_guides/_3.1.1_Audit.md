Top 5 findings (details in their sections):
1. **The Editor shows fields the chosen option does not use** (Scale Mode Real Size still draws Height / Marker Multiple; a Knowledge
   Check row draws 12 fields for every look; the header row every picture / clip / model field; the Block Library's Header "Default Fit"
   while its default look is Text Only). One framework fix covers all of them: a field declares when it applies (section 5).
2. **The card repeats one action up to four times and lets Sources sit mid-card** (the sticky "Show me where it is", two Show On
   Wall blocks, the Actions circle; Sources before the 3D / panorama / AR blocks). Fixture-driven, but the framework neither
   orders `meta` last nor warns (section 9).
3. **place_in_ar gives no feedback once placed**: the button still reads "See it here in 3D" beside Remove, the card drops to peek
   with a half-cut line of block text, and nothing says where the model stands (section 9).
4. **Portuguese visitors meet English wall words**: category and status names ("Royal Government", "Intact / Partial Damage")
   and other points' marker names ("Lamp - Infrastructure") have one language only; and one action has two Portuguese wordings
   ("Mostrar onde fica" / "Mostra-me onde fica") (section 9).
5. **Default Media's per-row (i) sits at the window's right edge**, not in the section's (i) column, at 880 and at 620 pt (a
   FlexibleSpace in an unconstrained group, `_5.1` "Do not") (section 5).

## 1. Developer flow

**Edit Mode, a new wall:**
1. Detail Card > Card Container: Enable Detail Card (on by default), Languages (`en, pt`; the FIRST is both the language shown
   and the fallback), Media Folder (Resources-relative; empty = no wall media), Open At, Half Height Max, the audio rows.
2. Detail Card > Block Library: every registered kind is a row with its defaults (enabled, default look); the first edit creates
   the wall's row. Two kinds carry a wall default for a field (3D Model > Default Fit, Place In AR > Default Scale Mode).
3. Card Texts / Glossary / Default Media: the wall's own wording of the card's 80 framework texts, the glossary words, a wall
   media library.
4. Specific Marker > a POI > Card Content: "+ Add block" (kind picker by family) appends a block at the END with every field
   empty, the Block Library's default look and `inline`; ^ / v move it one row at a time; the row opens to the kind's fields.
5. Save All to JSON, Copy to StreamingAssets, Play. In Play Mode every Detail Card edit reaches the open card live.

**What is awkward:**
- A new block is always empty: there is no "duplicate block", no "copy from another POI's block", no kind-level content
  template. Authoring the same Actions or Practical Info on 12 POIs is 12 times the typing. (Defaults per WALL exist only as the
  Block Library's look + two Choice fields.)
- A new block lands at the end; with 62 blocks, moving it to position 5 is ~57 clicks on ^. No "insert after this row", no drag.
- Collapsed rows show only the kind and the look ("Rich Text / plain" x4): a developer opens rows to find the one they want.
- Dialogue lines retype the speaker per row; there is no "same speaker as the previous line".
- The card shows the FIRST language only; to check the PT card the developer reorders Languages (or uses a test). There is no
  "preview language" in the Test foldout and no visitor language switch at all (section 3).
- The demo card (Test foldout) opens one chosen point at one stop: good. There is no way to jump the demo card to a given block.

## 2. Option coverage matrix

**How it was built (from the code, not from memory):**
- Rows: dumped from the LIVE registry (`BlockRegistry.Shared.Ordered`, every `BlockKindDefinition`: looks, display modes; every
  `BlockFieldDefinition` and `ItemFields`: type, label, required, help, options, `ChoiceDefault`, `LibraryDefault`) by
  `execute_code` into `registry.txt`.
- Editor row: the generic `BlockFieldDrawer` draws every field type a registered kind uses; `DetailCardEditorTabTests.
  EveryRegisteredKind_IsFullyEditableHere_WithHelpOnEveryRow` walks the registry (so the column is ok for every row), and the
  captures of section 5 looked at the rows.
- (i): the field's / kind's `Help` is non-empty for all 177 fields and 34 kinds (registry dump: 0 "nohelp"). A Choice option has
  no (i) of its own: its field's (i) names every option.
- Default: a look's default = the kind's `DefaultVariant`, overridable per wall in the Block Library; a Choice field's =
  `ChoiceDefault` (or the first option), overridable per wall where `LibraryDefault` is set; a Number's = `NumberDefault`.
- Undo / redo / round trip: `BlockKindRoundTripTests.EveryKind_WithEveryFieldFilled_SurvivesTheWindowHistory_SaveAndLoad_...`
  is parameterised over `BlockRegistry.Shared.All` and fills EVERY field (ok for every row by construction).
- Live sync: `LivePlayModeCardApplier`'s fingerprint is `card_settings` + every POI's whole `card`, and
  `LivePlayModeCardTests` proves it changes for every leaf (reflection) and drives one real typed edit, one real "+ Add block",
  one variant change and four Ctrl+Z on the open card. Generic: ok for every row. It does NOT prove that each field's effect is
  drawn correctly after a rebind; that is Phase B's job.
- Phase A: the gallery entries (`CardGalleryDefinitions.All`, 266 entries) dumped with every field and row sub-field they fill
  (`fields_filled.txt`); a row is ok if an entry fills it, or a gallery / stage test names its constant (cross-checked by
  scanning `*Gallery*Tests.cs` and `CardGalleryDefinitions*.cs` for the field / option constants of `BuiltInBlocks`,
  `ModelFitRule`, `ArPlacementRule`, `CardOptions`); "ok (default)" = left unset, so the default is what every entry shows.
  `CardGalleryTests.EveryBlockEntry_BuildsFitsReadsAndRenders` runs fit / contrast / tap target / heading checks on every entry.
- Phase B: the same over the shipped LivingRoom `config.json` (every POI's blocks) and the real-scene suites (`PoiCard*Tests.cs`,
  `LivingRoomCardSceneTests`). Every kind has at least one named real-scene test with real input on The Lamp.
- Capture: a `Card_<kind>_<look>*.png` render in `TestEvidence/Card/` (every kind x look has one) or this audit's product pass.
- Manually verified overrides: 3D Model > Fit's four options are proven on the REAL `CardPreviewStage` by `CardPreviewStageTests`
  (an isolated stage test, counted as Phase A).
- Limit: "ok" in Phase A / B means the field is filled (or named) where a test runs; a named test's assertions were read for the

## 4. Config ontology

`card_settings` today: `enabled`, `languages`, `media_resources_path`, `default_media_library_resources_path`, `container` (7
fields), `kinds[]`, `strings[]`, `glossary[]`, `demo_card`. Per POI: `card.blocks[]` of `{key, kind, variant, display, fields[]}`.

- **`container` mixes three responsibilities:** the sheet (`open_stop`, `half_max_ratio`, `dismiss_on_tap_outside`), audio
  (`keep_audio_on_close`, `audio_when_another_starts`, `audio_android_output_poll`) and motion (`reduce_motion`). The Editor
  draws them as one Card Container list, which reads well today (seven rows). Proposal: keep the JSON (renaming saved keys
  breaks configs for no gain, `_5.1`), but group the Editor rows under two small headers, "Sheet" and "Audio", with Reduce Motion
  under Sheet. When `_3.3` adds visitor controls, `reduce_motion` belongs with them (a `visitor` / `accessibility` block), not
  in `container`.
- **Languages are a wall setting but also the visitor's language today** (first = shown = fallback). When a visitor setting
  arrives, the rule becomes "Languages = what the wall offers, first = fallback"; the field and label can stay.
- **Media:** `media_resources_path` and `default_media_library_resources_path` live at the root; Default Media has its own
  section. Clear enough; a "Media" sub-group (Media Folder + Default Media Library) would put the two paths together.
- **Block Library rows hold a kind's wall defaults:** look, enabled, a note, and `field_defaults` (Choice only). This is the right
  place; the ontology question is which fields deserve a wall default. Today only two (Fit, Scale Mode); candidates where walls
  will differ: Video > Captions On By Default, Audio Guide > Speeds / Captions On, Related > Source, Feedback > look-level
  question. Decide per field, not wholesale.
- **Block instance `display`** is a per-block field drawn for every kind, though only three kinds offer more than `inline`
  (section 5).
- **Names:** Editor labels are clear and match the card. Two that read oddly: "Half Height Max" (it is the half stop's cap:
  "Half Stop Height" would say it), "Android Earbud Check" (it is a Bluetooth output check: fine, the (i) explains).
- **Kind keys vs display names** are consistent since 10B-pre.2; look keys are shown raw in the Editor (`grid_hairline`,
  `text_only`) while Choice options have labels: give looks labels the same way (`OptionLabels` for variants).
