# 4.1.9 · Visitor profiles and one editor (version 0, implemented in Lab v18)

TileStories · World Editor Lab v18. Agreed on 2026-11-15:
- Two onboarding questions, plus optional interests.
- The look follows the visitors' choice.
- Only colours are stored per light / dark.
- Explorer / Family / Expert are retired.

## 1. The dimensions and what each one owns

| Dimension | Options | Chosen by | Owns (stored per option) |
|---|---|---|---|
| **Visitors** | Just me / us · With children | Onboarding Q1 | Tone of the text, children's text variant, mascot coach, games first, the **default look** |
| **Time** | Quick · Classic · Deep | Onboarding Q2 | Which levels show at rest, the card text depth, tour length, extra card blocks |
| **Interests** | The 6 categories (multi, optional) | Onboarding, optional | Ranking only: matching POIs are emphasised and come first in pointers. Nothing is hidden |
| **Look** | Premium · Playful (more later) | Auto from Visitors; Settings | Every design token: shape, type faces, icon line, motion, outline, shadow style, marker preset |
| **Appearance** | Follow the phone · Light · Dark | The phone; Settings | Colour tokens only, per look (glass, text, accent, buttons, tags, panels, labels) |
| **Text size** | System · Small · Default · Large | The phone; Settings | Nothing stored. One multiplier on the type scale (0.9 / 1 / 1.2) |
| **Language** | English · Português | The phone; a switch on the onboarding | Content |

**Rule: every editor field belongs to exactly one dimension, or is global.**
- Storage is the **sum** of the dimensions, never their product:
  - looks × design tokens
  - looks × 2 × colours
  - 3 × time rows
  - 2 × visitor rows
- Runtime resolves once, when the profile changes, into one flat table. The cost per frame is zero.

## 2. Code organisation (Lab, mirrored in config.json for Unity)

```
D.profile  = { visitors, time, interests[], look:"auto"|key, appearance, text, language }   // the visitor's choices (runtime; the Lab previews)
D.looks    = { premium: { name, tokens:{…}, colours:{ light:{…}, dark:{…} } },
               playful: { name, base:"premium", tokens:{ only what differs }, colours:{ light:{diff}, dark:{diff} } } }
D.time     = { quick:{ levels, card_depth, tour_max_min, blocks }, classic:{…}, deep:{…} }
D.visitors = { adults:{ tone, look, mascot, games_first, kid_text:false }, children:{ … } }
resolveLook(lookKey, mode, textScale) → { ...tokens, colours }   // the base then the look's diff (deep merge); cached
```

- `dsT()` and `D.themes[mode]` become reads of the resolved table. All existing renderers keep their names.
- Unity: one theme asset per look with light / dark colour sets. They generate USS variables in a root class per look and mode. Time and Visitors are ScriptableObject rows. Look assets (a font, symbols) load on demand (Addressables).

## 3. The editor: one form plus a profile bar

- A sticky **profile bar** at the top of the editor, on every tab:
  - **Look** [Premium | Playful] and **Light | Dark**: these choose where design fields are saved.
  - **Visitors** [Me | Children] and **Time** [Quick | Classic | Deep]: these choose where the Profiles section's rows are saved.
  - **Text** [S | M | L] is preview only.
  - All of them preview on the phone at once.
- Each field shows its **scope**: a small tag (`look`, `look · light`, `time`, `visitors`, or none for global). It also shows whether the value is **set here or inherited** (a dot, with "reset to inherited"). For example, a Playful field that Playful doesn't override shows "from Premium".
- Colour fields check contrast in **both** modes, even while you edit one.
- The duplicated "Light design / Dark design" folds disappear (Design system › Colour, On tap › Tags, Main › wall labels). One fold each, bound to the bar.
- A new App section, **0 · Profiles**, holds:
  - the dimension rows (Visitors, Time);
  - the onboarding questions;
  - the visitor Settings defaults.

## 4. Screens on the phone

- **Onboarding (one screen):** Language switch (top) · "Who's visiting?" (2 big cards) · "How long do you have?" (3 cards with minutes) · optional interest chips (the categories) · Let's go / Skip. Choosing updates `D.profile` and the bar.
- **Settings page** (You tab): Look · Appearance · Text size · Language · Visitors · Time · Interests, so the visitor can change everything later.
- **Effects visible on the main AR screen and the card:**
  - Time filters the levels: Quick = Hub + Landmark, Classic = all, Deep = all plus "Deep dive" blocks.
  - The card text comes from `poi.story.{quick,classic,deep,kids}`, layered, with a fallback to classic.
  - Children turns on the mascot coach and games first.
  - Interests emphasise matching POIs.

## 5. The Playful look

- A real second look, designed from a spec by a design agent:
  - a rounded display face (Fredoka, embedded);
  - thicker icon line;
  - a sticker outline (2 pt ink border);
  - hard offset shadows;
  - expressive springs;
  - bigger corners;
  - saturated, cheerful colours in light and dark that still pass 7:1 for text;
  - Storybook markers by default.
- New tokens that Premium sets to neutral: `outline_pt`, `shadow_style` (soft | hard), `title_face`, `marker_preset`.
- The dead `.kids` CSS (58 rules, unreachable) is removed.

## 7. As built (Lab v18)

- **Code:** `js/34_profiles.js` holds:
  - the model;
  - the views (`D.ds` and `D.themes[mode]` are proxies);
  - `setProfile` and the bar;
  - the field scope (`scopeOf`, `resetScoped`);
  - `dimView` for the Time / Visitors rows;
  - the onboarding and the Settings sheet;
  - `profilesBody`;
  - the effects: `shownByTime`, `storyOf`, `isInterest`.
- **Fields:** `fSelect`, `fRange`, `fColor` and `fToggle` record their scope, and `row()` draws the tag:
  - the look's name (or "Premium · light" for colours);
  - "from Premium" when inherited;
  - "Playful ↺" when the look has its own value (click it to reset).
- **Appearance** resolves in this order: the Lab preview (the bar) → the visitor's Settings (`D.profile.appearance`) → the app's default (Design system › Look and mode › In the app).
- **The Playful look:** spec in `mk_review/playful_spec.md`; Fredoka 600 embedded; CSS under "Playful look's treatments" in `ds.css`.
  - Classes driven by its tokens: `.outlined` (outline_pt > 0), `.sh-hard` (shadow_style hard), `.sel-fill` (selected = fill + check).
- **Retired:** Explorer / Family / Expert (`D.app.theme`, `D.ds.audiences`, the `aud-*` classes) and the light / dark fold pairs (`themeFold` → `colourFold`). The dead positive `.kids` CSS is gone. The harmless `:not(.kids)` qualifiers stay, because removing them would lower their specificity.
- **Stories:** each POI has `story.{quick, classic, deep, kids}`. The peek card shows one line and the half card four; the immersive and full cards show the whole layer.
- **config.json:** `app.profiles` holds `{settings, looks, visitors, time, interests, onboarding, default_appearance, text_scale}`.
- **Speed:** a profile switch (setProfile + renderPhone) takes 24 ms median in the Lab. Each token read walks the proxy chain (about 0.07 ms). Unity bakes one flat table per look × mode instead.
- **Tests:**
  - regress has 153 checks (17 new for v18);
  - the sweep was run for Premium and for Playful;
  - verification: two visual critics (Premium, Playful), a profile-logic tester (8 bugs, all fixed) and a config audit.
