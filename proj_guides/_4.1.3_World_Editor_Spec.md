# World Design (4.1.3) -- the POI Editor for the world: organisation, rules and the Region spec

**What this file is.** How the POI Editor window is organised for everything a POI shows on the wall and in the app, the
rules every section follows, and the full spec of the Region (outlines and fills drawn on the wall). The feature map and
the On-tap system are in `_4.1.5`; Wall Life is in `_4.1.4`. The World Editor Lab (`_4.1.2_Prototype/`) is the working
model of this window: every rule here is visible there.

**The question every option has to pass:** can it be built in Unity, and can it be placed with the right size, position and
motion to sit on one specific building, square, street or hillside? Each Region style therefore shows **how many cm of
tracking error it hides** (section 4.6). The Editor warns when the wall's measured alignment error is larger.

## 1. The tabs

**App · Global Scene · Specific Marker · Experiences · Detail Card · Guide.**

| Tab | Owns | Rule |
|---|---|---|
| **App** | the app's own screens on a phone: Start, Onboarding, Main AR screen, Pointing, On tap, Explore menu, Look | composes screens; defines the On-tap components and styles |
| **Global Scene** | the wall: Wall & content → Looks (named styles) → Levels → Life → Behaviour on the wall → Test & validate | defines and assigns |
| **Specific Marker** | one POI: Identity → Position → Presentation (At rest with Shapes → On tap → Alive) → Content for actions → Card | places, fills and overrides |
| **Experiences** | sequences over many POIs: tours, games, moments on the wall, wall layers, capture & share | sequences |
| **Detail Card**, **Guide** | the card sheet and its blocks; Azu | as today |

Config keys do not depend on where a field is drawn.

## 2. Editor rules (every section)

1. **Define, assign, place.** Global Scene and App define named styles once. Levels assign them. A POI places itself
   (position, shapes) and overrides only where needed. Changing a style restyles every POI that uses it.
2. **A default for the whole app, then exceptions.** Every list of named styles starts with one row, "Default for the whole
   app". A level shows "(Default: …)" until it picks another; a POI shows "(level X: …)" until it picks another.
   Resolution order: shape (Region only) → POI → level → app default.
3. **Prefab-style overrides.** A POI may change single fields of the style it inherits without copying the style. An
   overridden field has a bold label and a blue bar on the left, and a ↺ button that reverts it to the inherited value; a
   field that is not overridden shows the inherited value, dimmed. Only the fields listed as overridable can be changed
   (On tap: `_4.1.5` section 3.4). A different look for many POIs is a new named style, not many overrides.
4. **Named lists are ReorderableLists.** One foldout per element; the header shows the name, a one-line summary and
   "used by N"; buttons ▶ (preview on the device), ↑ (move up), ⧉ (duplicate), − (remove, blocked while in use). The key is
   generated (`region_style_N`, `tap_layout_N`…); the name is edited (`_5.1` "Tables", taxonomy identity rule).
5. **Collapsed by default, titles stay visible.** Every section starts collapsed. Section and subsection titles stick to
   the top of the editor while it scrolls, each one below the titles that contain it.
6. **A click opens what it changes.** Clicking or focusing any field opens the screen that shows it (the device view in the
   Lab, the Game view in Unity); fields that belong to a step of the app open that step (e.g. On tap → a POI tapped).
7. **Everything is live in Play Mode** (`_5.1` section 0, "PlayMode Live Config"). Popups and rows use the shared helpers.
8. **Preview on a device.** The view shows every screen through a device: phone or tablet, portrait or landscape (two
   buttons above the view; a second click turns the device). In Unity this is the Game view's aspect presets plus the
   device simulator.

## 3. The model: what a POI shows on the wall

```
POI
 |- Anchor            position + facing
 |- At rest           layers per level: P point · R region · T tag (from a plain label to a card) · M model
 |    |- Point        the existing marker (shape, icon, badge, ring, effects)
 |    |- Region       one or more shapes drawn on the wall (this file)
 |    |- Tag          a label or a summary card, built from Detail Card blocks, anchored to the POI
```

A level switches each layer on or off; a POI may override the layers. A POI with the Region layer but no shapes yet shows
as a point, with a notice in the Editor.

## 4. Region

A Region is **geometry** (per POI, drawn in the scene) and a **style** (named, on the wall). The style has four parts:
Line, Vertices, Fill and Motion.

### 4.1 Geometry (Specific Marker › Presentation › At rest › Shapes)

| Option | Values | Notes |
|---|---|---|
| Shapes | a list; each has a key (`outline`, `door`, `windows`…) | A building can have its outline plus a door and a row of windows |
| Type | `polygon` (closed) / `path` (open) / `points` (separate marks: windows, lamps, drawn with the style's vertex mark) | The **Rectangle** draw tool makes a 4-knot polygon to reshape |
| Knots | 3D points in the map frame, snapped to the wall mesh | Drawn on the Immersal GLB with the Splines Draw tool, captured to config like marker positions |
| Corner, per knot | `sharp` / `rounded` (radius cm) / `smooth` | The Splines tangent mode |
| Default corner | as above | For new knots |
| Style | optional; a shape may pick its own Region style | Resolution: shape → POI → level → app default |
| Media | for a style whose fill is `media`: the file (`POIs/<poi_id>/media/`) | The style says how, the shape says which file |
| Surface offset | cm, under Advanced | Lifts the line off the wall to avoid z-fighting |

**No anchor-only shape type.** A shape that should anchor World Content without being seen (a window for a curtain) is a
normal shape with a quiet style: line opacity 0, no fill, no vertex marks. The Focus preset `appear` shows its edge on tap.

Authoring loop (Unity): select the POI, **Draw region**, click knots on the GLB, adjust with the Splines handles,
**Capture** (to config); **Apply** goes the other way. Live in Play Mode.

### 4.2 Line

| Option | Values | Note |
|---|---|---|
| Width | cm on the wall, with a minimum and maximum in screen px | thinner when far, like paint |
| Colour | `category` / `fixed` / `theme accent` / `status` (the Outline colour modes of `_2.2.3`) | |
| Opacity | 0 to 1 | |
| Pattern | `solid` / `dashed` (dash, gap cm) / `dotted` | |
| Offset outward | cm, 0 = on the edge; paths and points ignore it | **hides alignment error**: the author draws the true contour, the offset only moves the line, so one value retunes every building and the contour stays exact for the fill, the spotlight hole, the tap area and Wall Life anchors |
| Caps and joins | round / square; mitre / round | round hides error better |
| Glow | `none` / `soft` (width cm, intensity) | in the line shader; no Bloom over the camera feed |
| Double line | off / on (gap cm, second-line opacity) | the "architectural drawing" look |

### 4.3 Vertices

| Option | Values |
|---|---|
| Show at | `none` / `corners only` / `all knots` |
| Mark | `dot` / `square` / `diamond` / `ring` / `cross` / `corner bracket` |
| Size, colour | cm; the Line colour modes |

### 4.4 Fill

| Option | Values |
|---|---|
| Mode | `none` / `tint` (colour, opacity) / `gradient` (radial or linear, alpha from-to) / `pattern` (hatching, dots, azulejo grid; scale cm) / `media` (an image or a video seen only inside the shape) |
| Edge feather | cm (soft edges hide error) |
| Media: fit, opacity, video plays | cover / contain / stretch; 0-1; loop while visible / on tap (a still frame at rest) |

Taste rule: the colour fills modulate the camera image rather than paste over it (a tint stays at 0.10-0.25). Media is the
exception, by intent.

Unity: the fill mesh (the triangulated shape) gets planar UVs from the shape's box; its material samples a Texture2D or a
VideoPlayer's RenderTexture. Fit is a UV scale and offset; feather is an edge fade in the shader. No stencil, no extra camera.

### 4.5 Motion

The line mesh has a UV along its length; the shader reads a progress value; Animation or code drives it.

| Phase | When | Presets | Parameters |
|---|---|---|---|
| **Intro** | first shown (after the level's reveal delay) | `fade`, `draw on`, `build` (knots pop, then edges draw), `from centre`, `scan` | duration or speed (cm/s), start knot, direction, per-segment delay, easing |
| **Idle** | while visible | `none`, `breathe`, `flow`, `comet`, `sweep`, `knot pulse` | period, speed, count, length, intensity |
| **Focus** | the POI is tapped | `brighten`, `redraw`, `lock-on`, `spotlight` (dim outside), `appear` (rest opacity → tap opacity) | duration, amount |
| **Outro** | hidden or deselected | `fade`, `undraw` | duration |

Rules: Reduce motion and the wall's effects switch stop Idle and turn Intro into a fade. Intro plus Focus take at most
2-5 s (arm fatigue). One animated thing per POI at a time.

### 4.6 Precision and distance

**Precision is a number, not a setting.** Each style shows "hides about X cm": the outward offset plus half the line width,
plus a quarter of the glow; a fill's feather counts half; Spotlight counts about 4 cm. The Editor warns when the wall's
measured alignment error (Global Scene › Wall) is larger. The formula is calibrated on the phone (step 0).

| Option | Values |
|---|---|
| Visible from / to | metres (the LOD bands of `_2.4` where possible) |
| Simplify when far | vertices hidden, glow off, Idle off |

### 4.7 The point when a Region is present

| Option | Values |
|---|---|
| Point position | `own` / `region centre` / `region top` |
| Leader line | off / on (thin, the Line colour) |
| Point size | the same / smaller (a ratio) |

**Defaults:** values tried in the Lab are experiments; the final defaults are chosen by eye in Unity, on the phone.

## 6. Config sketch

```json
"region_default": "region_style_1",
"region_styles": [
  { "key": "region_style_1", "label": "Facade",
    "line":    { "width_cm": 1.5, "min_px": 1.5, "max_px": 4, "color_mode": "category", "opacity": 0.9,
                 "pattern": "solid", "offset_cm": 2, "caps": "round",
                 "glow": { "on": true, "width_cm": 3, "intensity": 0.5 }, "double": { "on": false } },
    "vertices":{ "show_at": "corners", "mark": "corner_bracket", "size_cm": 6 },
    "fill":    { "mode": "tint", "opacity": 0.15, "feather_cm": 4 },
    "motion":  { "intro": { "preset": "build", "duration_s": 1.6 }, "idle": { "preset": "comet", "period_s": 6 },
                 "focus": { "preset": "brighten", "amount": 1.5 }, "outro": { "preset": "fade", "duration_s": 0.3 } },
    "distance":{ "visible_to_m": 40, "simplify_from_m": 15 } }
],
"hierarchy_levels": [ { "...": "...", "layers": ["point", "region", "tag"], "region_style_key": "", "tap_style_key": "" } ],
"pois": [ { "id": "twin_tower_church", "...": "...",
  "world": { "presence_override": "", "style_override": "",
             "shapes": [ { "key": "outline", "type": "polygon", "default_corner": "sharp", "style": "",
                           "knots": [ { "p": [0.12, 1.40, -0.03], "corner": "" } ] } ] } } ]
```

An empty key means "inherit" (level → app default).
