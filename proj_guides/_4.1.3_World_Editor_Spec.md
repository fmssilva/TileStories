# World Design (4.1.3) -- Editor Tab spec for world markers (planning, 2026-10-29)

**What this file is.** This is the planned **Editor Tab organisation** for the world-marker components, written before any
prototype or code. It covers what each component is, which options it has, where each option lives in the POI Editor
window, and what goes into `config.json`.

**How we work (the developer's decision, 2026-10-29):**
1. Agree on this spec.
2. Build one local HTML prototype per component. Its control panel is laid out exactly like the proposed Editor section, so
   one prototype tests the look and the organisation together.
3. Feed what the prototypes teach back into this spec.
4. Only then design the code (research file `_4.1.1`, section 9b, is the draft) and write the first Worker brief.

**Scope now:**
- Group 1, "how a POI is identified on the wall": **Point** and **Region**.
- Group 2, "what comes with it": **Label** and **Tap**, listed here and specified after group 1.
- Later: 3D models, images, video, imported animation and wall-wide content (`_4.1.1`, sections 4.4 to 4.7).

**The question every option has to pass:** can it be built in Unity, and can it be placed with the right size, position and
motion to sit on one specific building, square, street or hillside? Each option therefore carries a **precision grade**
(high / medium / low, `_4.1.1` section 4.6). The Editor warns when the wall's measured alignment error is larger than the
grade tolerates.

## 1. What already exists (reuse, do not rebuild)

The "point" marker is already a full design system. The new work is the **Region**, and how Point and Region combine.

| Already built | Guide | Where in the Editor today |
|---|---|---|
| Position on the wall (map frame), facing | `_1.2`, `_2.1` | Specific Marker > Position |
| Shape, category colour and icon, custom symbol | `_2.2.1` | Global Scene > Marker; Specific Marker > Marker Style |
| Badge | `_2.2.2` | Global Scene > Badge |
| Status outline ring (three colour modes) | `_2.2.3` | Global Scene > Outline |
| Effects: Pulse, Ripple, Halo, Beacon; reveal delay/duration; rotate | `_2.2.4` | Global Scene > Effects + Hierarchy Levels |
| Label text, font, size, gap | `_2.0` | Global Scene > Labels, Text & Fonts |
| Hierarchy levels, LOD, zoom, displacement | `_2.3`, `_2.4`, `_2.5` | Global Scene |
| Selection, filter, search; tap opens the card | `_2.6`, `_3.x` | Global Scene > Select...; Detail Card tab |

**Design rule carried over from `_2.2.4` section 2.2: define, assign, place.**
- **Global Scene DEFINES** named styles once for the wall.
- **Hierarchy Levels ASSIGN** a style to each level.
- **Specific Marker PLACES** the POI (position, geometry) and may override sparingly.

The Region follows the same rule. A wall then reads as one design, and changing a style restyles every POI that uses it.

## 2. The model: what a POI shows on the wall

```
POI
 |- Anchor            position + facing (exists)
 |- Identification    Presence = point | region | both
 |    |- Point        the existing marker (shape, icon, badge, ring, effects)
 |    '- Region       one or more shapes drawn on the wall (NEW)
 '- Extras            Label (exists, extended later), Tap (exists, extended later), media (later)
```

**Presence** decides which identification the visitor sees:

| Presence | Use it for | Precision |
|---|---|---|
| `point` | Small or distant things, low alignment confidence. The marker as today | low (a point tolerates error) |
| `region` | Large, clearly bounded things: a palace facade, a square. No dot, the outline is the marker | medium to high |
| `both` | A point you can tap plus the region it stands for. The point can sit on the region or float off it with a leader line | mixed |

The default comes from the hierarchy level. A POI can override it. A POI with `region` or `both` but no shapes yet falls back
to `point`, and the Editor shows a notice.

## 3. Region: the components and their options

A Region is made of **geometry** (per POI, placed in the scene) and a **style** (defined once on the wall). The style has four
parts: Line, Vertices, Fill and Motion.

### 3.1 Geometry (per POI, Specific Marker > Region)

| Option | Values | Notes |
|---|---|---|
| Shapes | a list; each has a key (`outline`, `door`, `tower`...) | A palace can have its outline plus a door and a window row. Most POIs have one |
| Shape type | `polygon` (closed) / `path` (open) | `path` is for streets, walls and ridgelines. A **Rectangle** draw tool is the quick start: it makes a 4-knot polygon you then reshape (P1 settled that it is a tool, not a stored type) |
| Knots | 3D points in the map frame, snapped to the wall mesh | Drawn in the Scene view on the Immersal GLB with Unity's Splines Draw tool, then captured to config the way marker positions are |
| Corner, per knot | `sharp` / `rounded` (radius in cm) / `smooth` (curve through the knot) | `sharp` for buildings, `smooth` for hills, roundabouts and squares. In Unity this is the Splines tangent mode |
| Default corner | as above | Applies to new knots, so a building does not need every knot set |
| Surface offset | cm | Lifts the line off the wall to avoid z-fighting. Hidden under Advanced; the default works |

Authoring loop (Unity-native, `_4.1.1` section 4.3): select the POI, press **Draw region**, click knots on the GLB in the
Scene view, adjust them with the normal Splines handles, and press **Capture**. Knots go to `config.json`. **Apply** goes the
other way. Live in Play Mode.

### 3.2 Line (wall style)

| Option | Values | Precision note |
|---|---|---|
| Width | cm on the wall, with a minimum and maximum in screen px | Open question Q1 |
| Colour | `category` / `fixed` / `theme accent` / `status` (reuses the three Outline colour modes of `_2.2.3`) | -- |
| Opacity | 0 to 1 | -- |
| Pattern | `solid` / `dashed` (dash, gap in cm) / `dotted` | -- |
| Placement | `on edge` / `outside` / `inside`, plus an offset in cm | **Outside with a small offset hides alignment error**: a line 3 cm outside a facade still reads as "around it" when tracking is 2 cm off |
| Caps and joins | round / square; mitre / round | Round hides error better |
| Glow | `none` / `soft` (width cm, intensity) | Fake glow in the line shader, no Bloom over the camera feed (`_4.1.1` section 4.1) |
| Double line | off / on (gap cm, second-line opacity) | Premium "architectural drawing" look |

### 3.3 Vertices (wall style)

| Option | Values |
|---|---|
| Show at | `none` / `corners only` (sharp knots) / `all knots` |
| Vertex mark | `dot` / `square` / `diamond` / `ring` / `cross` / `corner bracket` (an L along the two edges) |
| Size, colour | cm; same colour modes as Line |

### 3.4 Fill (wall style)

| Option | Values | Precision |
|---|---|---|
| Fill | `none` / `tint` (colour, opacity) / `dim outside` (spotlight: the rest of the wall darkens) | tint: high; dim outside: low (it tolerates error) |
| Edge feather | cm | Soft edges hide error |

Taste rule: modulate the camera image rather than paste over it. A tint stays faint (opacity 0.10 to 0.25 by default).

### 3.5 Motion (wall style)

There are four phases, each with one preset and its parameters. They correspond to Unity as follows: the line mesh has a UV
along its length, the shader reads a progress value, and Animation or code drives that value (`_4.1.1` section 9b).

| Phase | When | Presets | Parameters |
|---|---|---|---|
| **Intro** | The POI is first shown (follows the level's reveal delay) | `fade`; `draw on` (one continuous pen stroke); `build` (one segment at a time: the knots pop in first, then each edge draws between them, like construction); `from centre` (draws both ways from one knot); `scan` (fills along a direction) | duration or speed (cm/s), start knot, direction (cw / ccw), per-segment delay, easing |
| **Idle** | While visible | `none`; `breathe` (glow in and out); `flow` (dashes march along the line); `comet` (1 to 3 sparks travel the line); `sweep` (a light band crosses the fill); `knot pulse` (the vertices pulse in sequence) | period, speed, count, length, intensity |
| **Focus** | The POI is selected | `brighten` (width and glow up); `redraw` (plays Intro again); `lock-on` (corner brackets close in); `spotlight` (dim outside) | duration, amount |
| **Outro** | The POI is hidden or deselected | `fade`; `undraw` | duration |

Rules:
- Reduce motion and the wall's effects master switch (`_2.2.4` section 2.3) stop Idle. Intro becomes a fade.
- Arm-fatigue budget: Intro plus Focus take at most 2 to 5 s (`_4.1.1` section 8).
- Idle is subtle by default. One animated thing per POI at a time.

### 3.6 Distance and level of detail

| Option | Values |
|---|---|
| Visible from / to | metres (reuses the LOD bands of `_2.4` where possible) |
| Simplify when far | on / off (vertices hidden, glow off, Idle off) |

Decisions the Lab adds to sections 3 to 6:
- **Points** is a third shape type: separate marks such as windows or lamps, drawn with the style's vertex mark.
- **A shape may pick its own style** (choice only). Resolution order: shape, then POI, then level.
- **Style rows follow the taxonomy identity rule** of `_5.1` "Tables": the key is generated (`region_style_N`), the name is
  edited, and a style cannot be deleted while in use.
- Each style shows a **precision chip**: how many cm of error it hides, compared with the measured error.
- Fill modes for v1 are `none` and `tint`. "Dim outside" moved to Focus as **Spotlight**, because dimming the whole wall
  per POI at rest makes no sense.

## 11. Developer questions after the Lab (2026-10-29)

**Defaults (developer's rule):** values the developer changes while trying a prototype are experiments, not defaults. The
prototype defaults stay as they are. The final defaults are chosen by eye in Unity, on the phone, during implementation.

**Precision: what it is.** It is not a setting. It is a read-only estimate computed from the style: how many cm of tracking
error the style hides before the misalignment shows. The estimate comes from:
- the line's offset outward;
- half the line width;
- a quarter of the glow;
- half the fill feather;
- Spotlight, which counts as about 4 cm.

The chip compares that estimate with the wall's measured alignment error (step 0). The formula is a guess to calibrate on
the phone. Proposal: drop the high/medium/low grade, show "hides about X cm" next to the style, and raise a validation
warning when the measured error is larger.

**Placement: why it exists.** The author draws the true contour. The offset is a style value that pushes the line out by a
few cm, so tracking error does not cut the line across the facade. Its advantages:
1. When the real error is measured (or improves), one value retunes every building, with nothing to redraw.
2. The true contour stays exact for everything else that uses it: fill, the spotlight hole, the tap area, sweep clipping.

Proposal: simplify to one "Offset outward" value in cm (no "inside", default 0 to 2 cm), ignored by paths and Points.

**Fill: proposed modes.**

| Mode | What it is | When |
|---|---|---|
| none / tint | as now | v1 |
| gradient | radial (centre to edge) or linear (angle), alpha from-to: the region fades into the wall | v1 (cheap in the shader) |
| pattern | procedural, in the style's colour: hatching, dots, a tile grid (azulejo); scale in cm, alpha | v2 |
| texture / image / video | art clipped to the region | the later "imported art" step (`_4.1.1` section 4.7), not a style option |

The "modulate the camera image, don't paste over it" rule still applies: low alpha by default.
