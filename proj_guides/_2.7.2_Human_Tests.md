# TileStories — Human Device Test Handover Guide (Blocks 1-6)

Audience: the developer with a real ARFoundation mobile device. This is Tier 2 / Tier C-D. It is the
ONLY gate that can close Steps 13-14 (zoom FOV + gestures) because on-device ARCameraManager
contention and touch disambiguation cannot be verified in Editor/Tier B.

## Setup
- Build a Development build to the device (mock OR real Immersal VPS; for gesture/FOV behavior the
  tracking source does not matter -- what matters is a live camera + the on-screen buttons).
- Print/display the LivingRoom wall with the lamp/painting/camera marker zones visible so the
  device can localize (or use mock tracking tier, if the target question is only FOV/gesture).
- Turn audio/volume off. Set time-of-day consistent lighting for consistent marker readback.
- Device orientation: portrait, held ~1 arm's length, wall filling ~70% of the frame.

## Block 5 -- Zoom FOV (2.4-l) + Gestures (2.4-m) -- HUMAN device checklist
Run each item once; record pass/fail + a one-line observation. This is the FOV "sticks" test.
- H1 Button-zoom FOV holds: press Zoom-In once, release, keep camera still ~5 seconds. The markers
  must stay zoomed (FOV narrowed) -- no reset-to-wide, no jitter fight with the ARCameraManager /
  Background. [holds 5s / resets / fights]
- H2 Pauses + zoom in sync: hold still then zoom in; pause marker reveal must not fight the zoom
  (no marker disappearing/re-appearing because of the FOV change). [in sync / fights]
- H3 Pinch hold: two-finger pinch OUT then release; the zoom level must HOLD (not snap back).
  Pinch IN and release -> holds. [holds on release / snaps back]
- H4 Double-tap step cycle: double-tap once -> next discrete level; double-tap repeatedly -> cycles
  through levels and RETURNS to 1x; single-tap on empty wall -> nothing happens (no zoom, no select).
  [cycles correctly / wrong level / single-tap does something]
- H5 Cross-system disambiguation: double-tap DIRECTLY on a marker -> exactly ONE zoom step and no
  accidental double "single-selection" (must not open or zoom twice). [one zoom / two actions]
- H6 Single-finger pan/drag must NOT trigger pinch or double-tap. Drag across a group of markers and
  confirm no spurious zoom/flicker. [drag clean / spurious zoom]
- H7 (conditional) If FOV write is fought on-device (any of H1-H3 show reset/fight), switch
  ARZoomController to the projectionMatrix override (entry option 2), rebuild, and re-run the whole
  list. Record the mechanism switch in decisions.md. Do NOT mark 2.4-l/m done until one of the two
  mechanisms (FOV direct OR projectionMatrix) visibly works on-device.

## Block 6 -- Displacement (2.5-g / 2.5-h) -- optional on-device sanity (code already Tier-0+PM green)
Only needed as a final "it doesn't look broken live" check; the algorithmic correctness is covered
by EditMode/PlayMode. Use the lamp family (distinct priorities) and the dev_disp_eq_* triple.
- D1 lower_priority_only: the highest-priority lamp marker stays put while the others fan out.
  [anchor fixed + others move]
- D2 equal-priority triple: all three separate symmetrically; none is unjustly pinned.
  [symmetric / one pinned]
- D3 hide-fallback: with a tiny max_displacement_px the lower-priority label disappears (no overlap),
  higher-priority label stays. [correct hide / wrong member hidden / none hidden]

## Handoff rules
- Record pass/fail + one concrete observation per H1-H7 (D1-D3 optional).
- Note orientation, lighting, and whether tracking was mock or VPS.
- If H7 was triggered, state which mechanism you ended on and paste the decisions.md line to add.

## Block 1 -- LOD (2.4) -- Human device sanity (optional, code already Tier-0 green)
Only needed as a final "it doesn't look broken live" check.
- L1 Distance banding: walk closer to the wall -> more markers appear. Walk farther -> fewer markers. [more/less / no change]
- L2 Density response: at closest approach to a dense cluster, markers shrink or aggregate (not all full-size overlapping). [yes/no]
- L3 Frustum cull: turn camera so a marker group is at the screen edge -> markers fade/disappear at the edge. [culled / still visible]

## Block 2 -- Selection (2.6 section 11) -- Human device sanity (optional)
- S1 Tap a marker: other markers dim, tapped marker stays bright. [yes/no]
- S2 Tap again: all markers return to full brightness. [yes/no]
- S3 Tap a dense marker: camera zooms in. Tap an isolated marker: no zoom. [yes/no]

## Block 3 -- Minimap + Filter + Results (2.6 sections 7-9) -- Human device sanity (optional)
- M1 Minimap dots match visible POIs (count check). [yes/no]
- M2 Toggle a filter: results list + minimap + scene markers all update to the same filtered set. [yes/no]
- M3 Type a search query: results list filters. Clear: all return. [yes/no]

## Block 4 -- Filtering composition (2.6-i) -- Human device sanity (optional)
- F1 Toggle filter + type query: all four surfaces (results, minimap, scene markers, highlight) show the SAME set. [yes/no]
- F2 `filter_mismatch_behaviour = "hide"`: non-matching markers invisible. [yes/no]
- F3 `filter_mismatch_behaviour = "dim"`: non-matching markers faintly visible. [yes/no]
