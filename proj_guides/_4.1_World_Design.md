Poderias ter ferramentas como:

Pincel: pintar regiões, como muralhas ou telhados.
Borracha: corrigir regiões desenhadas.
Polígono: desenhar o contorno exato de um castelo ou igreja.
Linha: desenhar percursos, muralhas ou ligações entre edifícios.
Spray ou brilho: definir zonas com efeitos luminosos.
Animações: escolher como uma região aparece, pulsa, muda de cor ou fica iluminada.
Camadas: separar telhados, muralhas, torres e outros elementos.
Pré-visualização: experimentar os efeitos antes de os utilizar na aplicação móvel.
E o mais importante: o resultado de cada desenho seria guardado como dados do POI, não como código específico desse edifício. O teu framework interpretaria esses dados e aplicaria os efeitos automaticamente.

1. Como seria o teu editor
Eu imaginaria uma janela própria dentro do Unity, por exemplo, chamada TileStories Editor.

A interface teria três áreas:

Esquerda: lista de POIs, com o Castelo de São Jorge, igrejas, torres, etc.
Centro: imagem do mural, onde desenhas e editas.
Direita: propriedades do elemento selecionado, incluindo cor, opacidade, animação e comportamento.
O fluxo seria simples:

Selecionas o Castelo de São Jorge.
Escolhes a ferramenta Polígono.
Desenhas o contorno do castelo diretamente sobre a imagem.
Escolhes uma cor e um efeito.
Carregas em Preview.
Guardas o POI.
Quando a aplicação reconhecer o mural, o teu sistema já saberá onde desenhar o contorno e como aplicar o efeito.

2. Como implementar isto tecnicamente
Utilizaria quatro componentes principais.

A. Editor visual: TileStoriesEditorWindow

Uma janela personalizada criada com as ferramentas de extensão do Unity Editor.

É aqui que implementas o pincel, a borracha, os polígonos, as camadas e a seleção de POIs.

Podes utilizar EditorWindow e UI Toolkit para construir a interface. Para desenhar sobre a imagem, podes utilizar um controlo visual com eventos de rato ou toque, conforme o contexto de utilização do editor.

B. Dados de cada POI: POIVisualData

Cada POI teria um conjunto de dados que descreve a sua representação visual.

Por exemplo:

POI: Castelo de São Jorge

Regiões:
    - Muralhas
    - Torres
    - Telhados

Efeitos:
    - Contorno luminoso
    - Preenchimento colorido
    - Animação de entrada

Interação:
    - Selecionar POI
    - Mostrar detalhe
Estes dados poderiam ser guardados em assets ScriptableObject, juntamente com referências a máscaras e outros recursos visuais.

C. Sistema de renderização: POIRenderer

Este componente interpreta os dados e apresenta os efeitos na aplicação.

Por exemplo, recebe um polígono e desenha o seu contorno. Ou recebe uma máscara e utiliza um shader para colorir uma região.

A vantagem é que o renderer não precisa de saber se está a desenhar um castelo, uma igreja ou uma torre.

D. Sistema de animações: POIAnimationController

Permite reutilizar animações, como:

Aparecimento gradual.
Contorno que percorre o edifício.
Brilho pulsante.
Mudança progressiva de cor.
Destaque sequencial de diferentes regiões.
Assim, podes criar uma biblioteca de efeitos e associá-los a qualquer POI através do editor.

3. A decisão que tomaria para o MVP
Não começaria por implementar um Paint completo.

Começaria por um editor de polígonos sobre a imagem do mural.

É uma primeira versão relativamente simples e já permite obter resultados interessantes.

O editor teria apenas cinco funcionalidades:

Carregar a imagem do mural.
Selecionar um POI.
Desenhar um polígono à sua volta.
Escolher uma cor e um efeito de contorno.
Guardar e pré-visualizar o resultado.
Por exemplo, desenhas o contorno do Castelo de São Jorge uma única vez. Depois, o framework permite escolher entre um contorno branco, um brilho dourado ou um preenchimento translúcido, sem redesenhar o polígono.

Mais tarde, acrescentas o pincel e as máscaras para colorir individualmente as muralhas, as torres e os telhados.

Uma distinção técnica importante: desenhar na imagem do mural dentro do editor é relativamente simples. Garantir que esse desenho fica corretamente sobreposto ao mural real, através da câmara do telemóvel, exige que o mapeamento entre a imagem, as coordenadas do mural e o sistema de coordenadas AR esteja correto. No teu caso, o editor deve reutilizar o sistema de posicionamento que já desenvolveste.

4. Como tornar o framework realmente reutilizável
Eu separaria os dados artísticos da lógica de execução.

Elemento	Criado no editor	Executado na aplicação
Contorno de um castelo	Polígono	Linha animada
Telhado de uma igreja	Máscara ou polígono	Preenchimento colorido
Torre	Região identificada	Brilho pulsante
Percurso histórico	Linha ou sequência de pontos	Animação do percurso
Edifício 3D	Referência a um modelo	Apresentação do modelo
Desta forma, podes desenvolver novos POIs e novas experiências sem modificar o código principal.
